# LP 画像配信の最適化

LP の split / fullbleed hero と「特徴 3 つ」パターンが使う画像を WebP に切り替え、転送量を減らします。レイアウト、画像要素の寸法、読み込み優先度、文言、その他の LP 表示は変えません。

hero は 1200×900 の q85 WebP、feature icon は 192×192 の q90 WebP を追加しました。icon 元画像は 600×600 で、CSS 表示寸法は 64×64 です。192px 画像は表示密度に合わせて縮小した候補であり、元 PNG と画素一致する画像ではありません。候補は視覚レビューで採用対象になりました。

変更した pattern は `patterns/lp.php` の hero 2 箇所と `patterns/features.php` の icon 3 箇所だけです。元の PNG は、HOME、category header、LP 資料カード、他の parts pattern、既存ページ内容から参照されるため残しています。保存済みの投稿・固定ページにある画像 URL は自動移行されません。必要な場合は編集画面で該当パターンを明示的に更新してください。

## 性能検証の範囲

LP 専用 PoC では q85 hero と q90 icon の候補を同じ WordPress / Lighthouse 条件で比較し、推定 LCP の中央値がおよそ 12.53 秒から 2.56 秒へ下がりました。q80 hero は q85 に対する測定上の改善がなく、細部の平滑化が視覚レビューで確認されたため採用していません。これらは候補画像の PoC 結果で、全 candidate run は LCP 2.5 秒の閾値を超えており、性能要件の達成を示しません。q85 の試行では最大 11.04 秒の run も記録されました。追加 trace 試行では再現せず、原因は未確定です。中央値だけで結果の安定性を示すものではありません。

PoC の baseline と candidate はどちらも LP 専用の非選択 hero 画像を遅延する処理が有効な候補テーマで計測しました。この変更にはその処理を含めていません。main からの実測では非選択 variant の取得条件が異なる可能性があるため、統合後のテーマで通常描画と Lighthouse を改めて検証する必要があります。PoC 数値を本変更の本番性能結果として扱わないでください。

## VPS停止後のソース保全

このブランチは未完了の保存用Draftです。現HEADの受入合格を主張せず、マージしません。実機検査・証拠再生成は停止しています。元の作業ツリーの画像・生成証拠・私用ログはこの保存PRに含めていません。再開時にソース、実機、証拠の対応を確認してください。

参照先の新規WebP 4枚は公開確認前のため、このDraftには未収録です。このブランチ単独では画像表示を成立させられません。直近の試行は変更前の表示確認8条件でVPS再起動により中断し、Lighthouse比較は未完了です。一時ページ削除・設定復元・元マウント復元も未確認であり、コンテナーは停止したままです。

### 中断後の後片付け確認

停止済みの既存ラボだけを一時起動し、試行が作成した固定ページをID・slug・所有者・テンプレートで照合して削除した。IDとslugの両方で不在を確認し、テーマ設定は試行前の値と一致し、削除前後でも不変だった。コンテナーは後片付け後に停止した。元マウントへの復元は未実施で、変更前テーマの読み取り専用マウントが残る。性能測定や候補画像の実機検証は再開しておらず、中断試行を合格には変更しない。
