# 中間幅の比較候補を読める幅へ戻す

基準: `26074c4252756bfc3ac027bbebf9b86637dd3c7e`。カタログUIのみ。

## PoC と範囲

変更前の Chromium 768px で、3候補比較の本文幅は183px、最初の見出しの scrollWidth は190pxだった。
701pxでも3列に縮み、画像と説明が細分化する。詳細単独は320/390/768/1024/1440pxで横溢れなし。
CSSをページ内で一時適用すると768pxの選択カード幅が664px、画像幅が601pxとなった。
共有WordPress lab・テーマ・意味契約・要求本文・受入台帳には変更しない。

## 設計

701〜1000pxの比較のみ、既存の候補切替と data-active を使って1候補ずつ表示する。
3ボタンは同じ行で均等幅にする。候補・メモ・比較表・画像モードの内容と挙動は保持する。
比較表の初期開閉は変更しない。700px以下と1001px以上の表示も保持する。
1000pxは既存の共通部品一覧の中間幅境界と揃える。

[W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) の情報・操作を失わない再配置を参照。
今回の検査はChromiumの限定幅であり、WCAG全項目適合や全ブラウザ検収を主張しない。

## 検証計画

390/700/701/768/1000/1001/1440px、2・3候補で表示数・候補切替・横溢れを検査する。
中間幅で全候補の画像モード・判断メモを操作し、幅変更後も内容が保持されることを確認する。
基準CSSをrouteしたbeforeと現CSSのafterを同じデータで撮影し、幅・内容digestを比較する。
既存visual証跡は実captureでsource digestを更新し、公開guardとCIを通す。

## 実測結果

専用E2Eは15件成功。2/3候補×7幅に加え、3候補それぞれのメモ編集、画像幅モード、1440pxへの拡大と768pxへの復帰を確認した。
28件のbefore/after観察で候補・画像参照・比較表の内容digestは一致した。

| 3候補時の幅 | カード幅 before → after | 画像幅 before → after | 本文の横溢れ before → after |
| --- | --- | --- | --- |
| 701px | 186.33 → 599px | 121.33 → 534px | 0 → 0px |
| 768px | 208.66 → 666px | 143.66 → 601px | 7 → 0px |
| 1000px | 286 → 898px | 221 → 833px | 0 → 0px |

390/700/1001/1440pxの各候補の表示状態・カード幅・画像幅・本文幅・横溢れはbefore/after一致。
保存画像は768/1000px×before/afterの4枚。表を同じ操作で閉じた状態を比較している。
全viewportのバイト一致や、全704候補の個別目視は主張しない。

関連の選択/絞り込み39件、比較表/強制配色11件も成功。
既存11組のcaptureを実行し、filter-contextも再検証した。
強制配色captureの初回は1440px通常配色のcontrol画像digest不一致で停止し、単独再実行では成功した。
この既存captureの撮影安定性を本変更の改善成果には含めない。
