# 比較・選択カタログ（実行中）

試作03の1020枚を574候補へまとめ、共通部品・面・目的・検索語から探す。PC/SPの記録を切り替え、最大3候補を比較し、採用候補・保留・除外と理由をブラウザへ保存できる。JSON書出し・読込で移行する。同じ候補のメモは読込内容で更新する。正式な要求承認・G3判断にはならない。

## 開く・検証する

リポジトリのルートで実行する。

```sh
node scripts/build-selection-catalog.mjs
python3 -m http.server 8099 --bind 127.0.0.1
```

ブラウザで `http://127.0.0.1:8099/docs/research/2026-09-08-selection-catalog/` を開く。
別のターミナルで次を実行する。

```sh
npx playwright install chromium
npx playwright test tests/e2e/selection-catalog.spec.ts --workers=1
npm test
```

`CATALOG_BASE_URL` で検証サーバーを変更可能。静的JSON取得のため、HTMLファイルの直接オープンでは動作しない。外部サービスへの保存は行わない。ブラウザ保存が利用不可ならメモを書出して保管する。

## 受入条件ごとの証拠監査

`node scripts/audit-catalog-evidence.mjs`で全ACの対応を再集計する。カタログ生成からも毎回実行する。対応付けの正本は`acceptance-evidence.json`、生成結果は`acceptance-audit.json`。要求digest・AC本文digest・実装/検証コードdigest・結果ファイルdigestと成功行を照合し、変更や未完了を検出した場合は再検証扱いとして生成を止める。

この照合は証拠の鮮度と参照整合性の検査であり、任意の成功行が要求を満たすと意味的に保証するものではない。`scope`と`remaining`は条件を精読した対応付けとして管理する。既存試作の証拠も未対応付けとして残り、証拠なしを未実装と同一視しない。
