## 開く・検証する

リポジトリのルートで実行する。

```sh
node scripts/build-selection-catalog.mjs
python3 -m http.server 8099 --bind 127.0.0.1
```

ブラウザで `http://127.0.0.1:8099/docs/research/2026-09-08-selection-catalog/` を開く。
別のターミナルで次を実行する。

```sh
npx playwright install chromium
npx playwright test tests/e2e/selection-catalog.spec.ts --workers=1
npm test
```

`CATALOG_BASE_URL` で検証サーバーを変更可能。静的JSON取得のため、HTMLファイルの直接オープンでは動作しない。外部サービスへの保存は行わない。ブラウザ保存が利用不可ならメモを書出して保管する。

## 選別の途中から再開する

比較中の最大3候補、面・目的・採用状態・検索語・PC/SP、要求タブと条件検索、関連候補の範囲、「さらに見る」で展開した件数を同じブラウザへ保存し、再読込後に復元する。比較候補名は画面下部へ表示し、別の面を見ながら1候補ずつ外せる。スマホでは候補名の列を横へスクロールでき、キーボードの操作対象も列内へ表示する。比較欄の高さに応じて末尾の余白を確保する。

選んだ理由も候補検索の対象に含める。詳細で採用状態や理由を変更して閉じた後は、その候補のボタンへ操作位置を戻す。条件変更で候補が表示対象から外れた場合は検索欄へ戻す。これは[WAIのダイアログ操作指針](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)を参照した復帰の扱いであり、スクリーンリーダーを含む全アクセシビリティ確認の完了を意味しない。

変更前の再現は`resume-baseline.json`の4失敗。手順は、最初の候補へ理由「余白を広くしたい」と採用候補を保存→Escapeで閉じ操作位置を照合→その理由で検索→検索を空にして2候補を比較へ選択→記事/SPへ切替→再読込し比較候補と面/SPの保持を照合、の順。最終検査は`selection-catalog.spec.ts`の15件で、既存操作に加え、復元・個別解除・理由検索・破損データからの復帰・メモ保全・操作位置・PC/SPの横溢れと表示余白を確認した。

## 長いページを読みながら比較する

詳細・比較で「全体を見る」「幅に合わせる」「原寸で読む」を切り替えられる。全体表示はページの構成、幅合わせは同じ列幅での見た目、原寸は元画像のピクセル幅で文字と余白を見る用途。幅合わせ/原寸の画像内はスクロールでき、Tabで画像領域へ移動すると矢印キーで縦横に移動できる。表示方法は詳細と比較で共通にし、同じブラウザで再開時にも復元する。1〜3候補の数に合わせて比較列の幅を割り当てる。
