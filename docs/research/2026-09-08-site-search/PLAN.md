# サイト検索の追調査と代表再現

状態: 実行中。WT-FR-PAGE-02の未検証種別「サイト内検索」を具体化する提案。学習限定検索WT-FR-LEARN-01と同一視しない。正式IRへの新規候補化・全受入対応は後続の作業であり、ここで既存条件の達成を主張しない。

## 追調査（2026-09-08）

- [公的デザインシステムの検索結果](https://designsystem.gov.scot/patterns/search-results): 件数・ページ送り・ゼロ件案内を結果面の要素として示している。並び替えや関連語は任意。必須要素と追加機能を分ける参考にする。
- [検索コンポーネント](https://design-patterns.service.justice.gov.uk/components/search/): 検索入力と結果なしの案内を接続する。入力欄の設置だけで結果面の成立としない。
- [WordPressの検索クエリ](https://developer.wordpress.org/reference/classes/wp_query/): 検索語、投稿種別、公開状態、パスワード対象を別条件として扱える。独自の索引や認可をテーマに持たず、公開対象はプラグインと標準クエリの責務として検証する。

## 現状証拠と要求案

専用labの匿名・JS無効でPC/SP、結果あり・ゼロ件・空欄の6条件を照合。変更前は30検査中18失敗。index.htmlへのfallbackでは主見出し・主領域内の再検索・状態案内が欠ける。before画像は架空fixtureのみ。

1. 結果面に検索語を修正できるフォーム、検索対象と件数、結果への移動、ページ送りを持つ。
2. 結果なしと未入力を区別し、語を変える案内・再検索で復帰できる。ゼロ件を障害・404と同一視しない。
3. クエリを保持してページ移動し、範囲外ページ・公開件数減少でも実件数と矛盾しない。
4. 非公開・下書き・パスワード本文・購入本文を結果の見出し/抜粋/件数へ漏らさない。権限による標準挙動の差を確認する。
5. PC/SP・JS有効/無効で検索入力・結果移動・復帰が成立し、入力文字列がHTMLとして実行されない。
6. 投稿種別の表示と絞り込み、関連度/更新日、アクセシブルなページ送りを比較可能な追加候補として検討する。実装済みには数えない。
