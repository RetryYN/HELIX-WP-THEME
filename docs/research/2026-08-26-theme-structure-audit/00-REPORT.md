## 2. 三者の構造的性格（一行で）

- **テーマA** = 設定駆動のクラシックテーマ。オプション 1,225 キーが実質の正本で、拡張点（filter 1 本）を持たない**閉じた**設計。
- **テーマB** = ブロック・ファーストのクラシックテーマ。block.json 50 種・CPT 3 種（全て `show_in_rest`）・filter 79 本・REST 14 本を持つ**開いた**設計。
- **agent-neo** = FSE / theme.json v3 の宣言的テーマ。REST 34 コントローラ + MCP + 中間 JSON でエージェント接点が一級。ただし**運用面（ウィジェット・メニュー・CPT・ショートコードすべて 0）が空**。

## 3. 主要な発見

### 3-1. agent-neo に無いのは「機能」ではなく「面」
欠落 7 件（D-01〜D-07）のほぼ全部が、記事内広告 / CV / 再利用パーツ / 追尾サイドバー / メニューといった
**収益と回遊の置き場所**。テーマの表現力ではなく運用の面積が足りていない。

### 3-2. テーマA のゾーン構造は既にスキーマへ取り込まれている
`agent-neo-core/schema/ad-zone.schema.json` に
「CARRY-A2-001: テーマA の 4 ゾーン（h2 前挿入 / 記事終 / 関連上 / カテゴリ別上書き）に対応する静的管理」
と明記されていた。今回の実測は**その 4 ゾーンでは足りない**ことを示した（追尾サイドバー・固定ボトム・CTA 枠・11 + 24 のウィジェットエリア）。

### 3-3. 実使用が移植優先度を決める（証跡ベース）
第 1 群（100 回超）は 7 種のみ:
`themeA-blocks/simplebox`(697) / `button`(339) / `blogcard`(330) / `fukidashi`(186) / `comparechild`(177) / `themeB/dt`(106) / `themeB/dd`(106)。
一方 **テーマB のショートコード 20 種は実使用 0、CPT 3 種も実データ 0**。機構の存在と運用実態は一致しない。

### 3-4. 決定論レンダリングと衝突するのは SSR ブロック
テーマA 25 種のうち **7 種**が `render_callback` を持ち（postcard / postlist / paidpost / slider /
button / blogcard / category）、出力がオプション・投稿 DB・ログイン状態に依存する。
中間 JSON → 決定論レンダラの前提と正面から衝突するため、写像可否の個別判定が要る（THEME-INV-02）。
消化の結果、**6 種は正規化で決定論レンダラに載る／`paidpost` のみ載らない**と判定した
（`reports/INV-02-dynamic-render-semantics.md`）。

### 3-5. 操作経路の非対称
テーマB は REST 14 本（ただし `wp/v2` に相乗り）+ filter 79 本で機械操作の余地がある。
**テーマA は操作用 REST を持たず filter 1 本で、オプション書き換え以外の経路が無い**（REST 2 本はブロック描画の内部用途）。
「既存 2 サイトをハーネスから操作する」計画に対する最大の構造制約。

### 3-6. テーマA は「実装を移植する」対象ではない（RE パスの結論）
グローバル関数のみ・クラスなし・依存は require の行順のみ。設定は **手書きアクセサ 707 関数**、
動的 CSS は **単一 2,098 行関数**、ブロック契約は **block.json 無し**でエディタの単一 minified バンドル内にしか無い。
さらに未指定属性がカスタマイザ値へフォールバックするため、**同じ保存内容でも出力が変わる**。
取るべきはコードではなく**出力マークアップと意味構造**。詳細は `10-reverse-themeA.md`。

### 3-7. テーマB には中間 JSON と同型の機構が既にある
`Pre_Parse_Blocks` が `wp_head(0)` で本文を `do_shortcode` → `parse_blocks` で再帰走査し、
ブログパーツ・同期パターンは参照先まで展開、ウィジェットは `ob_start()` → 実出力 → `ob_clean()` の
**ドライラン**で収集する。`content_filter` は優先度 12 に変換群を揃え、**`is_rest()` で保存経路と表示経路を
意図的に分けている**。目次は**プレースホルダ置換方式**。中間 JSON 設計の前例として読む価値が高い（THEME-INV-15）。

### 3-8. 描画パスに DB 書き込み副作用がある（テーマA）
`themeA_customize_inline_style()` は `wp_head` にフックされた CSS 生成関数だが、内部で
**`set_theme_mod()` を 5 箇所**呼び、未設定なら既定値を DB へ書く。
閲覧やクロールが設定を確定させ、複製・移管時に「触っていないのに値が入っている」状態を生む（THEME-INV-16）。

### 3-9. 未認証 REST が 2 本ある（前回の「REST 0 本」を訂正）
複数行の `register_rest_route(` だったため初回の単一行 grep で漏れていた。
`themeA/post_by_url` と `themeA/external_url` の 2 本で、**いずれも `permission_callback => __return_true`**。
特に後者は任意 URL を検証せず `file_get_contents()` に渡しており、**SSRF の形**。
本調査は読み取りのみで到達性は未検証。実サイトの話なので優先度高（THEME-INV-13）。
