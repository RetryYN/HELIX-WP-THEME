## 2. 三者の構造的性格（一行で）

- **JIN:R** = 設定駆動のクラシックテーマ。オプション 1,225 キーが実質の正本で、拡張点（filter 1 本）も REST（0 本）も無い**閉じた**設計。
- **SWELL** = ブロック・ファーストのクラシックテーマ。block.json 50 種・CPT 3 種（全て `show_in_rest`）・filter 79 本・REST 14 本を持つ**開いた**設計。
- **agent-neo** = FSE / theme.json v3 の宣言的テーマ。REST 34 コントローラ + MCP + 中間 JSON でエージェント接点が一級。ただし**運用面（ウィジェット・メニュー・CPT・ショートコードすべて 0）が空**。

## 3. 主要な発見

### 3-1. agent-neo に無いのは「機能」ではなく「面」
欠落 7 件（D-01〜D-07）のほぼ全部が、記事内広告 / CV / 再利用パーツ / 追尾サイドバー / メニューといった
**収益と回遊の置き場所**。テーマの表現力ではなく運用の面積が足りていない。

### 3-2. JIN:R のゾーン構造は既にスキーマへ取り込まれている
`agent-neo-core/schema/ad-zone.schema.json` に
「CARRY-A2-001: JIN:R の 4 ゾーン（h2 前挿入 / 記事終 / 関連上 / カテゴリ別上書き）に対応する静的管理」
と明記されていた。今回の実測は**その 4 ゾーンでは足りない**ことを示した（追尾サイドバー・固定ボトム・CTA 枠・11 + 24 のウィジェットエリア）。

### 3-3. 実使用が移植優先度を決める（証跡ベース）
第 1 群（100 回超）は 7 種のみ:
`jinr-blocks/simplebox`(697) / `button`(339) / `blogcard`(330) / `fukidashi`(186) / `comparechild`(177) / `loos/dt`(106) / `loos/dd`(106)。
一方 **SWELL のショートコード 20 種は実使用 0、CPT 3 種も実データ 0**。機構の存在と運用実態は一致しない。

### 3-4. 決定論レンダリングと衝突するのは SSR ブロック
JIN:R 25 種のうち 9 種以上が `render_callback` を持ち、出力がオプション・投稿 DB・ログイン状態に依存する。
中間 JSON → 決定論レンダラの前提と正面から衝突するため、写像可否の個別判定が要る（THEME-INV-02）。

### 3-5. 操作経路の非対称
SWELL は REST 14 本（ただし `wp/v2` に相乗り）+ filter 79 本で機械操作の余地がある。
**JIN:R は REST 0・filter 1 で、オプション書き換え以外の経路が無い**。
「既存 2 サイトをハーネスから操作する」計画に対する最大の構造制約。
