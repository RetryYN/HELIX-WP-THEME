# 操作系 → JSON 写像表（テーマA / テーマB → 本テーマ同等の JSON 資産）

PoC 検証台で `wp.customize` から全 control（A: 1,045、B: 520）と setting 値を採取し、写像先を 1 件ずつ機械分類した（2026-08-27）。
「値あり」= 既定から変更・入力済みの control 数（A: 606、B: 275）。移管時に実際に運ぶ必要があるのはこの部分。
個票（control id・現在値・写像先）はリポジトリ外の `json-map.json` に保持（固有名を含むため）。

## 2. テーマA の hidden 166 件の正体

セクション別: デザインプリセット 26 / ボックス 19 / サイトデザイン設定 9 / スマホ専用機能 8 / メインビジュアル 7 / ボタン 6 / 吹き出し 1 5 / 吹き出し 2 5 / 吹き出し 3 5 / 吹き出し 4 5 / プリセット１ 5 / プリセット２ 5 / プリセット３ 5 / プリセット４ 5 / プリセット５ 5 / プリセット６ 5 / 見出し 4 / カラー設定 3 / CVボタン１ 3 / CVボタン２ 3 / アウトラインボタン１ 3 / アウトラインボタン２ 3 / アローボタン 3 / インフォメーション 3 / 比較表用ボタン1 3 / 比較表用ボタン2 3 / SNS登録 / シェア設定 3 / その他の設定 3 / 基本設定 2 / アニメーション設定 2

- 「デザインプリセット」26 件は **プリセット #1〜#15（プリセット名 等）の束**（色 + 見出し + ボックス + ボタン + 吹き出しの複合値）。
  → 本テーマでは `styles/*.json`（style variation）1 本 = プリセット 1 個として写像できる。**JSON 化可**。
- 「ボックス」19・「吹き出し 1〜4」各 5・「プリセット１〜６」各 5・各種ボタン 3 = **部品別のプリセット slot**。
  → block style（`styles.blocks.*` + `register_block_style`）へ写像。**JSON 化可**（ただし部品 = ブロックの対応が先に要る）。
- 残り（基本設定 2・スマホ専用機能 8・その他）は JS 内部状態。**要個別解析（~15 件）**。

結論: サンプル時点で「JSON 化不可」とした hidden は、全数で見ると **約 9 割が style variation / block style として JSON 化可能**。真に写像不能なのは 15 件前後。

## 4. 独自ブロック属性（再掲）

A 24 ブロック 559 属性（json 554）、B 33 ブロック 408 属性（json 382）。値は JSON で保持可。描画意味論は §5 のカタログで 1 ブロックずつ本テーマの受け皿（core ブロック + block style / 新規パターン / 新規ブロック）を決める。

## 5. 判定

| 問い | 答え |
|---|---|
| 操作系の **値** を本テーマ同等の JSON（theme.json / options / wp_navigation / パターン）へ置換できるか | **できる**。A: hidden 解析残 ~15 件、theme-ui 44 件を除く約 94%。B: theme-ui 1 件を除く約 99% |

| 移管作業量の目安 | 値あり control A 606 / B 275 件が実移送対象 |
