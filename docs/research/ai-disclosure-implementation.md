# AI-Generated Content Disclosure Implementation Guide

**Status**: Research synthesis (2026-06-20)  
**Focus**: WordPress plugin + backend integration for transparent AI content marking  
**Compliance target**: EU AI Act Article 50 (enforcement August 2026), Google Search Central guidance

---

## Executive Summary

AI-generated content disclosure in WordPress requires a **three-layer approach**:
1. **User-visible disclosure** (badge/indicator) — Trust signal for readers
2. **Schema markup** (JSON-LD) — Machine-readable author attribution for search engines
3. **Metadata tagging** (IPTC for images, custom fields for posts) — Regulation compliance + provenance tracking

Current WordPress ecosystem is **fragmented**: Aithenticate (visual badges) is the only plugin focused on disclosure; SEO plugins (AIOSEO, SEOPress) assist with meta *generation*, not disclosure. **Implementation gap**: No WordPress plugin currently marks content as AI-generated at the database level for system-wide compliance.

## 1. Meta Generator Tag and Schema.org Author Implementation

### 1.1 Meta Generator Tag Strategy

**Finding**: Google does NOT mandate a specific `<meta name="generator">` format, but recommends transparent information about content creation method.

**Implementation for Automation SEO**:
```html
<!-- Single AI system attribution -->
<meta name="generator" content="Automation SEO with Claude + OpenAI + Grok">

<!-- Fallback for multimodal generation -->
<meta name="generator" content="Automation SEO (claude: article generation, gpt-5.4: analysis, grok: social)">
```

**Placement**: Output by WP Plugin REST endpoint `/aseo/v1/compose` when inserting post metadata.

**Database field**: `wp_postmeta` テーブル（`$wpdb->postmeta`）
- Key: `_ai_generation_model`
- Value: JSON structure
```json
{
  "generator": "Automation SEO",
  "models": {
    "article_body": "claude-sonnet-4",
    "analysis": "gpt-5.4-mini",
    "social_content": "grok-2"
  },
  "disclosed": true,
  "disclosure_method": "meta_tag + schema + badge"
}
```

### 1.2 Schema.org Author Type for AI Content

**Critical Finding**: schema.org `author` property officially accepts only **Person** and **Organization** types—no native Bot/Algorithm support.

**Recommended Pattern A: Organization as Author Proxy** (simplest)
```json
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "Article Title",
  "author": {
    "@type": "Organization",
    "name": "Automation SEO",
    "description": "AI-generated article using Claude, OpenAI, and Grok models",
    "url": "https://automation-seo.site-B.example",
    "sameAs": [
      "https://www.anthropic.com/claude",
      "https://openai.com",
      "https://grok.com"
    ]
  },
  "creator": [
    {
      "@type": "Organization",
      "name": "Claude (Anthropic)",
      "url": "https://www.anthropic.com/"
    }
  ],
  "datePublished": "2026-06-20T10:00:00Z",
  "dateModified": "2026-06-20T10:00:00Z"
}
```

**Recommended Pattern B: Person with Disclosure Bio** (for byline display)
```json
{
  "@context": "https://schema.org",
  "@type": "Article",
  "author": {
    "@type": "Person",
    "name": "AI Writing Assistant",
    "description": "Content generated by Automation SEO using Claude AI model",
    "jobTitle": "AI Content Generator",
    "url": "https://automation-seo.site-B.example/about/ai-disclosure"
  }
}
```

**Implementation in WordPress Plugin**:

Backend endpoint `/aseo/v1/compose` generates JSON-LD schema during post creation:

```python
def generate_ai_author_schema(article_data: ArticleData) -> dict:
    """Generate schema.org author block for AI-generated content."""
    return {
        "@type": "Article",
        "author": {
            "@type": "Organization",
            "name": "Automation SEO",
            "description": (
                f"AI-generated article using "
                f"Claude ({article_data.model_version}) "
                f"for article body, GPT-5.4 for analysis"
            ),
            "url": "https://automation-seo.site-B.example"
        },
        "creator": [
            {
                "@type": "Organization",
                "name": "Anthropic - Claude",
                "url": "https://www.anthropic.com/"
            }
        ],
        "datePublished": article_data.published_at.isoformat(),
        "dateModified": article_data.modified_at.isoformat(),
        "sourceOrganization": {
            "@type": "Organization",
            "name": article_data.site_name,
            "url": article_data.site_url
        }
    }
```

### 1.3 E-E-A-T Signals with AI Disclosure

**Critical**: Pages with comprehensive author, datePublished, dateModified, and publisher metadata are **36% more likely to appear in AI-generated summaries** (ChatGPT, Perplexity, Claude, Google AI Overviews).

**Implementation**:
- Author bio should disclose AI usage + link to human editorial process
- `dateModified` updated when article is revised or AI-assisted updates occur
- `publisher` always maps to site publisher, not AI provider
- Link to transparent AI disclosure policy on site

## 2. WordPress Plugin Implementation for AI Disclosure

### 2.1 Aithenticate Plugin Integration Model

**Aithenticate** (primary disclosure tool):
- Visual badges: Blue for AI-generated, Green for human-generated
- One-click badge deployment
- Compliance layer for EU AI Act Article 50
- Each badge links to disclosure profile on Aithenticate's verification website

**Integration approach for Automation SEO**:
1. WP Plugin outputs `data-ai-disclosure="true"` attribute on `<article>` tag
2. Aithenticate badge JavaScript reads attribute and renders badge
3. Badge links to `/wp-admin/edit.php?post_type=post&ai_content=true` admin filter
4. Custom post meta `_ai_generated` = 1 stored in database for filtering

### 2.2 Custom Post Meta Structure

**Database schema** (`wp_postmeta` / `$wpdb->postmeta`):

```sql
-- AI generation metadata
INSERT INTO wp_postmeta (post_id, meta_key, meta_value)
VALUES (
  $post_id,
  '_ai_generation_disclosure',
  JSON_OBJECT(
    'disclosed', true,
    'disclosure_method', 'badge,schema,byline',
    'ai_model', 'claude-sonnet-4',
    'ai_provider', 'Anthropic',
    'model_version', '4.0.20260620',
    'generation_date', '2026-06-20T10:00:00Z',
    'human_review_status', 'approved',
    'human_reviewer_id', 12,
    'compliance_framework', 'EU_AI_ACT_ARTICLE_50',
    'edit_percentage_by_human', 5
  )
);
```

**New WP Plugin Settings** (to be added to v2.0.0 settings page):

## 3. Google Search Central Compliance Guidelines

### 3.1 Quality-First Approach (Not Method-Based Ranking)

**Key Google Position**:
> "Google does not penalize AI content. What matters is quality, accuracy, relevance, and authorship responsibility."

**Automation SEO Implementation**:
1. **Quality assurance**: QualityCheck agent validates article against site topical authority
2. **Accuracy**: Fact-check module cross-references claims against source data
3. **Attribution**: Clear byline disclosure + schema author markup
4. **Expertise**: Author bio links to human domain expert (site owner/editor)

### 3.2 Helpful Content Update: Scaled Content Abuse

**Violation risk**: Generating many pages of low-value AI content without editorial value

**Automation SEO safeguards**:
- Content created only from validated keyword research (not bulk automation)
- Each article maps to specific search intent + topical gap in site
- Editorial review required before publication (AI-assisted, not automated)
- Removal of underperforming content on 90-day rolling window

### 3.3 E-commerce Specific: AI-Generated Product Images

**Requirement**: Images must include **IPTC `DigitalSourceType` metadata** labeled as `trainedAlgorithmicMedia`

**Implementation for visual content**:
```json
{
  "image_metadata": {
    "iptc_digital_source_type": "trainedAlgorithmicMedia",
    "iptc_digital_source_type_url": "http://cv.iptc.org/newscodes/digitalsourcetype/trainedAlgorithmicMedia",
    "ai_generation_model": "DALL-E 3 / Grok Image",
    "generation_date": "2026-06-20T10:00:00Z"
  }
}
```

### 3.4 AI Overviews Opt-Out

**If needed**: Sites can suppress AI Overviews / search snippets per article using valid Google directives:
```html
<!-- スニペット（AI Overviews 含む）全体を抑止 -->
<meta name="robots" content="nosnippet" />
<!-- または最大長を 0 に設定 -->
<meta name="robots" content="max-snippet:0" />
<!-- 特定要素のみ除外する場合はインライン属性を使用 -->
<span data-nosnippet>AI 生成であることを開示する文章</span>
```

> **補足**: `noindex-snip` は Google の有効なディレクティブではない（無効値）。スニペット・AI Overviews を抑止するには `nosnippet`、`max-snippet:0`（Robots meta tag）、または `data-nosnippet` 属性を使用する。詳細は [Google 検索セントラル — robots meta タグ](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag) 参照。

**Automation SEO approach**: Opt-in by default (beneficial for discovery), selectable per article.

### 4.2 Emerging Standard: C2PA Content Credentials

**C2PA** (Coalition for Content Provenance and Authenticity):
- Cryptographic binding of provenance metadata to media files
- **EU AI Act Article 50** mandates machine-readable disclosure (August 2026)
- Native support on Samsung Galaxy S25, Google Pixel 10
- Open standard (Adobe, Arm, BBC, Intel, Microsoft)

**Implementation roadmap** (Phase C candidate):
1. Integrate C2PA library into image generation pipeline
2. Tag generated images with `trainedAlgorithmicMedia` credential
3. Embed content credentials into JPEG/PNG/WebP before upload
4. Display C2PA badge on article pages for high-trust scenarios

**Reference**: https://spec.c2pa.org/

### 4.3 IPTC Metadata for AI-Generated Images

**Field**: `DigitalSourceType = trainedAlgorithmicMedia`

**XMP data packet** (stored in image file):
```xml
<rdf:RDF>
  <rdf:Description rdf:about=""
    xmlns:Iptc4xmpCore="http://iptc.org/std/Iptc4xmpCore/1.0/xmlns/"
    Iptc4xmpCore:CreatorContactInfo="https://automation-seo.site-B.example"
    Iptc4xmpCore:IntellectualGenre="AI-Generated"
  >
    <Iptc4xmpCore:CiAdrCtry>JP</Iptc4xmpCore:CiAdrCtry>
  </rdf:Description>
</rdf:RDF>
```

**WordPress challenge**: Image re-encoding (WebP, AVIF) often strips XMP metadata. Mitigation:
- Store metadata in `wp_postmeta`（`update_post_meta()` 経由）with reference to attachment ID
- Display metadata in article template even if image is re-encoded
- Use CDN that preserves IPTC metadata (e.g., Cloudinary, Imgix)
