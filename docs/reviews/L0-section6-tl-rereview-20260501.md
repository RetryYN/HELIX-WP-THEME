## Phase B: 新規矛盾チェック

### 矛盾候補 1: ループ図 vs 23 件機能の整合
判定: ⚠️
所見: §6.3 は運用フローの抽象図としては成立しているが、§6.6 の 23 件と 1:1 で照合できる形にはなっていない。たとえば Phase 1 セットに含まれる `REQ-F-001/002/003/010/017/029/042` はループ図に直接現れず、逆に `手動 X 投稿運用` は要件 ID に紐付かない（`66-106` vs `167-176`）。監査用には、各ループ要素がどの REQ 群を前提にしているかを 1 行注記した方がよい。

### 矛盾候補 2: 公開指標ポリシーと §6.8 の重複
判定: ✅
所見: §6.4 は「何をどの条件で公開してよいか」の方針表、§6.8 は「過剰開示や障害時に何が起きるか」のリスク表として役割分担できている。直接矛盾は見当たらない（`128-147` vs `205-214`）。

### 矛盾候補 3: §6.5「成立条件」と §6.6 ローンチ機能の整合
判定: ❌
所見: `個人版先行` は `記事/BLP 中心`、`個人版の収益化ブロックと BLP を早く見せられる` と記述されている（`155, 159`）。しかし L1 では BLP は `REQ-F-005` の一部であり、`法人版限定` と定義されている（`docs/requirements/L1-requirements.md:51`）。一方、個人版は `REQ-F-016` で `HP / sidebar / archive / single` の固定テンプレ構成に限定される（`57`）。さらに §6.6 の `個人導線` グループも `REQ-F-004 / REQ-F-016 / REQ-F-030` のみで、BLP を含まない（`173`）。このため、個人版先行の成立条件説明が L1 と §6.6 の双方から浮いている。

### 矛盾候補 4: 「手動投稿」の言葉の妥当性
判定: ⚠️
所見: `手動投稿運用` は Phase 配分を伝える補助語としては機能しているが、L1/NSRM の要件名ではないため、製品機能なのか人間運用なのかが初読で曖昧である（`31, 36, 56, 81, 174, 181`）。ここは「WP 運用者が共有導線から X に人手投稿する運用」を明示した方が誤読を防げる。

### 矛盾候補 5: 公開指標ポリシーの「24h 以上遅延公開」
判定: ✅
所見: 表中の `24h 以上遅延公開（推奨、要確認）` と本文の `最終値は PO 確認事項とする` により、前提値であって断定ではないことは明示されている（`132-147`）。
