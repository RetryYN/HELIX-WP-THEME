## 観点別レビュー（18 観点を順番に判定）

### 観点 1: F-018/F-019/F-020 と X 投稿導線の整合
判定: ❌
所見: 現行 NSRM 正本では Phase 1 は `REQ-F-018` のうち「シェアボタン + OGP」のみで、自動投稿は Phase 2、`REQ-F-019/020` も Phase 2 配置である。一方、ドラフトは `記事公開時の投稿導線` と `X 投稿導線（記事公開時）` を Phase 1 文脈で読める形に置いており、自動投稿前提にも読める。さらに Threads / LINE の扱いは NSRM と整合的でも、L1 `REQ-F-018` 本文とは未整合である。
指摘事項: P1-01 文書整合不備。Phase 1 の X 導線が「共有/OGP」なのか「自動投稿」なのか読者が確定できない。
推奨アクション: `Phase 1 = 共有導線 + OGP/X Card + 手動または運用起点投稿`、`Phase 2 = 自動投稿/複数アカウント/LINE 深い統合` と本文で固定し、ADR-006 未凍結事項として脚注化する。

### 観点 2: Q-002 は自社サイトの初期 IA を先に決めてから判断する整理でよいか
判定: ✅
所見: Q-002 を機能順ではなく「初期 IA の顔つき」から逆算する整理は、PO 原則「自社サイト = 製品 = 販売 LP」に整合する。ドラフトは決定権を PO に残しており、TL が結論を先取りしていない。
指摘事項: なし
推奨アクション: Q-002 の参照先として、L0 §10 / L1 §8 の open 状態も明記すると追跡しやすい。

### 観点 3: 法人版先行 / 個人版先行 / 同時 の推奨度が論理的に妥当か
判定: ⚠️
所見: 推奨ロジック自体は妥当で、法人版先行が「販売 LP としての説得力」、個人版先行が「検索資産の厚み」で優位という整理は首尾一貫している。ただし `高 / 中 / 条件付き` の表現は、IA 未決・PO 未決の段階ではやや結論を先に出し過ぎる。
指摘事項: P2-01 推奨度表現が判断材料表より一段強い。
推奨アクション: `推奨度` を `成立条件 / 向いている前提` に置き換え、PO が決める判断軸の表として見せる。

### 観点 4: `phase_1_mvp` キーを「Phase 1 ローンチセット」と読み替える方針
判定: ✅
所見: PO 原則として MVP 概念を採らない一方、`phase_1_mvp` は NSRM/HELIX の機械可読キー名であり、本文側で「ローンチセット」と明示読み替えするのは許容できる。機械キーと事業用語を分離しており、論理破綻はない。
指摘事項: なし
推奨アクション: `HELIX 標準命名のためキー名は残置、事業上の呼称は Phase 1 ローンチセット` を一文で固定する。

### 観点 5: Phase 1 ローンチ可否に `REQ-NF-001f/014/015/017/018` を実質必須として添える整理
判定: ✅
所見: 自社サイトが販売 LP 兼実証環境である以上、性能予算、契約整合、AI運用性、LLMO、運用ハザード管理を実質必須とみなす判断は妥当である。機能 22/23 件の列挙だけではローンチ可否を判定できないため、この補足は必要。
指摘事項: なし
推奨アクション: これら 5 件は「追加機能」ではなく「ローンチ判定基準」であることを注記する。必要なら NF-016（配布品質）も別系統の必須ゲートとして追記する。

### 観点 6: 公開ダッシュボードや live counter の公開範囲
判定: ⚠️
所見: 「匿名化する」「PO/TL 判断とする」だけでは基準が粗い。自社サイトが sales proof であるほど、公開指標は景表法・誤認表示・競争上の情報漏えい・問い合わせ数の過度な可視化に直結する。
指摘事項: P1-02 公開範囲の allowlist / denylist が未定義。
推奨アクション: 公開可は `集計済み / 遅延あり / 自社サイト全体 / 個人非識別` のみとし、`顧客別数値 / リアルタイムCV / 売上 / 問い合わせ件数 / 内部改善ログ詳細` は非公開と明記する。

### 観点 7: X を主力 SNS としつつ、Threads / LINE 公式を Phase 2 オプションに置く整理
判定: ⚠️
所見: PO の販促方針には整合する。X 主力、SEO 主軸、Automation SEO 運用が前提だからである。ただし L1 `REQ-F-018` は Threads を必須対応 SNS と読めるため、「Phase 2 オプション」は Go-To-Market 優先度の話なのか、製品機能 Phase の話なのかを分けて書く必要がある。
指摘事項: P2-02 チャネル優先度と機能実装 Phase が混線している。
推奨アクション: `販促主戦場は X`、`Threads/LINE は製品 capability としては保持、販促運用の主戦場には置かない` と二層で明記する。

### 観点 8: 有料広告 / PR Times を初期主戦場にしない判断
判定: ✅
所見: PO 制約が `SEO + X + Automation SEO` を主軸としている以上、初期に有料広告や PR Times を主戦場にしない判断は矛盾しない。むしろ「自社運用実績を先に証拠化する」という本章の論理と一致する。
指摘事項: なし
推奨アクション: なし

### 観点 9: 価格戦略・競合比較を再掲せず参照に留める境界
判定: ✅
所見: ドラフトは価格表や競合採点表を持ち込まず、09・26 を参照に留めている。流入・運用・自社実証ループに集中できており、既存解析との重複回避として適切である。
指摘事項: なし
推奨アクション: なし

### 観点 10: PO 原則「MVP 不採用」の遵守
判定: ✅
所見: 機械確認では `MVP / ベータ / alpha / pilot / 最小限 / 実験 / 仮説検証` の該当語は本文に存在しない。加えて論理面でも、Phase 1 を「最初に出せる形」でなく「販売開始できる完成セット」と定義しており、PO 原則に適合する。例外は機械キー `phase_1_mvp` のみで、これは本文で読み替え済みである。
指摘事項: なし
推奨アクション: `MVP` は機械キー名に限る旨を注記し、事業文脈では今後も使用しない。

### 観点 11: §6.0 既存内容の残置
判定: ✅
所見: §6.0 の製品ファネル記述は L0 正本の既存 §6 を実質そのまま保持しており、既存企画の販売構造を壊していない。無料プラグイン → Plan B → テーマ受け皿 → Automation SEO 別課金の流れも一致する。
指摘事項: なし

### 観点 12: L1 要件 ID の引用整合

### 観点 17: §6.4 公開戦略のリスク
判定: ⚠️
所見: ドラフトは `自社サイト障害 = 販売停止 = 証拠停止` を認識しているが、`Built with AGENT NEO` とページ別機能注記を強く打ち出す割に、競合に実装意図・導線設計・改善観点を読まれるリスクと、障害時にブランド毀損を緩和するフォールバック設計が十分に書かれていない。
指摘事項: P2-03 競争上の情報開示リスクと障害時ブランドリスクが過少評価。
推奨アクション: 6.8 に `競合模倣リスク` と `障害時フォールバック導線` を追加し、公開する機能説明は原理レベルに留め、内部運用ノウハウは開示し過ぎない方針を明記する。

### 観点 18: 法務観点
判定: ❌
所見: live counter / 公開ダッシュボードについて、現状は「匿名化する」「顧客名を出さない」止まりで、個人情報保護、GDPR/越境、景表法上の実績表示、特商法上の表示責任、同意取得・保存期間・集計閾値・遅延公開・監査証跡の条件が文書化されていない。法務観点ではこのまま正本化できない。
指摘事項: P1-05 公開データの法務ガード未整備。
推奨アクション: `公開指標ポリシー` を別表で追加し、公開可否、匿名化単位、公開遅延、集計閾値、保存期間、根拠ログ、広告表現レビュー責任者を定義する。

## 総合所見

本ドラフトは、PO 原則を壊さずに「自社サイト運用そのものを販売根拠に変える」という §6 の方向性を明確化できている点で評価できる。特に、価格・競合の再掲を避けて運用と販売証拠化に集中した構成はよい。一方で、この章は販売戦略であると同時に Phase 境界と公開ポリシーを読者に誤読させやすい章でもあるため、SNS Phase 整合、Phase 1 件数、公開指標の法務基準の 3 点はマージ前に確実に固めるべきである。
