# L2 Screen Flow

## 通常

`WT-UI-01 パターン / パーツ / 変種選択 → 差し替えプレビュー → 構造差分確認 → 保存 → WT-UI-07 ゲート → WT-UI-05 / 06 公開面確認`

AI 経路は `WT-UI-08 manifest 取得 → 選択 → dry-run 差分 → apply → WT-UI-07 ゲート → WT-UI-05 / 06 確認` で同じ結果に到達する。
値の編集は `WT-UI-03 値入力 → 安全域 / 生値 / 破壊域の判定表示 → 保存（破壊域は停止）`。記事単位の切替は `WT-UI-04 メタ切替 → 公開面確認`。サイト全体の既定は `WT-UI-10 設定画面で編集 → 保存（schema 検証）→ 公開面確認`、AI は同じ設定 JSON を MCP パックから読み書きする。商品一覧は `WT-UI-10 ProductCatalogTable で追加・更新 → 商品カード等への差し込み → 商品 CTA クリック計測` とし、購入完了は外部側で扱う。
クローラー計測は `WT-UI-11 ダッシュボード表示 → クローラー別推移 / 古い URL / 404・5xx / 初回捕捉時間 / AI クローラーアクセス確認 / llms.txt 効果実証用アクセス時系列 → robots.txt・AI クローラー許可 / 拒否を設定 → 設定 JSON 保存` で行う。ログの取得は WP が応答したリクエストに限り、MCP / REST は同じデータを読む。
追加タブは `WT-UI-10 A/B の variant 選択 → cookie 固定配信 → variant ID 付き impression / click / CV 確認 → 承認・停止・rollback`、`画像最適化 → ブラウザ側処理 → 非ブラウザ経路の dry-run / 非同期処理 → 進行・削減見込み確認`、`操作ログ → 絞り込み → CSV / JSON export`、`鍵管理 → 発行（値は一度だけ表示） / 失効`、`共通 + device 別差分 → 主たる確認面のサイト設定 → SP / PC 両幅プレビュー → 代表ページ種別確認`、`タグ slot → 出し分け → data layer 契約差分 / Consent Mode v2 7 種写像 → 同意状態確認`、`第三者プラグイン検出 → 領域別既定 / 警告 → manifest 確認` の流れで行う。API 契約と 3 面の能力集合は `WT-UI-08 manifest / 契約差分 → dry-run` で確認する。
SNS / CV / バナーは `WT-UI-10 正本の編集 → 記事・LP・section へ選択 → 公開面で表示・計測確認` とし、CV は主文言と任意 microcopy を選ぶ。監査は `WT-UI-10 指摘一覧 → 対象 section へ移動 → 適用 / 却下 / 保留 → 適用時は dry-run → 差分レビュー` とする。

## 取消

差し替え・値入力・メタ切替を保存前に取り消した場合は theme.json・テンプレート・メタ・option に何も書かず、編集前の状態へ戻る。dry-run は何も書かない。

## failure

ゲート FAIL は対象ファイル・ゲート ID・原因（生値、参照欠落、尺度再定義、Block validation invalid）を示し、修正の再入場条件を出す。
破壊域停止は「どの規則に、どの値が、どの境界で」触れたかを示し、権限による解除手段を提示しない。manifest 外の指定は拒否理由付きで返す。
差分レビューで却下・保留された変更は適用せず、rollback は直前の digest へ戻す。期限切れ・リンク切れ・計測ゼロのバナー、Discover 画像要件未達、alt 欠落、予算超過は WT-UI-10 の警告として残す。SP / PC の両幅でタップ領域・文字サイズ・横スクロール・固定要素の被覆・ドロワーと固定バーの積層を検査し、違反は赤にする。軽いブロックの device 別非表示は Block Visibility を使えるが、広告面・CTA 束・バナー・商品テーブル等の重い面を同機能だけで出し分けた場合は赤にする。タグ slot 外の script 注入、consent default の注入順違反、同意前のカテゴリ該当タグ発火、データ層必須項目・7 種写像の欠落は赤にする。第三者プラグイン検出時に二重出力・二重フォーム送信があれば赤にする。microcopy 未選択だけでは公開前に赤にしない。
クローラー判定外の閲覧を記録せず、UA と逆引き / 公開 IP レンジ照合の結果を確認できない場合は bot として記録しない。キャッシュ / CDN 応答はダッシュボードの対象外であることを表示する。

## timeout/recovery

実機ゲート（G-E1）の docker 起動 timeout と dry-run の timeout は再実行で同一結果を返す。途中結果を pass として扱わない。apply 後の失敗は rollback で元の digest に戻す。

## navigation

Site Editor / Block Editor の各面へは WP 標準ナビゲーションで到達する。テーマ独自メニューはテーマ設定画面（WT-UI-10、PO 2026-09-02）の 1 つだけを追加し、A/B・画像・運用・CV・バナー・監査はそのタブとして扱う。WT-UI-11 は Core プラグインの管理画面として扱う（画面数 11、PO 2026-09-03）。
