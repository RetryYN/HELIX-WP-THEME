- 証拠の状態の語彙（WT-EVT-0300「未検証を対応済みとは扱わない」）:

## 3. 継承セット（0298 §4 の 5 種）と段 10c の束の対応

段 10c の束の台帳 `wt_side_bundles()` は「名前 → 軸接頭辞」。継承セットの追加は 1 行 + 軸 5 本。5 種は固定上限ではない（0300）。

| 継承セット（提案） | 主な対象 | 段 10c での実体 | 状態 |
|---|---|---|---|
| サイト案内系 | HOME、企業、サービス、店舗、採用 | HP 側の束 `home_side_*`（固定ページの既定継承先） | 対応済み（サイドバーのみ。ヘッダー・フッター・CTA の束化は未検証） |
| 読物・回遊系 | 記事、カテゴリ、有料記事、インタビュー、事例 | 記事側の束 `side_*`（カテゴリの既定継承先） | 対応済み（同上） |
| 独立訴求系 | LP、BLP、キャンペーン、一部イベント | 束 none（LP）/ `event_side` off 既定 | 対応済み（LP は非表示として。「目的別に選ぶ」= 独自設定 own の束（面別の `own_category_side_* / own_event_side_* / own_page_side_*`、Astra 1 巡目で共通の own_side_* から是正）をカテゴリ / イベント / 固定ページで検証。LP 自体で own を選ぶ検証は無い） |
| 学習・支援系 | マニュアル、講座、用語集、ヘルプ | 無し | 未観察（目次・階層ナビ・前後・検索を重視する束の代表モックが必要） |
| 会員・手続き系 | 購入、予約、会員ホーム、購読管理 | 無し | 未観察（現在の手続き状態を優先し無関係な誘導を抑える束。外部機能の画面との接続を含む） |

継承の分離（0299）: **継承**（束を選ぶ）/ **独自設定**（面別の own の束 `own_<face>_side_*`）/ **非表示**（off）。さらに 0298 §4 の「サイトの共通規則（認可・同意）と見た目・導線を別扱い」は未着手（フォームと同時に扱う）。

## 4. 着手順（0299 の指示を写した順序。観察頻度だけで決めない）

1. **A**: 共通設定（ヘッダー・フッター・CTA・サイドバーの束化の残り）とフォーム（送信・確認・完了・失敗の遷移、同意）。
2. **B**: 有料記事・インタビュー・BLP の固有部分を代表モックで早期確認（状態 × 表示用途、人物・発言・掲載確認、理解 → LP への送客）。
3. **C**: 残りの種別を代表モックで順次（テーマ別ハブ / 特集、学習・支援系、常設説明の面、キャンペーンの期限遷移、法定表示・FAQ 面）。
4. **D**: 会員・決済・予約・認証は外部機能との接続、権限別表示、遷移の確認のみ。業務処理をテーマ内へ持ち込まない。

## 5. 更新規則

- 行の追加・証拠状態の更新は events.jsonl の証跡（PR・verify・INDEX）を根拠に行い、「対応済み」へ上げる条件は verify 行 + 撮影の両方。
- 系統の追加は上限ではない前提（0300）で行う。追加時は元 7 分類との対応列を空にせず「－」で明示する。
- PO の問い（例: 0296「LP と BLP は分割してもいいがどうする？」）は決定に昇格させない。採否は PO の決定イベントだけを根拠に書く。
