7分類を維持・拡張する形で、私は次の**9系統**に整理します。有料記事とインタビューは、通常記事のオプションではなく別管理です。

## 1. ページの分類案

| 大分類 | 独立して扱うページ種別 | 主な役割 |
| --- | --- | --- |
| **①入口・案内・探索** | HOME、事業別／メディア別トップ、カテゴリー、テーマ別ハブ、編集特集、サイト内検索 | サイトや領域の目的を伝え、目的の情報・商品・サービスへ案内する |
| **②企業・事業の常設説明** | 会社紹介、ブランド紹介、サービス詳細、機能説明、料金、店舗・拠点、アクセス、採用紹介 | 運営主体や提供価値を理解してもらう。サイト内で継続的に参照する説明の基盤 |
| **③情報発信・信頼形成** | 無料記事、ニュース、コラム、**有料記事、インタビュー**、導入事例、実績・作品、調査レポート、レビュー | 集客、教育、信頼形成、情報そのものの販売 |
| **④イベント・キャンペーン** | セミナー、展示会、説明会、体験会、期間限定企画、募集企画、キャンペーン | 参加・応募・期間内の行動を促す。受付期間や開催状態を持つ |
| **⑤資料・学習・参照** | 資料ダウンロード、ホワイトペーパー、テンプレート配布、用語集、マニュアル、講座、レッスン、動画・音声ライブラリ | 情報を持ち帰る、体系的に学ぶ、必要なときに調べ直す |
| **⑥比較・獲得・販売** | **BLP、LP**、比較・選定ページ、商品販売ページ、予約対象の詳細、求人・募集要項 | 理解・比較から、購入・申込・予約・応募へ進める |
| **⑦手続き** | 問い合わせ、資料請求、申込、応募、予約、カート、決済、入力確認、完了・失敗 | 行動を実際に完了させる。説明するページと手続きするページを分離する |
| **⑧会員・継続利用** | 会員ホーム、購入済みコンテンツ、購読管理、購入・予約履歴、お気に入り、学習履歴、コミュニティ | 購入・登録後に価値を提供し、継続利用を支える |
| **⑨支援・規約・システム補助** | FAQ、ヘルプ、サポート窓口、利用規約、プライバシー、各種表示、ログイン・認証、404、メンテナンス | 利用上の不安や問題を解消し、サイトを安全に利用できるようにする |

**大分類は整理するためのまとまりで、実際の管理単位は「ページ種別」です。**
例えば③に含まれていても、有料記事・インタビュー・導入事例を全部「記事」という一つの編集画面へ押し込める想定ではありません。

## 2. 元の7分類から、特に分けたいところ

### イベントから「特集」「資料」を分離する

| 元のイベント枠に含まれるもの | 拡張後の分類 |
| --- | --- |
| セミナー・説明会・展示会 | **イベント** |
| 期間限定セール・プレゼント・募集企画 | **キャンペーン** |
| 関連記事をまとめて読ませる特集 | **編集特集・テーマハブ** |
| ホワイトペーパー・資料ダウンロード | **資料** |

見た目がLPに似ていても、管理対象は異なります。**開催日時を持つもの、施策の期限を持つもの、情報を束ねるもの、配布物を持つもの**を別管理にします。例えばセミナーなら「イベント詳細＋申込フォーム＋完了画面」、資料なら「資料紹介＋取得フォーム＋ダウンロード画面」という組み合わせです。**ページ種別を分けても、一つの導線としてつなげられます。**

### 「企業・サービス説明」と「LP」を分離する

**サービス詳細ページ**は、そのサービスの常設説明を担うページ。**LP**は、特定の対象者・流入・訴求に合わせて行動を促すページ。同じサービスでも、常設のサービス詳細は1つ、広告や対象顧客別のLPは複数、という構成を許します。サービス名や基本情報は共用しても、訴求順序やヘッダー・CTAまで一緒にはしません。料金、機能、導入事例、インタビューなどを常設説明へ接続し、その一部をLPでも参照できる形です。

### 「インタビュー」「導入事例」「レビュー」も別にする

| ページ種別 | 管理の中心 |
| --- | --- |
| **インタビュー** | 誰が、何を語ったか。人物・所属・発言・掲載確認 |
| **導入事例** | 誰の、どの課題が、何によって、どう変わったか |
| **レビュー** | 何を、どんな条件・基準で評価したか |
| **実績・作品** | 何を制作・提供したか。成果物・担当範囲・関連情報 |

インタビュー形式の導入事例も作れますが、**形式が対談だから管理もインタビューへ移す、とはしません。** 主たる管理対象を決め、関連する人物や素材を共用する案です。

### LPとBLPは別のページ種別にする

**BLPは「理解・納得を進めて、次のLPへ送る」ページ。LPは「その場で申込・購入意思を固める」ページ**という区分を維持します。比較ページも、商材の理解を促して販売先へつなぐならBLPです。一方、独立した情報提供が目的なら比較記事として扱います。**「比較表がある」という見た目だけでは分類しない**方針です。

## 3. 「一覧・詳細・埋め込み」は、別の分類軸にする

例えばインタビューという一つの管理対象から、**一覧ページ、詳細ページ、企業ページ内の抜粋、サービスページ内のカード**を出します。有料記事なら、一覧・販売案内・試し読み・購入者向け本文を、同じ記事の状態と表示用途に応じて出し分けます。

> **ページ種別＝何を管理するか**
> **表示形式＝それをどう見せるか**
> **閲覧・受付状態＝今、誰に何を許すか**

を分離します。WordPressでも、投稿型、カテゴリーなどの分類、表示テンプレートは別の仕組みとして扱えます。独立した投稿型にカスタム分類を関連付け、詳細・アーカイブや個別テンプレートを使い分けられます（WordPress 公式 Plugin Handbook「Registering Custom Post Types」）。

## 4. 共通設定は「5種類の基本セット」から選ぶ

| 基本セット | 主な対象 | 既定の考え方 |
| --- | --- | --- |
| **サイト案内系** | HOME、企業、サービス、店舗、採用紹介 | 全体ナビと主要サービスへの導線を重視 |
| **読物・回遊系** | 記事、カテゴリー、有料記事、インタビュー、事例 | 読みやすさ、関連記事、著者、回遊導線を重視 |
| **独立訴求系** | LP、BLP、キャンペーン、一部イベント | サイト案内系・読物系からの自動継承を切り、目的別に選ぶ |
| **学習・支援系** | マニュアル、講座、用語集、ヘルプ | 目次、階層ナビ、前後の項目、検索を重視 |
| **会員・手続き系** | 購入、予約、会員ホーム、購読管理 | 現在の手続き・利用状態を優先し、無関係な誘導を抑える |

**ページ種別ごとに推奨セットを持たせますが、固定はしません。** 例えばイベントでも、申込を完結させるなら独立訴求系、サイト全体への理解を深める展示企画ならサイト案内系を選べます。ヘッダー・サイドバーなどの部品単位でも変更可能にします。そして継承は「サイトの共通規則」と「見た目・導線」を別扱いにします。LPが独立訴求系でも、認可や同意などの共通規則まで外れる設計にはしません。

## 5. 範囲を広げても、すべてをテーマの自作機能にはしない

**対応する画面を増やすことと、決済・購読・予約などの処理をテーマ内に実装することは別**です。例えば〔EC 系プラグイン〕には商品一覧、カート、決済、マイアカウントなどの画面があります。こうした外部機能の画面も、WP-THEME側で一貫した見た目・導線として扱う、という拡張ができます。

独立コンテンツの登録・管理はCoreプラグイン側、表示はテーマ側、決済などの業務処理は対応プラグインや外部サービス側へ分ける案です。カスタム投稿型をテーマではなくプラグインに置くことは、テーマ変更時にもコンテンツを維持するためのWordPress公式推奨とも一致します。

**この分類なら、企業サイト・メディア・有料コンテンツ・採用・イベント・教育・ECまで、ページ種別を混同せずに広げられます。** モックでは「ページ種別を選ぶ → 基本セットを選ぶ → 固有項目と状態を設定する → 次の遷移先をつなぐ」という操作に落とすのが、私の推奨です。
