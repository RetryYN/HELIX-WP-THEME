### ThemeBの良いポイント

ThemeBはAIエージェント前提で扱いやすい。`block.json` とREST routeが多く、機能境界を機械的に見つけやすい。CPT、ブロック、REST、設定画面が比較的分離されており、Automation SEO側が「何を読めるか」「何を操作できるか」を推定しやすい。

### ThemeBの悪いポイント

ThemeB固有REST routeは便利だが、`/wp/v2/themeB-reset-*` や `themeB-do-update-action` のような強い操作名がpublic indexに見える。権限があっても、AIエージェント向けにはdry-run、監査ログ、操作schema、rollback idがないと安全運用契約としては不足する。

### テーマAの良いポイント

テーマAはSEO設計の思想がテーマ内に統合されている。SEOメタ、canonical、noindex、OGP、JSON-LDをテーマの体験として扱っているため、初心者・個人アフィリエイト向けに「設定すればSEOらしい出力が揃う」方向に強い。

### テーマAの悪いポイント

REST/ブロック契約が薄く、AIエージェントが安全に差分更新するには追加の契約層が必要。AJAXとテーマ内グローバル関数が多いため、操作対象を機械的に特定しにくい。PHP 8.3 warningがWP CLI実行だけで再現しており、今後のPHP/WP更新で破綻しやすい箇所がある。

## AIエージェント運用における不都合な真実

| 不都合 | テーマA | ThemeB | AGENT NEOでの回避 |
|---|---|---|---|
| UIパーツの機械可読性 | 低い。CSS class/ショートコード/AJAX寄り | 高い。block.json/RESTが多い | 全section/CTA/cardにschemaとIDを付与 |
| SEO出力の保証 | テーマ思想は強いが運用で欠落し得る | 実運用では強いが設定依存あり | DOM実測SEO smoke testを標準化 |
| 速度 | 運用プラグインで崩れやすい | 軽量運用に乗せやすい | ページ予算、画像予算、script budgetを契約化 |
| API安全性 | REST少数でAI操作しづらい | REST多いが強い操作名も見える | dry-run、audit log、rollback、capability matrix |
| 更新性 | PHP warningあり | update checker/権限境界が見える | WP/PHP互換CI、deprecated検出 |
| LLMO/AI crawler | h1/JSON-LD欠落が起き得る | 構造化しやすい | answer unit、entity graph、citation blockを標準搭載 |

| 領域 | 採用方針 |

## WP 7.0 / 将来互換で見ておくべき点

WordPress 7.0そのものは本検証時点では未リリースの将来イベントであり、公式互換要件は確定していない。そのため、ここではWP 6.9.4 + PHP 8.3で見えた将来リスクとして扱う。

| リスク | 現状 | 対策 |
|---|---|---|
| PHP警告の厳格化 | テーマA Customizerで多数発生 | null coalesce、isset、型初期化、CIでPHP 8.3/8.4 warning fail |
| Block Editor進化 | テーマAはblock.jsonなし | FSE/block.json/schemaへ寄せる |
| REST contract拡大 | ThemeB/Automation SEOはpublic indexに多数露出 | schema、permission、dry-run、auditを契約化 |
| WP-Cron依存 | connectorが1時間cron | system cron/queue、失敗再試行、last_success記録 |
| SEOプラグイン共存 | テーマSEOとプラグインSEOの二重出力リスク | head output registryと競合検出 |
