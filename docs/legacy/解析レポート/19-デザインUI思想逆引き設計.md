# デザイン/UI思想逆引き設計

## 結論

AGENT NEOで真似るべきものは、参照テーマの見た目そのものではなく「失敗しにくい情報設計の型」である。

| 参照元 | 強み | AGENT NEOで真似る思想 |
|---|---|---|
| ThemeB | 読みやすい記事/カード/タブ/CTA、設定で崩れにくい、LPと記事導線が堅実 | 情報整理、可読性、収益導線、条件付き表示、編集者が迷わないパーツ化 |
| テーマA | メインビジュアル、フォント/丸み/デザインルール、デモプリセット、リッチメニューの訴求力 | 第一印象、世界観プリセット、トップページの入口設計、初心者でも選べるデザインUX |
| AGENT NEO | AI操作、JSON契約、法人LP/個人アフィリエイトの2パッケージ | 「AIが改善できるデザインシステム」として再構築 |

失敗しにくいテーマにするには、自由度を増やすのではなく、選ぶだけで破綻しにくい`blueprint`、`section preset`、`design token`、`conversion pattern`を用意する。

## R1: 逆引きしたUI思想

### 1. 入口で迷わせない

| 観測 | 思想 | AGENT NEO化 |
|---|---|---|
| ThemeBのタブ、pickup、post slider | トップページは記事一覧ではなく入口の整理 | `gateway-grid`、`pickup-card`、`category-route` |
| テーマAのrich menu/main visual | 最初の1画面で世界観と次アクションを示す | `hero-blueprint`、`top-gateway-blueprint` |

### 2. デザインは自由入力ではなく選択式

| 観測 | 思想 | AGENT NEO化 |
|---|---|---|
| テーマAのflat/material、角丸、フォント選択 | 初心者でも破綻しにくい抽象設定 | `design-preset.json` |
| ThemeBのメインビジュアル高さ/余白/overlay | 見た目の調整幅を安全な範囲に限定 | `visual-composition.schema.json` |

### 3. パーツは「見た目」ではなく「目的」で作る

| 観測 | 思想 | AGENT NEO化 |
|---|---|---|
| FAQ、Step、Button、Tab、Post List | 用途が明確なblockは編集しやすい | `purpose-first-blocks` |
| CV button、blog card、profile、timeline | 読者の不安解消や次行動に直結 | `conversion-parts` |

### 4. 記事/LP/HPで視線の型を変える

| ページ | 視線 | 失敗しにくい型 |
|---|---|---|
| 記事 | F型 | 見出し、囲み、FAQ、CTAで視線リセット |
| LP | Z型 + セクション下降 | Hero、Problem、Solution、Proof、CTA |
| HP | Gateway型 | Hero、入口メニュー、主要カテゴリ、信頼、CTA |
| 比較記事 | 表比較型 | Best Pick、Ranking、Comparison、Review、FAQ、CTA |

### 5. 装飾よりも不安解消

| 観測 | 思想 | AGENT NEO化 |
|---|---|---|
| PR表記、著者、プロフィール、関連記事 | 信頼要素をページ内に埋め込む | `trust-layer` |
| FAQ、Step、Timeline、Review | 決断前の疑問を減らす | `objection-handling-sections` |

## R2: 真似れば失敗しにくい型

### 共通Core

| 型 | 内容 | 理由 |
|---|---|---|
| 12-column + readable content width | 本文は狭め、LP/HPは広め | 読み物と訴求ページの役割が違う |
| 8px spacing scale | 余白を倍数管理 | AIが一貫したUIを生成しやすい |
| 70-25-5 color ratio | 背景70、補助25、CTA5 | CTAの視認性を保つ |
| 1 primary CTA / 1 secondary CTA | CTAを増やしすぎない | 迷いを減らす |
| Design preset first | 先に世界観を選ばせる | 初心者でも破綻しにくい |

### 個人アフィリエイト

| 型 | 推奨 |
|---|---|
| Hero | 検索意図への結論 + PR表記 + Best Pick |
| Ranking | 3〜5件に絞る。1位だけ強く、残りは比較しやすく |
| Comparison Table | 価格、向き不向き、注意点、CTAを固定列にする |
| Review | いい点/悪い点/向いている人/向かない人/根拠 |
| CTA | 記事中は控えめ、比較後は強め、最終CTAは明確 |
| Trust | 著者、検証日、レビュー根拠、PR表示を隠さない |

### 法人LP/HP

| 型 | 推奨 |
|---|---|
| Hero | 対象者、成果、証拠、CTAを1画面に収める |
| Problem | 読者が自分ごと化できる課題を3つ以内 |
| Solution | 機能ではなく成果から説明 |
| Proof | ロゴ、数値、事例、Before/Afterを早めに出す |
| Pricing | 価格を出す/出さないの両方に対応。問い合わせ導線を明確化 |
| Final CTA | 資料DL、無料相談、デモ申込のどれかに絞る |

## R3: AGENT NEOのデザイン原則

### Design Principles

| ID | 原則 | 内容 |
|---|---|---|
| DP-001 | 目的先行 | block/sectionは「何のためか」を先に持つ |
| DP-002 | 選択式の自由度 | 色・角丸・フォント・密度はpresetで選ばせる |
| DP-003 | 入口を設計する | HP/トップは記事一覧ではなくgatewayとして作る |
| DP-004 | CTAを絞る | 1画面の主CTAは原則1つ、補助CTAは1つまで |
| DP-005 | 証拠を近くに置く | CTAの前後にproofを置く |
| DP-006 | 視線をリセットする | 長文では見出し、画像、囲み、比較表、FAQを意図的に挟む |
| DP-007 | AIが改善できる単位にする | すべてのsectionに`section_id`、CTAに`cta_id` |
| DP-008 | 装飾を成果に紐づける | 動き/背景/影/角丸はコンバージョンか可読性に寄与する場合だけ |
| DP-009 | 日本市場の安心感 | FAQ、根拠、著者、実績、注意書きを隠さない |
| DP-010 | コピー禁止 | 参照テーマのCSS、画像、文言、デモ構成はコピーしない |

### Design Preset

| Preset | 対象 | 視覚言語 |
|---|---|---|
| `affiliate-clear` | 個人収益記事 | 白背景、比較表強め、PR明示、CTAは明るい単色 |
| `affiliate-editorial` | 専門メディア | 余白広め、著者/根拠重視、落ち着いた配色 |
| `corporate-trust` | B2B法人HP | ネイビー/グレー基調、数値/ロゴ/事例を強調 |
| `corporate-product` | 製品LP | Heroを強く、CTAを明確化、図解/機能カード |
| `startup-bold` | SaaS/新規事業 | 大見出し、非対称レイアウト、グラデーション背景 |
| `local-business` | 士業/店舗/地域企業 | 安心感、顔/実績/地図/問い合わせ導線 |

## R4: 設計へ落とす契約

### JSON契約

| 契約 | 役割 |
|---|---|
| `design-preset.schema.json` | 配色、角丸、フォント、密度、装飾量 |
| `visual-composition.schema.json` | セクション余白、グリッド、Z/F/Gateway型 |
| `section-pattern.schema.json` | Hero、Proof、FAQ、Pricingなどの型 |
| `conversion-intent.schema.json` | CTA目的、offer、反論処理、証拠 |
| `trust-layer.schema.json` | 著者、実績、レビュー根拠、検証日、PR表示 |
| `ui-risk.schema.json` | CTA過多、証拠不足、情報密度過多、PR表記不足を警告 |

### UI Audit

| Audit | 検出する失敗 |
|---|---|
| `cta.overload` | CTAが多すぎて主行動が曖昧 |
| `proof.too_late` | 証拠が価格/CTAより後にしか出ない |
| `hero.vague` | 誰向け/何が得られる/何をすればよいか不明 |
| `comparison.missing_basis` | 比較根拠や検証日がない |
| `visual.no_hierarchy` | 見出し、本文、CTAの強弱が弱い |
| `mobile.tap_target_small` | mobileのタップ領域が小さい |
| `affiliate.disclosure_weak` | PR表記が見えにくい |

## 不採用にする真似方

| 不採用 | 理由 |
|---|---|
| 参照テーマのCSS class/画像/文言/デモをコピー | ライセンス/独自性リスク |
| 装飾パターンを無制限に増やす | AI生成とユーザー選択が破綻する |
| テーマA型の巨大global CSS | 速度と保守性が落ちる |
| ThemeB型のCPT/計測/RESTをthemeに抱え込む | plugin territoryとデータ移植性の制約 |
| CTAを各セクションに無制限配置 | CVRではなく迷いが増える |
| なんとなくSaaS風の青白UI | 法人版の差別化が弱く、価格の根拠にならない |
