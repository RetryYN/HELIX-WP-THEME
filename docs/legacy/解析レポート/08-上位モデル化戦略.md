# 上位モデル化戦略

## 前提

目的は、参照テーマの良いところをすべて学習対象として抽象化し、より強い設計に作り直すこと。コード、画像、固有CSS、固有文言、商標的な表現はコピーしない。取り込むのは、機能カテゴリ、編集体験、設計パターン、運用思想、ユーザー価値である。

## 上位モデルの定義

| 観点 | 参照テーマから学ぶこと | 上位モデルで改良すること |
|---|---|---|
| 編集体験 | ブロックと設定で記事/LPを作れる | JSON契約でAIエージェントも同じ操作をできる |
| 収益化 | 広告、CTA、レビュー、ランキング | アフィリエイト専用の計測・PR表記・比較表まで統合 |
| LP構築 | LPテンプレート、Full Wide、CTA | 法人向けLPセクションビルダーに拡張 |
| 設定管理 | 管理画面に多機能設定 | package別UI + JSON export/import + preset |
| パフォーマンス | CSS分割、遅延読み込み | block usage解析、critical CSS、計測付き最適化 |
| SEO | 構造化データ、パンくず、FAQ | 個人はReview/FAQ、法人はOrganization/Product/FAQに最適化 |
| 運用 | CPT、再利用パーツ | 個人は広告/商品、法人はCTA/LPセクションを再利用管理 |
| 連携 | REST、Gutenberg、管理画面 | GA4/GTM/ASP/HubSpot/AI action連携を前提化 |

## 奪うべき長所と改良方針

| 長所 | そのままの価値 | 改良後の設計 |
|---|---|---|
| 薄い起動層 | 保守しやすい | `Bootstrap` + `FeatureRegistry` + package matrix |
| parts分割 | テンプレート差し替えがしやすい | `layout-registry.json` で宣言的に構成 |
| block.json中心 | 編集体験が強い | `block-registry.json` と同期し、AI生成/検証可能にする |
| 広告タグ管理 | アフィリエイト向き | `affiliate-manager` として広告、商品、CTA、計測を一体化 |
| LP投稿タイプ | LPを独立管理できる | 法人向け `lp-section-builder` とテンプレートpreset化 |
| 再利用パーツ | CTAや共通部品を使い回せる | 法人向けに承認/用途分類/差分管理を追加 |
| CSS分割 | 表示速度に効く | ブロック使用解析 + package別bundle + critical CSS |
| REST計測 | CTA/広告効果を見られる | nonce/rate limit/event schema/GTM adapterで堅牢化 |
| 管理画面設定 | 多機能 | 個人/法人で表示項目を絞り、迷わせない |
| エディター装飾 | 執筆速度が上がる | 収益記事/法人LPに特化したブロックpresetへ寄せる |

## 参照テーマより強くする差別化

| 差別化 | 内容 |
|---|---|
| AIファースト | すべての主要操作をJSON actionでdryRun可能にする |
| パッケージファースト | 個人アフィリエイトと法人LPを最初から別UXにする |
| CVファースト | 見た目より、CTA、比較、計測、改善サイクルを中核に置く |
| トークンファースト | CSS直接編集ではなく、design tokensから見た目を生成 |
| 連携ファースト | GA4/GTM/ASP/HubSpot等へのadapterを標準設計に入れる |
| 検証ファースト | block schema、REST contract、security guardを必須にする |

## 個人アフィリエイトで上回るポイント

| 領域 | 上位モデル機能 |
|---|---|
| 商品訴求 | Product Card、Review Box、Ranking、Comparison Tableを標準化 |
| 収益導線 | Affiliate CTA、Ad Slot、Blog Card、Related Postを統合 |
| 計測 | affiliate_click、ad_click、ranking_cta_clickを標準イベント化 |
| 法務/信頼 | PR表記、nofollow/sponsored、広告開示を自動化 |
| SEO | FAQ、Review、Article、Breadcrumbを記事タイプに応じて出し分け |
| AI支援 | 商品比較表、レビュー構成、FAQ、CTA文言をJSONで生成可能 |

## 法人LPで上回るポイント

| 領域 | 上位モデル機能 |
|---|---|
| LP構築 | Hero、Problem、Solution、Feature、Benefit、Case Study、Pricing、FAQ、CTAを標準セクション化 |
| ブランド統制 | Brand Tokens、Component Preset、禁止色/余白ルール |
| リード獲得 | 資料DL、問い合わせ、デモ申込、外部フォーム遷移の計測 |
| 再利用 | CTA、FAQ、導入事例、製品カードをCPT/JSONで管理 |
| 運用 | 設定export/import、権限、監査ログ、承認フロー候補 |
| AI支援 | 製品LPをJSON briefから組み立て、差分レビュー可能 |

## 欠点として潰すべきもの

| 欠点候補 | 改良 |
|---|---|
| 多機能ゆえに設定が重い | package別にUIを分ける |
| PHP配列中心でAIが扱いにくい | JSON manifestを正にする |
| REST計測が雑に作られると危険 | event schema、nonce、rate limit、重複排除 |
| ショートコードが増えると保守しづらい | ブロック中心、ショートコードは互換用 |
| CSS/JSが肥大化しやすい | 使用ブロック検出、package別bundle |
| 法人運用には承認/監査が不足 | 法人パッケージで段階導入 |

## 実装優先度

| Phase | 目的 | 成果物 |
|---|---|---|
| Phase 1 | 上位モデルの骨格 | Bootstrap、package matrix、design tokens、block registry |
| Phase 2 | Core編集体験 | FAQ、Step、Button、Post List、Accordion |
| Phase 3 | 個人アフィリエイト特化 | Product Card、Review、Ranking、Comparison、Affiliate CTA、Ad Tag |
| Phase 4 | 法人LP特化 | LP Section Builder、Hero、Feature、Case Study、Pricing、Lead CTA |
| Phase 5 | 計測/連携 | event API、GTM adapter、affiliate/lead tracking |
| Phase 6 | AI操作基盤 | agent actions、dryRun、diff review、schema validation |

## 成功条件

| 条件 | 判定基準 |
|---|---|
| 個人パッケージが強い | レビュー/比較/ランキング/CTA/広告計測がテンプレート化されている |
| 法人パッケージが強い | 製品LPがセクション選択とJSON briefから構成できる |
| 参照テーマより扱いやすい | 設定がpackage別に絞られ、迷わない |
| AIで完結できる | 主要操作がJSON actionでdryRunできる |
| 安全に運用できる | REST、計測、設定更新にnonce/rate limit/権限チェックがある |

## 結論

上位モデル化の中心は「多機能テーマ」ではなく「目的別に最適化されたテーマ基盤」にすること。個人はアフィリエイト収益化、法人は製品LPとリード獲得に振り切る。参照テーマの強みは、ブロック、再利用パーツ、設定、計測、パフォーマンスの考え方として取り込み、実装はJSON操作とAIエージェント前提で作り直す。
