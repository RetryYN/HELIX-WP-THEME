# AIエージェント運用性とクローラビリティ分析

## 結論

ThemeB/テーマAは、人間管理者と通常検索エンジンには十分使いやすいが、AIエージェントが継続運用する前提では不都合が多い。最大の問題は、ページ構造、編集意図、CTA、SEO、計測、公開可否、クローラ許可方針が「人間が読めば分かるUI/HTML」に分散していて、AIが安全に判断できる契約になっていないこと。

AGENT NEOでは、AIエージェント運用性をテーマの差別化要件にする。具体的には、公開ページ、REST、MCP、WP CLI、管理画面、robots.txt、sitemap、構造化データ、ログをすべて「AIが読める契約」に揃える。

## 不都合な真実

| # | 不都合な真実 | 参照テーマでの兆候 | AGENT NEOでの対策 |
|---|---|---|---|
| 1 | AIはブラウザ操作だけでは安定運用できない | Customizer、管理画面、class名、JS UIに依存 | REST/MCP/WP CLIを正本にし、UIは補助面にする |
| 2 | DOM classは意味契約ではない | `c-`、`p-`、`o--`、`a--`等は見た目/部品識別で、CV意図までは示さない | `data-agent-section-id`、`data-agent-role`、`data-cta-id`を必須化 |
| 3 | lazyload/infinite loadはAIクローラに不利 | ThemeBのlazyload、テーマAのloadmore/AJAX | 静的HTML/JSON snapshotに全主要情報を出す |
| 4 | REST routeがあっても契約がないとAIは壊す | ThemeBの独自RESTはresponse形が混在 | OpenAPI、JSON Schema、dryRun、idempotencyを必須化 |
| 5 | SEO状態が複数箇所に分散しやすい | テーマAのhead出力、post meta、option、ThemeBのJSON-LD/SEO plugin連携 | `seo-meta.schema.json`と`crawlability-profile.json`へ集約 |
| 6 | noindex/robots/canonicalはAIが誤ると致命傷 | テーマAはnoindex設定が多いがAI向け理由/影響説明はない | critical SEO change warning、impact diff、approval gateを必須化 |
| 7 | AIクローラは「クリック」「タブ切替」「もっと見る」を期待できない | tab、accordion、loadmore、sliderが多い | 主要コンテンツはHTMLかcontent snapshotに展開 |
| 8 | robots.txtは法的/技術的な完全防御ではない | 既存テーマ側にAI crawler policyは見えない | robots、Content Signals、WAF/ログ監視を分ける |
| 9 | AI検索露出とAI学習許可は別問題 | OpenAI/Google/Anthropicでbot目的が分かれる | search/ai-input/ai-trainを別々に制御する |
| 10 | AIエージェントは「なぜこの設定か」を読めない | theme_mod/optionに値はあるが意図メタがない | change reason、owner、expires_at、sourceを保存する |
| 11 | 既存テーマはロールバックの単位が粗い | 設定更新やSEO変更の差分復旧が弱い | section/page/seo/action単位のrollback point |
| 12 | 外部URL取得はAI運用で攻撃面になる | テーマAの`file_get_contents($post_url)` | SSRF guard、allowlist、fetch job化 |

## 扱いやすいポイント

| ポイント | 参照元 | AGENT NEOで伸ばす方向 |
|---|---|---|
| block.json中心のブロック | ThemeB | block registryをAI操作の正本にする |
| JSON-LD Entity Graph | ThemeB/テーマA | Entity GraphをAIが読める公開/管理APIへ出す |
| noindex/canonical/OGP UI | テーマA | SEO変更のdiff、risk score、approval workflowを追加 |
| data属性による部品状態 | ThemeB/テーマA | 見た目用data属性ではなくAI契約用data属性を分離 |
| REST route | ThemeB/テーマA | vendor namespace、OpenAPI、標準responseへ再設計 |
| lazyload/条件付きasset | ThemeB | 人間表示速度とAI snapshotを両立する |
| post list / ranking / CTA部品 | 両方 | `section_id`、`offer_id`、`cta_id`、`evidence_id`を付ける |
| PR表記や`data-nosnippet` | ThemeB | AI/検索向けにPR、根拠、検証日を契約化 |

## AIエージェントが苦手な運用対象

| 対象 | 苦手な理由 | 必要な補助契約 |
|---|---|---|
| Customizer設定 | 値は取れても意図・影響範囲が不明 | `settings-intent.schema.json` |
| Classic PHP template | セクション意味がHTMLから推定になりやすい | `section-registry.schema.json` |
| タブ/アコーディオン | 非表示DOMやJS状態を見落とす | `content-snapshot.schema.json` |
| もっと見る/AJAX | 初期HTMLにない投稿を認識しづらい | `crawl-map.json` |
| Slider | 代表画像/CTA/順序が曖昧 | `visual-priority.schema.json` |
| SEOメタ | 変更ミスの影響が大きい | `seo-risk.schema.json` |
| A/Bテスト | variantと結果の紐付けが壊れやすい | `experiment-contract.schema.json` |
| 外部タグ | 計測・同意・速度が絡む | `third-party-tags.schema.json` |
| robots.txt | search/training/user-requestの目的差を表現しにくい | `crawler-access-matrix.json` |

## AIクローラ/検索AIへの考慮

### 前提

AIクローラは1種類ではない。検索表示、ユーザー要求による取得、モデル学習、広告審査など目的が違う。AGENT NEOでは「AIに見せる/見せない」を単一スイッチにしない。

| 目的 | 代表例 | 方針 |
|---|---|---|
| Search | OAI-SearchBot、Googlebot系 | 公開記事/LPは許可し、検索・AI検索で発見されやすくする |
| User requested fetch | ChatGPT-User、Claude-User | robots.txtだけに頼らず、公開ページの安全な取得を前提にする |
| Training | GPTBot、ClaudeBot、Google-Extended等 | サイト方針に応じて許可/拒否を明示する |
| AI input / grounding | RAG/AI検索要約 | 重要ページだけ許可、薄い一覧/重複ページは抑制する |
| Suspicious scraper | UA偽装、過剰巡回 | WAF、rate limit、bot log、path制御で防御する |

### robots.txtプリセット

| Preset | 用途 | 方針 |
|---|---|---|
| `ai_search_open_train_closed` | 推奨初期値 | Searchは許可、AI trainingは拒否 |
| `ai_all_open` | 認知獲得優先 | Search、AI input、trainingを許可 |
| `ai_search_only` | 企業/権利保護寄り | Searchのみ許可、trainingとAI inputは拒否 |
| `ai_closed` | 非公開性重視 | 主要AI crawlerを拒否。検索流入低下リスクを表示 |
| `custom` | 法務/ブランド方針あり | botごとに制御 |

### 推奨robots.txt例

```text
User-agent: *
Allow: /
Sitemap: https://example.com/sitemap.xml

User-agent: OAI-SearchBot
Allow: /

User-agent: GPTBot
Disallow: /

User-agent: Google-Extended
Disallow: /

User-agent: ClaudeBot
Disallow: /

Content-signal: search=yes, ai-input=yes, ai-train=no
```

`Content-signal`は新しい考え方で、すべてのcrawlerに技術強制できるものではない。AGENT NEOでは、robots.txt生成、Content Signals、WAF連携、ログ監視を別レイヤーとして扱う。

## AGENT NEOに追加すべき契約

| 契約 | 役割 |
|---|---|
| `agent-operability.schema.json` | AIが触れる対象、危険度、承認要否、rollback可否を定義 |
| `dom-anchor.schema.json` | `data-agent-section-id`、`data-agent-role`、`data-cta-id`等のDOM契約 |
| `content-snapshot.schema.json` | AI/クローラ向けの静的ページ要約、全section、CTA、schema、robots状態 |
| `crawlability-profile.json` | indexability、robots、canonical、sitemap、AI crawler方針を管理 |
| `crawler-access-matrix.json` | crawler別にsearch/ai-input/ai-train許可を定義 |
| `ai-crawler-log.schema.json` | AI crawler access、robots violation、rate limit、WAF actionを記録 |
| `rendered-content-digest.json` | HTML/JSON-LD/snapshotの差分hashを持つ |
| `agent-readable-sitemap.xml` | 優先ページ、更新日、section数、content typeを示す補助sitemap |
| `settings-intent.schema.json` | 設定値の理由、owner、期限、変更元を保持 |
| `seo-risk.schema.json` | noindex/canonical/robots/schema変更のrisk scoreを定義 |

## AI Snapshot設計

AIエージェントやAIクローラがJSを実行しない/クリックしない前提でも理解できるように、公開ページごとに安全なsnapshotを出す。

| Endpoint | 役割 |
|---|---|
| `GET /wp-json/agent-neo/v1/public/pages/{id}/snapshot` | 公開情報だけのページ構造 |
| `GET /wp-json/agent-neo/v1/public/crawl-map` | 公開ページ一覧、canonical、robots、更新日 |
| `GET /wp-json/agent-neo/v1/public/entities` | Organization、Product、Article、FAQ等の公開Entity |

Snapshotに含めるもの:

| 含める | 含めない |
|---|---|
| title、description、canonical、robots | 下書き、非公開、会員限定情報 |
| section一覧、heading、本文抜粋 | 個人情報、管理者情報、secret |
| CTA label、destination domain、offer id | nonce、license、内部token |
| FAQ、Product、Review、Breadcrumb | 生の計測ログ |
| updated_at、content_hash、schema_hash | AI内部プロンプト |

## AI Agent Readiness Score

AGENT NEOの競合優位を測るため、AI運用性をスコア化する。

| 評価軸 | Lv1 | Lv3 | Lv5 |
|---|---|---|---|
| 操作契約 | GUIのみ | RESTあり | REST/MCP/WP CLI/OpenAPI統一 |
| DOM安定性 | class依存 | 一部data属性 | 全section/CTAにstable ID |
| SEO安全性 | 手動設定 | noindex/canonical UI | risk diff + approval + rollback |
| クローラ対応 | 通常sitemapのみ | robots制御 | crawler matrix + snapshot + logs |
| JS非依存 | JS前提 | 主要本文はHTML | snapshotと静的HTMLで全主要情報 |
| 監査性 | 更新履歴なし | 操作ログあり | actor/reason/diff/rollback完備 |
| 外部連携 | 個別実装 | adapterあり | contract test + fallback |

初期目標は全軸Lv4以上。競合との差別化は、速度やデザインだけではなく「AIが安全に運用できる」ことをスコアで示す。

## 公式情報からの設計反映

| 公式情報 | 反映 |
|---|---|
| OpenAI crawler docs | `OAI-SearchBot` と `GPTBot` は用途が違うため、search許可とtraining拒否を分ける |
| Google crawler docs | `Google-Extended` はGoogle Search登録とは別の制御tokenなので、検索SEOとAI利用制御を混同しない |
| Anthropic crawler docs | `ClaudeBot`、`Claude-User`等を分け、Crawl-delayやrobots設定を扱えるようにする |
| Cloudflare managed robots docs | `Content-signal: search/ai-input/ai-train` とWAF/監視を設計に入れる |
| Google Search technical requirements | クロール可能、HTTP 200、indexable contentを満たすことを最低条件にする |
