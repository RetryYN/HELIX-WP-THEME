## 修正必須（ブロッカー 2 件）

### P1-06: §6.5 個人版先行の BLP 前提を撤去・SKU 境界整合化

L1 正本での SKU 境界:

- **BLP（記事 LP / Blog LP）= 法人版限定**。L1 [REQ-F-005](../../requirements/L1-requirements.md) で「HP/LP/BLP 三位一体は法人版核心価値」と定義
- **個人版 = REQ-F-016 固定テンプレ構成**（HP / sidebar / archive / single の標準テンプレ 1 セットのみ、HP/LP/BLP 構造変更スコープ外）
- 個人版で扱えるのは「記事」「アーカイブ」「商品カード」「アフィリ CTA」など、§6.6 の `個人導線 = REQ-F-004 / REQ-F-016 / REQ-F-030` の範囲

→ §6.5 の表「個人版先行」行を以下のように修正：

- 「整合しやすいサイト像」: `記事 / BLP 中心、アフィリエイト寄り` → **`記事 / アーカイブ 中心、アフィリエイト寄り`**（BLP を削除）
- 「成立条件」（旧メリット）: `SEO 記事資産を厚く作りやすい。個人版の収益化ブロックと BLP を早く見せられる。` → **`SEO 記事資産（記事 + アーカイブ + 商品カード）を厚く作りやすい。個人版の固定テンプレ構成（REQ-F-016）と収益化ブロック（REQ-F-030）を早期に live demo として見せられる。`**
- 「向いている前提」（旧デメリット）: 既存記述を保持しつつ、`法人 LP/BLP の証拠は法人版ローンチまで作れない` を追記

§6.5 末尾の散文（「自社サイトを販売 LP 兼運用ショーケースとして使う度合いが強いなら…」）も同様に、**個人版先行 = BLP なし** を反映して書き換える。

### P2-02: §6.5 から「推奨としては」を撤去・PO 決裁余地を完全に残す

§6.5 の散文段落で「**推奨としては、… 法人版先行が整合的である。同時ローンチは魅力的だが…**」のような TL 結論先置きを撤去。

代わりに以下のような中立的整理に書き換える：

> 上記いずれを選んでも成立しうる。決定要因は「自社サイトの初期 IA を法人 LP 寄りで設計するか、記事/アーカイブ寄りで設計するか」である。前者を選べば法人版先行、後者を選べば個人版先行が機能・証拠面で整合する。同時ローンチは Phase 1 ローンチセットの完成条件と公開時の証拠密度を二面同時に満たす必要があり、運用負荷が最も大きい選択肢になる。決定は PO に委ねる。

→ 「推奨度」「成立条件」列も完全に「成立条件 / 向いている前提」のみとし、特定選択肢に肩入れしない記述にする。

## 軽微修正（3 件、同時反映）

### P3-01: §6.3 自社運用ループと §6.6 23 件 REQ の対応注記

§6.3 の Phase 1 ループ図の各ステップに、対応する REQ 群を 1 行注記する。例：

```text
自社サイト（AGENT NEO 本番運用）           [REQ-F-001 / 003 / 010 / 042]
  ↓
記事生成 → AGENT NEO に POST              [REQ-F-002 / 003 / 025 / 011]
  ↓
記事公開・OGP 生成                         [REQ-F-018]
  ↓
seo-tool-connector で計測                  [REQ-F-006 / 007 / 026 / 027]
  ↓
WP 運用者が共有導線から X へ人手投稿       [REQ-F-018 範囲内]
  ↓
SEO 流入継続強化                           [REQ-F-011 / NF-017]
  ↓
CV（テーマ購入 / S1 問い合わせ）            [REQ-F-005 / 030 / 031]
```

Phase 2 拡張ループも同様に H2 編集 = REQ-F-022、要素 swap = REQ-F-023、自律 A/B = REQ-F-024、自動投稿 = REQ-F-018 拡張 / F-019 / F-020 と注記。

### P3-02: 「手動投稿」を「WP 運用者の人手投稿」と再定義

ドラフト中の「手動投稿」「手動投稿運用」をすべて以下のように書き換える：

- 単独で出る箇所: 「**WP 運用者の人手投稿**」
- 文脈で十分な箇所: 「**人手投稿**（WP 運用者がシェア導線から X へ手動で投稿する運用）」

これにより「製品機能としての投稿」と「人間運用としての投稿」を明確化。
