## レビュー観点

### Phase A: 前回再レビュー指摘（5 件）の反映完全性

各指摘について「✅ 完全反映 / ⚠️ 部分反映 / ❌ 未反映」を機械的に判定。

#### ブロッカー 2 件
- **P1-06**: §6.5 個人版先行の BLP 前提撤去 + L1 SKU 境界整合
  - 「BLP」が個人版先行の前提から完全に消えているか
  - 「記事 / アーカイブ 中心、アフィリエイト寄り」または同義の SKU 整合表現になっているか
  - REQ-F-005（法人版限定）/ REQ-F-016（個人版固定テンプレ）/ REQ-F-030（個人版収益化）と齟齬がないか
- **P2-02**: §6.5 から「推奨としては」TL 結論先置きを撤去 + PO 決裁余地完全保持
  - 「推奨としては」「推奨度」「TL 推奨」等の TL 結論先置き表現が残存していないか
  - §6.5 全体が「PO が選ぶための成立条件比較表」に徹しているか
  - 「決定は PO に委ねる」表現が維持されているか

#### 軽微 3 件
- **P3-01**: §6.3 ループ図に各ステップ対応 REQ 注記追加（Phase 1 / Phase 2 両方）
  - 各ステップに `[REQ-F-XXX]` 形式の注記が付いているか
  - §6.6 の 23 件と機械的にトレース可能か
- **P3-02**: 「手動投稿」→「WP 運用者の人手投稿」統一
  - ドラフト全体で「手動投稿」単独表記が残っていないか（grep）
- **P3-03**: 改訂履歴「TL レビュー反映済」→「前回 TL 指摘反映版」修正

### Phase B: 2 次修正に伴う新規矛盾チェック

1. **§6.5 表構造の整合**: 表の見出し（成立条件 / 向いている前提）と各行の内容が論理的に揃っているか
2. **§6.3 REQ 注記と §6.6 23 件の 1:1 トレース**: ループに登場する REQ ID が §6.6 の 23 件にすべて含まれているか / §6.6 の 23 件のうちループに現れない REQ がある場合、それは「裏で動く基盤」として説明されているか
3. **「人手投稿」と F-018 範囲の整合**: F-018（Phase 1）が定義する「シェア導線 + OGP + X Card」と「WP 運用者の人手投稿」の関係が文書内で明確か
4. **§6.5 中立化と §6.4 / §6.6 の整合**: §6.5 で結論を出さない方針と、§6.4 / §6.6 が暗黙に「法人版先行を想定した記述」になっていないか
5. **修正反映ログの 2 段階構成**: 1 次・2 次が分離され、どの指摘がどの修正に対応するか明確か

### Phase C: PO 原則遵守再確認

1. **禁則語スキャン**（grep で機械的に確認）:
   - `MVP`、`ベータ`、`β`、`α`、`pilot`、`最小限の検証`、`実験`、`仮説検証`、`α 版`、`アルファ版`
   - `推奨としては`、`TL 推奨`（PO 決裁侵食）
   - `手動投稿`（単独表記、再定義後の正規表記以外）
   - `22 件`（旧件数）、`TL レビュー反映済`（旧改訂履歴表記）
2. **自社サイト = 製品 = 販売 LP 原則の論理整合**
3. **PO 決裁余地**: §6.5 / §6.6 / §6.7 で PO 決定事項が明確に分離されているか

### Phase D: 前回観点で見落としがあれば指摘

特に：
