## レビュー観点

### Phase A: 前回指摘の反映完全性

前回 TL レビューが指摘した以下が**完全反映されているか機械的に検証**する：

#### ブロッカー 3 件
- **P1-01**: F-018/F-019/F-020 と X 投稿導線の Phase 整合
  - §6.2 / §6.3 / §6.6 のすべての箇所で「Phase 1 = シェア導線 + OGP + X Card + 手動投稿」「Phase 2 = 自動投稿 / 複数アカウント / LINE 深い統合 / SNS API 認証情報管理」となっているか
  - F-018 本文（自動投稿言及）への参照が、ドラフト側で適切に「Phase 1 範囲では自動投稿は含まない」と注記されているか
- **P1-04**: Phase 1 ローンチセット件数
  - 「23 件」表記に統一されているか（22 件の残存がないか）
  - F-041 が §6.6 の機能リストに含まれているか
  - nsrm.yaml `metrics.phase_1_count: 23` と完全整合
- **P1-05**: 公開指標ポリシー
  - §6.4 末尾または §6.8 直前に「公開指標ポリシー」表が存在するか
  - 個人情報保護法・景表法・特商法・GDPR・同意取得・公開遅延・保存期間・根拠ログ・表示責任者の各条項が明記されているか
  - 公開可・公開不可の代表例が示されているか

#### 軽微修正 4 件
- **M1**: §6.5「推奨度」→「成立条件」または「向いている前提」への変更
- **M2**: §6.3 自社運用ループの Phase 1 / Phase 2 拡張分離
- **M3**: §6.2 Threads/LINE の二層表現（Phase 1 販促主戦場ではない / Phase 2 capability 保持）
- **M4**: §6.8 リスク表に「競合模倣リスク」「障害時のブランドリスク + 静的フォールバック導線」追加

### Phase B: 修正に伴う新規矛盾チェック

修正で新たに発生した可能性のある矛盾を検出する：

1. **ループ図の整合性**: §6.3 の Phase 1 / Phase 2 ループ図が、§6.6 の機能 23 件と 1:1 で照合できるか
2. **公開指標ポリシーと §6.8 の重複**: §6.4 末尾の公開指標ポリシーと §6.8 リスク表の項目が矛盾なく分業されているか
3. **§6.5「成立条件」と §6.6 ローンチ機能の整合**: 「法人版先行 / 個人版先行 / 同時」の各成立条件が、Phase 1 ローンチセット 23 件で実際に成立可能か（特に法人版先行が REQ-F-005/F-012/F-013/F-031 で本当に十分か、個人版先行が REQ-F-004/F-016/F-030 で本当に十分か）
4. **「手動投稿」の言葉の妥当性**: F-018 が定義するのは「シェア導線 + OGP」であり、「手動投稿」は WP 運用者の人間操作を指すのか / それとも別の何かか。意味が曖昧でないか
5. **公開指標ポリシーの「24h 以上遅延公開」**: PO 確認前の前提値であることが明示されているか（断定になっていないか）

### Phase C: PO 原則の遵守再確認

1. **MVP 関連禁則語の完全排除**: `MVP`、`ベータ`、`β`、`α`、`pilot`、`最小限の検証`、`実験`、`仮説検証`、`α 版`、`アルファ版` の文字列が含まれていないこと
2. **「自社サイト = 製品 = 販売 LP」原則**: 修正で追加された記述（特に競合模倣リスク・静的フォールバック）が、原則と論理矛盾していないか
3. **PO 決裁余地**: ドラフト全体が「PO が決定する事項」と「ドラフトが提示する判断材料」を明確に分離しているか

### Phase D: 前回未指摘だが新規発見した課題

前回観点 18 件 + 上記 Phase A/B/C で拾えていない問題があれば指摘する。
