# ADR-031: 一次オーケストレーターを automation SEO から HELIX-MARKETING-HARNESS へ変更する

- status: proposed
- date: 2026-08-13
- decision_authority: PO
- 関連: ADR-024（配布モデル）、docs/design/api-catalog.md §17（catalog-update）、HELIX 側 ADR-008/ADR-010

## 背景

1. 本テーマ/プラグインの外部連携は automation SEO backend（/opt/seo-tool）を一次 consumer と
   想定して設計された（catalog-update push・ライセンス照会・HMAC 契約）。
2. automation SEO の開発は停止された（2026-08 PO 判断）。
3. HELIX-MARKETING-HARNESS（helix-worker 上のマーケティング運用 OS）が実働の
   オーケストレーターとして立ち上がり、agent-neo/v1 に対する実機検証
   （コンテンツ/デザイントークン/actions 2 段階コミット/jobs — 全 PASS）を完了している。
4. `integration_health.automation_seo: not_configured` での縮退動作は実機で確認済みで、
   コア機能は単独で完結する。

## 決定（提案）

1. **一次オーケストレーター = HELIX-MARKETING-HARNESS**。agent-neo/v1 は HELIX の
   V1 WordPress 媒体アダプタの第一契約とする。
2. **外部認証経路**: 外部エージェントの書込みは Application Password（Basic）を正規経路とし、
   nonce は cookie 認証時のみ要求する（CSRF 対策の本来の適用範囲に限定）。
3. **catalog-update / ライセンス**: 送信先・照会先は設定値（endpoint option）であり、
   automation SEO 固有の実装は持たない。HELIX 側 evidence/KPI 基盤が受け手となる場合の
   契約凍結は別 ADR で行う（本 ADR は方向の確定のみ）。
4. ADR-024 の「automation SEO 専用配布」は「HELIX 経由運用サイト向け 1st party 配布」へ読み替える。
5. 文書上の「automation SEO」参照は歴史的記録（ADR・carry・レビュー）を除き、
   HELIX 連携の記述へ改訂する。

## 帰結

- CLAUDE.md / AGENTS.md の連携前提の書き換え（本コミットで実施）
- design-tokens の表示投影（presenter）を製品本体の責務に追加（HELIX 実機検証からの還流）
- 検証環境: HELIX 側 poc（poc.solobiz-lab.com + helix-worker）を実機フィードバックループとして使用
