# ADR-001: FSEテーマとして実装

- Status: Accepted
- Date: 2026-06-14
- Phase: L2 / Gate: G2

## Context
- AIエージェントが「見る・触る・更新」を機械的に行う設計が必要で、`block/theme.json` と `block.json` を前提とした運用が前提である。`L2設計 2.2` でも WordPress FSE / theme.json / block.json を採用し、目的はAI操作しやすい宣言的構造を担保することとされている。
- テーマ表示層をFSE化することで、AIに安定した編集単位（section/block）を提供し、`§8.8` の DOM/スナップショット系前提と整合する。

## Decision
- WordPressテーマ実装は `FSEテーマとして実装` を採用する。表示側は theme.json と block.json を基盤化し、AI運用での差分更新、可読性、再適用性を高める。

## Consequences
- 良い面: AIオペレーション向けに編集単位が明確になり、Automation SEO 側の安定参照（セクション・CTA・構造化）と接続しやすい。
- 制約: 既存の classic テーマ系ワークフローや独自フックを使った一部実装は前提が変わる。
- 制約: FSE更新時のテーマ側差分対応、環境依存（WP/FSE対応）を前提とする。

## Alternatives considered
- `非FSEテーマでの継続` は、AI編集性と配列安定性の要件を満たしにくいとして不採用。
