# ADR-028: テーマのカスタマイズ余地境界 ― エンドユーザー設定UIは持たない / 制作側の Global Styles・Variation・パターン編集の余地は残す

## Context

AGENT NEO は AI 運用型 WP テーマとして Automation SEO と連携し、記事生成・LP改善・CTA/A-Bテストを自動実行する。このアーキテクチャにおいて、テーマのカスタマイズ設計について以下の問いが生じた。

**問い**: 受託制作や AI 生成物の手直しのために「どこまで制作側に上書き余地を提供するか」を設計として明文化する必要がある。

**背景にある二つの引力**:

1. ThemeB は Customizer 331設定・独自パネル等の分厚いエンドユーザー設定 UI を持つ。AGENT NEO がこの方向を採れば、非技術者ユーザーがテーマを自由にカスタマイズできるが、AI 生成コンテンツとの競合・設定の肥大化・保守コストの増大を招く。
2. 一方、制作側（受託制作者・運営者）が AI 出力の調整・微修正をしたい場面は発生する。FSE 標準の上書き経路（Global Styles / Style Variations / 追加CSS / 非同期パターン）を閉じてしまうと、この正当なニーズを遮断し商用テーマとしての実用性を損なう。

また、AI 再生成との競合回避の観点から、制作側調整はテーマ層（Style Variations / Global Styles / 追加CSS）で行う設計が望ましい。ブロック単位インライン上書きは投稿再生成で消えうるため非推奨とする。

---

## Decision

テーマのカスタマイズ余地を以下の二分で設計する。

### D1: エンドユーザー向けの分厚い設定UIは持たない

- Customizer 大量オプション・独自設定パネル・フォントピッカー等の「エンドユーザーが自由にテーマを設定するUI」は提供しない。
- 理由: ThemeB の Customizer 331設定 の世界は戦略的に不採用（REQ-NF-008 / package.matrix marketPositioningStrategy）。AI 運用型テーマとしての価値は「設定の自由度」ではなく「AI が安全に操作できる一貫性と Automation SEO 連携」にある。

### D2: 制作・運営側が AI 生成物を上書き・微調整する余地は残す

FSE 標準の以下の上書き経路を保持し、テーマ設定で阻害しない。

| 経路 | 内容 |
|---|---|
| Global Styles（サイトエディタ） | 色/タイポグラフィ/余白の上書き |
| Style Variations（`styles/*.json`） | 配色全体の切り替え。業種別派生の起点 |
| 追加CSS | 細部のスタイル上書き |
| 非同期パターンの流し込み後編集 | 同梱パターンは全て非同期（synced 禁止）で流し込み後に編集可能 |

- theme.json の値は「初期値」として提供する。`custom:false` 等のロックフラグを使わない（REQ-NF-026）。
- AI 再生成と競合しない調整経路として、テーマ層での調整を制作側ガイドラインに明示する。

### D3: Style Variations の実装方針

- `styles/light.json`（標準・明示見本）と `styles/dark.json`（ダーク）の2本を同梱する。
- Variation は palette の色値のみ override する設計とし、業種別 variation を `styles/light.json` を複製・palette 変更するだけで作れる骨格にする。
- `styles/` 配下には雛形ファイルを置かない（全 `.json` が variation として読み込まれるため）。

### D4: template parts 追加方針

- `parts/post-header.html` / `parts/post-footer.html` を新規追加し、single.html から参照化する。
- これにより制作側が記事レイアウトの一部を局所的に上書き・カスタマイズできる。

## Consequences

### 肯定的影響

- エンドユーザー設定 UI を持たないことで、テーマの保守コストと設定肥大化を抑制できる。
- FSE 標準の上書き経路を保持することで、受託制作者や運営者が AI 出力を手直しできる実用性を確保できる。
- AI 再生成と競合しないテーマ層調整経路を明示することで、Automation SEO との安全な共存設計が成立する。
- REQ-NF-026（制作側カスタマイズ余地の保持）を設計として固定できる。

### 否定的影響・トレードオフ

- エンドユーザーが期待するような「テーマのカスタマイザー」がないため、非技術者がセルフカスタマイズするには学習コストが生じる。これは意図的な選択（AI 運用型テーマとしての差別化）であり、サポート・ドキュメントで補完する。

### PF-006（Theme Core 責務境界）との整合

本 ADR は表示層の拡張性のみを扱う。CPT・SEO保存・計測保存・API永続化をテーマに持たせないという PF-006 の Theme Core 責務境界（ADR-008）とは矛盾しない。Style Variations / Global Styles / template parts は全て FSE 表示層の機能であり、Core Plugin の責務範囲に干渉しない。

---

## Alternatives Considered

### 案A: Customizer 系の設定UIを提供する

ThemeB 型の多数の設定を提供し、ユーザーが自由にカスタマイズできるようにする。

却下理由: AI 運用型テーマとしての差別化を失う。設定とAI生成コンテンツの競合・保守コストの増大・設定肥大化が発生する。REQ-NF-008 と矛盾する。

### 案B: FSE の上書き経路を全て閉じ、AI のみが制御する

`custom:false` 等のロックを全面適用し、制作側調整を一切禁止する。

却下理由: 受託制作・AI出力の手直し等の正当なニーズを遮断する。商用テーマとして実用性が大幅に低下する。REQ-NF-026 と矛盾する。
