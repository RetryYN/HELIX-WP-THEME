# ADR-022: SEO 出力責務境界（テーマ内蔵 vs 外部 SEO プラグイン委任）

- Status: Proposed

- Phase: L3 / Gate: G3
- 関連 GAP: GAP-RT-016（OGP/meta 責務境界）

## Context

### 実テーマ精読で判明した二極構造

ThemeB 2.16.0 と テーマA の実コード監査（解析レポート `13-SEO設計比較-ThemeA優先分析.md` / `14-ThemeA-seo-hero-deep-extract.md`）で、同カテゴリの有料テーマが SEO 出力の責務を正反対の設計で実装していることが確認された。

| 観点 | ThemeB 2.16.0 | テーマA 1.4.6 |
|------|-------------|-------------|
| title / meta description | 外部 SEO プラグイン（Yoast/AIOSEO 等）前提 / テーマ未出力 | テーマ内蔵（`include/head/tags.php`） |
| canonical | 外部 SEO プラグイン前提 | テーマ内蔵 |
| OGP（og:*） | 外部 SEO プラグイン前提 | テーマ内蔵 |
| Twitter Card（twitter:*） | 外部 SEO プラグイン前提 | テーマ内蔵 |
| JSON-LD @graph | 部分出力（Article / BreadcrumbList）| `include/json-ld.php`（Person / FAQPage / Article 等） |
| robots meta | 外部 SEO プラグイン前提 | テーマ内蔵（noindex 種別制御あり） |

AGENT NEO は FSE テーマとして、この二極のどちらに寄るかを明示しなければならない。ADR-005「テーマA 型統合 UX 採用」は AI が SEO メタを一括操作できる方向性を示したが、外部 SEO プラグインとの共存ルール・二重出力排除・出力種別ごとの優先権についての具体決定を含んでいない。

### 設計上の論点

L3-A3 addendum が `seo-conflict-rules.json`（暫定版）を策定し、`priority_rules.canonical = agent_neo`・`priority_rules.ogp = external_seo_plugin` という非対称配置を採用した。この非対称の根拠を ADR として確定する必要がある（CARRY-A3-001）。

論点は以下の 4 点に収束する:

1. **テーマ内蔵で出すべき SEO 出力はどれか**（テーマA 型内蔵 vs ThemeB 型委任）
2. **外部 SEO プラグイン共存時に canonical だけ AGENT NEO 優先とする根拠**
3. **OGP を外部 SEO プラグイン優先とする根拠と fallback ルール**
4. **二重出力排除の実装方針**（remove_action / remove_filter の使用基準）

---

## Decision

### 決定 1: AGENT NEO のデフォルト SEO 出力範囲（テーマ内蔵）

**外部 SEO プラグイン不在時は、AGENT NEO がすべての SEO 出力を担当する。**

| 出力種別 | 外部 SEO プラグイン不在時 | 外部 SEO プラグイン検出時 | 優先権 |
|---------|--------------------------|---------------------------|--------|
| `<title>` | AGENT NEO 内蔵出力 | 委任（suppress） | 外部優先 |
| `<meta name="description">` | AGENT NEO 内蔵出力 | 委任（suppress） | 外部優先 |
| `<link rel="canonical">` | AGENT NEO 内蔵出力 | **外部を suppress し AGENT NEO が単一出力** | **AGENT NEO 優先** |
| `<meta name="robots">` | AGENT NEO 内蔵出力 | **外部を suppress し AGENT NEO が単一出力** | **AGENT NEO 優先** |
| OGP 一式（`og:url` / `og:title` / `og:description` / `og:image` / `og:type`） | AGENT NEO 内蔵出力 | **委任（OGP 全体 suppress）** | **外部優先（whole-OGP 単位）** |
| `twitter:card` / `twitter:title` / `twitter:image` | AGENT NEO 内蔵出力 | 委任（suppress） | 外部優先 |
| JSON-LD `@graph` | AGENT NEO 内蔵出力 | **AGENT NEO 優先維持** | **AGENT NEO 優先** |

> **設計原則（OGP 所有権）**: OGP は `og:url` を含む一式（whole-OGP）単位で所有権を扱う。外部 SEO プラグインを検出した場合、AGENT NEO は OGP 全体（`og:url` 含む）を suppress し外部に委任する。`og:url` だけ AGENT NEO が出力し続けると外部プラグインの OGP 出力と二重になり TC-053「OGP not duplicated」に違反するため禁止。
>
> canonical と OGP（`og:url`）の扱いが**異なる**理由: `canonical` は `<link rel="canonical">` として head に単一出力されるため外部プラグインがあっても AGENT NEO 側が priority 高い filter で後勝ち上書きできる。一方 OGP はプラグインが `og:url` を含む OGP 一式を `wp_head` hook から出力するため、AGENT NEO が `og:url` のみ出力すると必然的に二重になる。このため OGP は一式単位でどちらかに所有権を割り当てる。

### 決定 2: canonical / robots / JSON-LD を AGENT NEO 優先とする根拠

**これらは AI 操作の安全性・冪等性・監査可能性に直結するため、外部プラグインに委任しない。**

- **canonical**: Automation SEO が指定する canonical URL が正規コンテンツの識別子として機能する。外部 SEO プラグイン（Yoast 等）が canonical を上書きすると、AI が設定した canonical と実出力が乖離し、SEO 操作の冪等性が崩壊する。`SeoMetaRepository` が保存した canonical 値は常に AGENT NEO が出力する。
- **robots**: Automation SEO が `noindex` を指定した記事が検索エンジンにインデックスされるリスクは致命的。外部 SEO プラグインの robots 設定がより「緩い」場合（index 許可）、AI の意図が無効化される。AGENT NEO の robots 設定が常に最終権限を持つ。
- **og:url（外部 SEO プラグイン不在時のみ AGENT NEO 出力）**: 外部プラグインが OGP を出力しない場合のみ、AGENT NEO が canonical と一致した og:url を出力する（決定 3 fallback ルール参照）。外部 SEO プラグイン検出時は og:url を含む OGP 全体を外部に委任し、AGENT NEO 側は一切出力しない（whole-OGP 委任）。og:url だけ AGENT NEO が残すことは TC-053「OGP not duplicated」違反のため禁止。
- **JSON-LD @graph**: AGENT NEO は @graph 統合出力方式（複数 schema node をひとつの `<script type="application/ld+json">` に統合）を採用する。外部 SEO プラグインの JSON-LD との重複ノード（Article / Organization が二重）を防ぐため、AGENT NEO @graph を正本とし、外部プラグインの JSON-LD は各プラグインの公開フィルタで抑制する（決定 4 原則 B 参照）。

### 決定 3: OGP 一式（og:url / og:title / og:description / og:image / og:type）を外部優先とする根拠と fallback

**外部 SEO プラグインが OGP を出力する場合、AGENT NEO は `og:url` を含む OGP 全体（一式）をスキップする（whole-OGP 委任）。**

根拠:
- Yoast / Rank Math / AIOSEO はいずれも `og:url` を含む OGP 一式を `wp_head` hook から inline で出力する。`og:url` だけ AGENT NEO が出力すると og:url が二重になり TC-053「OGP not duplicated」に違反する。
- OGP の品質（カスタムタイトル / カスタム説明文 / アイキャッチ画像選択）は外部 SEO プラグインの管理画面で長年運用されているサイトが多く、AGENT NEO に強制移行するとユーザーの既存設定が失われる。
- OGP は robots / canonical と異なり「AI 操作の意図」が直接反映されるものではなく（記事内容が変わっても OGP は別管理されることが多い）、外部委任のコストが低い。
- Yoast / Rank Math は OGP 管理 UI を独自に持ち、ユーザーが慣れている。

**fallback ルール（外部 SEO プラグイン不在時 または 外部プラグインが OGP を出力しない場合のみ AGENT NEO が出力）**:

```
og:title       = seo_meta.ogp.title ?: seo_meta.title.value ?: post_title
og:description = seo_meta.ogp.description ?: seo_meta.description.value ?: excerpt
og:image       = seo_meta.ogp.imageMediaId → WP media URL ?: seo_profile.organization.logo.url
og:type        = is_front_page() || is_page() ? "website" : "article"
og:url         = AGENT NEO canonical URL
                 （外部 SEO プラグイン検出時は og:url を含む OGP 全体を suppress し出力しない）
```

### 決定 4: 二重出力排除の実装ルール

外部 SEO プラグイン検出後の suppress 実装は以下の原則に従う。

**原則 A: remove_filter による抑制（AGENT NEO 側の出力を止める）**

外部優先の出力種別（title / description / OGP）は、`SeoConflictDetector::scan()` が競合プラグインを検出したタイミングで AGENT NEO 側の出力フィルタを除去する。

```php
// 外部 SEO プラグイン検出時：AGENT NEO 側の title/description/OGP 全体出力を止める
remove_filter('pre_get_document_title', ['AgentNeoSeoHead', 'render_title'], 5);
remove_filter('wp_head', ['AgentNeoSeoHead', 'render_description'], 6);
remove_filter('wp_head', ['AgentNeoSeoHead', 'render_ogp'], 9);          // og:url 含む OGP 一式
remove_filter('wp_head', ['AgentNeoSeoHead', 'render_twitter_card'], 9);
// canonical / robots は除去しない（AGENT NEO 優先維持）
// og:url は render_ogp に統合済みのため上記 suppress で二重出力を防ぐ
```

**原則 A-2: 外部 SEO プラグインの canonical / robots 出力を抑制し AGENT NEO が単一出力する（canonical / robots は AGENT NEO が主権）**

HTML の `<link rel="canonical">` は後から出力されたタグが先のタグを上書きしないため、外部 SEO プラグインと AGENT NEO が両方出力すると二重・矛盾出力になる。TC-052 / TC-054 を満たすために、外部プラグインの canonical / robots 出力を各プラグインの公開フィルタで抑制し、AGENT NEO が単一出力する。

| プラグイン | canonical 抑制フック | robots 抑制フック |
|-----------|--------------------|-----------------| 
| Yoast SEO | `add_filter('wpseo_canonical', '__return_false')` | `add_filter('wpseo_robots', '__return_false')` または `add_filter('wp_robots', ['AgentNeoSeoHead', 'override_robots'], PHP_INT_MAX)` |
| Rank Math | `add_filter('rank_math/frontend/canonical', '__return_false')` | `add_filter('rank_math/frontend/robots', function() { return []; }, PHP_INT_MAX)` |
| AIOSEO | `add_filter('aioseo_canonical_url', '__return_false')` | `add_filter('aioseo_robots_meta', '__return_false')` |
| WordPress Core | `remove_action('wp_head', 'rel_canonical')` — singular コンテンツで WordPress Core が `wp_head` に出力する `rel_canonical` を除去し、AGENT NEO が単一の canonical を出力する（priority=1）。SEO プラグイン不在の経路でも必須 | `add_filter('wp_robots', ['AgentNeoSeoHead', 'override_robots'], PHP_INT_MAX)` |

```php
// WordPress Core の rel_canonical を除去（SEO プラグイン有無に関わらず常時実行）
// singular コンテンツで Core が wp_head に出力する rel_canonical と AGENT NEO の二重出力を防ぐ
remove_action('wp_head', 'rel_canonical');

// 外部 SEO プラグイン検出時：canonical / robots の外部出力を抑制し AGENT NEO が単一出力する
add_action('init', function() {
    // --- Yoast SEO ---
    // canonical: wpseo_canonical フィルタで false を返すと Yoast は canonical を出力しない
    add_filter('wpseo_canonical', '__return_false');
    // robots: wpseo_robots フィルタで false を返すと Yoast は robots meta を出力しない
    add_filter('wpseo_robots', '__return_false');

    // --- Rank Math ---
    // canonical: rank_math/frontend/canonical フィルタで false を返す
    add_filter('rank_math/frontend/canonical', '__return_false');
    // robots: rank_math/frontend/robots フィルタで空配列を返す（Rank Math は配列で robots 指示を保持）
    add_filter('rank_math/frontend/robots', function(): array {
        return [];
    }, PHP_INT_MAX);

    // --- AIOSEO ---
    // canonical: aioseo_canonical_url フィルタで false を返す
    add_filter('aioseo_canonical_url', '__return_false');
    // robots: aioseo_robots_meta フィルタで false を返す
    add_filter('aioseo_robots_meta', '__return_false');
});

// WordPress Core の wp_robots フィルタを最高優先度で上書き（全プラグイン共通）
// AGENT NEO の robots 指示（noindex 等）を最終確定値として強制する
add_filter('wp_robots', ['AgentNeoSeoHead', 'override_robots'], PHP_INT_MAX);
```

**フィルタ不在・バージョン差時の fallback（canonical / robots）**:

各プラグインの canonical / robots 抑制フックが存在しない場合（旧バージョン / 未知プラグイン等）は、`SeoConflictDetector` が二重出力を検出した際に管理画面へ `error` レベルの警告を表示し、AGENT NEO 側の canonical / robots 出力を一時退避（suppress）して外部プラグインに委任する。robots で noindex が抑制されるリスクがあるため、管理画面警告は即時対応を促す `error` レベルとする。

```php
// フィルタ不在の fallback：AGENT NEO canonical/robots を suppress して外部に委任
// ※ noindex 意図が失われる可能性があるため admin_notices に error を表示する
if ($this->conflictDetector->hasUnknownCanonicalPlugin()) {
    remove_filter('wp_head', ['AgentNeoSeoHead', 'render_canonical'], 1);
    $this->conflictDetector->addAdminError(
        'canonical_conflict',
        '未知の SEO プラグインが canonical を出力しています。AGENT NEO の canonical 出力を退避しました。プラグイン設定を確認してください。'
    );
}
if ($this->conflictDetector->hasUnknownRobotsPlugin()) {
    remove_filter('wp_robots', ['AgentNeoSeoHead', 'override_robots'], PHP_INT_MAX);
    $this->conflictDetector->addAdminError(
        'robots_conflict',
        '未知の SEO プラグインが robots meta を出力しています。AGENT NEO の robots 出力を退避しました。noindex 設定が無効になる可能性があります。'
    );
}
```

**原則 B: 外部 SEO プラグイン公開フィルタによる JSON-LD 抑制（JSON-LD は AGENT NEO が主権）**

Yoast / Rank Math / AIOSEO の JSON-LD は `script` ハンドルに enqueue されず `wp_head` hook から **inline** で出力される。`wp_dequeue_script` では排除できないため、各プラグインが提供する公開フィルタ/フックを使用して抑制する。

| プラグイン | 公開フィルタ/フック | 抑制方法 |
|-----------|--------------------|---------| 
| Yoast SEO | `wpseo_json_ld_output` | `add_filter('wpseo_json_ld_output', '__return_false')` |
| Rank Math | `rank_math/json_ld` | `add_filter('rank_math/json_ld', function($data) { return []; }, PHP_INT_MAX)` |
| AIOSEO | `aioseo_schema_output` | `add_filter('aioseo_schema_output', '__return_empty_string')` |
| SLIM SEO | JSON-LD 非出力 | 抑制不要（原則 D 参照） |

```php
// 外部 SEO プラグインの JSON-LD inline 出力を公開フィルタで抑制
add_action('init', function() {
    // Yoast SEO: wpseo_json_ld_output フィルタで完全無効化
    add_filter('wpseo_json_ld_output', '__return_false');

    // Rank Math: rank_math/json_ld フィルタで @graph を空配列化
    add_filter('rank_math/json_ld', function(array $data): array {
        return [];
    }, PHP_INT_MAX);

    // AIOSEO: aioseo_schema_output フィルタで出力を空文字化
    add_filter('aioseo_schema_output', '__return_empty_string');
});
```

**フォールバック方針（フィルタ不在・バージョン差異がある場合）**:

各プラグインの公開フィルタが存在しない場合（旧バージョン等）は、AGENT NEO 側の JSON-LD @graph 出力を suppress し外部プラグインに委任する（「外部 schema に負ける」方向で fail-safe とする）。二重出力のほうが単一欠落より SEO リスクが高いため、AGENT NEO @graph を出さないことを選択する。

```php
// フィルタ不在の fallback：AGENT NEO @graph を suppress して外部に委任
if ($this->conflictDetector->hasUnknownSchemaPlugin()) {
    remove_filter('wp_head', ['AgentNeoSeoHead', 'render_json_ld'], 10);
}
```

**原則 C: 競合警告の管理画面表示**

`SeoConflictDetector` は競合検出時に `admin_notices` に `error` レベルの警告を表示する。
競合 severity `high`（Yoast / Rank Math / AIOSEO）は「競合が検出されました。設定確認を推奨します」のバナーを表示する。

**原則 D: SLIM SEO は warn のみ（suppress なし）**

SLIM SEO は SEO 出力が軽量で JSON-LD を出力しないため、warn レベルの通知のみで suppress しない。

### 決定 5: seo-conflict-rules.json の確定版優先ルール

L3-A3 addendum の暫定版を以下に確定する。

```jsonc
"priority_rules": {
  "meta_title":       { "winner": "external_seo_plugin", "fallback": "agent_neo" },
  "meta_description": { "winner": "external_seo_plugin", "fallback": "agent_neo" },
  "canonical":        { "winner": "agent_neo" },
  "robots":           { "winner": "agent_neo" },
  // OGP は og:url を含む一式（whole-OGP）で外部優先。個別キーに分割しない。
  "ogp_whole":        { "winner": "external_seo_plugin", "fallback": "agent_neo",
                        "note": "og:url/og:title/og:description/og:image/og:type を一括委任" },
  "twitter_card":     { "winner": "external_seo_plugin", "fallback": "agent_neo" },
  "json_ld_graph":    { "winner": "agent_neo",
                        "suppress_method": "public_filter",
                        "note": "Yoast:wpseo_json_ld_output / RankMath:rank_math/json_ld / AIOSEO:aioseo_schema_output" }
}
```

## Consequences

### 良い面

- **AI 操作の安全性確保**: canonical / robots / JSON-LD は AGENT NEO が常に正本。外部 SEO プラグインの canonical / robots 出力はプラグイン別の公開フィルタ（`wpseo_canonical` / `rank_math/frontend/canonical` / `aioseo_canonical_url` 等）で抑制し、AGENT NEO が単一出力することで TC-052 / TC-054 に準拠する。Automation SEO が設定した値が必ずフロントに反映される。og:url は外部プラグイン不在時のみ AGENT NEO が canonical と一致した値を出力し、外部プラグイン共存時は whole-OGP 委任で二重出力を防ぐ。
- **既存ユーザーの移行コスト最小化**: Yoast / Rank Math 利用者はそのまま OGP / title / description 管理を継続できる。
- **二重出力の完全排除**: 各出力種別に対して唯一の権威（AGENT NEO か外部）を設定し、OGP は whole-OGP 単位で所有権を割り当てるため、Google が重複メタを検出するリスクを排除できる。
- **テーマA 型内蔵 UX（ADR-005）との整合**: 外部 SEO プラグイン不在時は テーマA 同等の完全内蔵 UX を提供し、ADR-005 の決定を維持する。
- **プラグイン有無に関わらず canonical は常に AGENT NEO 単一出力**: WordPress Core の `rel_canonical` を `remove_action('wp_head', 'rel_canonical')` で除去するため、SEO プラグインが存在しない経路でも Core canonical と AGENT NEO canonical の二重出力が発生しない。TC-052 / TC-054 はすべての経路で保証される。

### 制約・リスク

- **OGP 全委任による og:url と canonical の乖離リスク**: 外部 SEO プラグインが出力する og:url が AGENT NEO の canonical と一致しない場合、SNS シェア時の URL が canonical と異なる可能性がある。

  → **対策（CARRY-ADR022-001 に引き継ぎ）**: `SeoConflictDetector` が外部プラグインの og:url と AGENT NEO canonical を比較し、不一致の場合は管理画面に warn レベル警告を表示する。og:url を上書きしたい場合は外部プラグインの管理画面で設定変更を促すドキュメントを整備する。AGENT NEO が og:url を直接上書きすることはしない（whole-OGP 委任ルールの例外を作らない）。

- **canonical / robots 抑制フックのバージョン差異リスク**: Yoast / Rank Math / AIOSEO の canonical・robots 抑制フック（`wpseo_canonical` / `rank_math/frontend/canonical` / `aioseo_canonical_url` 等）がプラグイン更新で変更・廃止される可能性がある。

  → **対策**: `SeoConflictDetector::scan()` でフックの存在確認を実施し、不在時はフォールバック処理（AGENT NEO 出力を退避 + `error` レベル管理画面警告）へ遷移する（原則 A-2 fallback 参照）。CI に Yoast / Rank Math / AIOSEO 各バージョンでの canonical・robots 出力テストを組み込む（CARRY-ADR022-003 拡張対象）。WordPress Core の `wp_robots` フィルタ（`PHP_INT_MAX` priority）は WP 5.7 以降で安定しており、最終防衛線として常時有効。

- **外部 SEO プラグインの JSON-LD 排除による機能損失**: Yoast Premium の FAQ Schema / HowTo Schema 等が排除される。

  → **対策**: AGENT NEO が FAQPage / HowTo JSON-LD を @graph で独自実装済み（L3-A3 §4）。Yoast Premium の独自拡張スキーマ（Local Business / WooCommerce 等）は AGENT NEO でカバーしない範囲として明示し、対象ユーザーへの告知ドキュメントを整備する。

- **Yoast バージョン更新によるフィルタ名変更**: `remove_filter` のターゲットが Yoast の内部変更で崩れる可能性がある。

  → **対策**: Yoast の public hook（`wpseo_head`）を使って AGENT NEO 優先項目を後から上書きするアプローチ（priority 高い filter で再出力）を補完的に採用し、フィルタ名変更耐性を持たせる。CI に Yoast 競合テスト（GAP-RT-040 / TC-NF-040）を組み込む。

## Alternatives Considered

### 案 A: 全項目を外部 SEO プラグイン優先にする（ThemeB 型）

ThemeB と同様に外部 SEO プラグインに全委任する案。

**不採用理由**: canonical / robots を外部プラグインに委任すると、Automation SEO が設定した noindex が無効化されるリスクが生まれる。AI 操作の安全性が破綻するため却下。

### 案 B: 全項目を AGENT NEO 優先にする（テーマA 型完全内蔵）

外部 SEO プラグインを一切考慮せず AGENT NEO が全出力を担う案。

**不採用理由**: WordPress サイトの多数は Yoast / Rank Math を導入済みであり、これを強制排除するとユーザーの既存 SEO 設定（カスタム OGP / カスタム description）が消失する。テーマ導入コストが増大し採用率が下がる。

### 案 C: canonical も外部優先とする（本決定との差分）

OGP / title とまとめて external_seo_plugin 優先にする案。

**不採用理由**: Automation SEO が canonical を設定するのは「この URL を正規 URL として処理せよ」という機械的指示であり、人間の SEO 設定（Yoast の canonical 欄）とバッティングした場合に AI の意図が上書きされる。canonical と robots は AI 操作ループの整合性の根幹であるため、AGENT NEO が主権を持つ。
