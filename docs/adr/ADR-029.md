# ADR-029: Stripe 決済は Stripe ホスト型導線に限定する

- Status: Accepted
- Date: 2026-06-26
- Phase: L2 / Gate: G2（追記）
- 関連要件: REQ-F-047 / REQ-NF-027
- 参照 ADR: ADR-008（Theme Core / Companion Plugin 分離） / ADR-024（配布・課金統合） / ADR-028（制作側の編集余地）
- 関連設計: stripe-payment-design-spec.md §3, L1-REQ 追記仕様

---

## Context

AGENT NEO は販売導線の追加に対して、初期段階で「どこまでサイト側実装に持たせるか」を決める必要がある。

仕様の MVP は **Stripe ホスト型（Payment Link / Checkout）導線**を 1 クリック導線として提供すること。これは以下が許容される一方で、決済自体は Stripe が担うため、AGENT NEO が `sk_live` や `sk_test` 等の秘密情報、カード情報、決済 API 連携、Webhook 署名検証を抱える構成を避けられる。

同時に REQ-NF-025 / PF-006 方針により AI 判定ロジックは Theme/Plugin に持たせず、表示ブロックは Companion Plugin 所有という境界が前提。

## Decision

AGENT NEO の stripe決済ブロックは、次を満たす構成で採択する。

1. Stripe ホスト型へのリンク埋め込みに限定
   - ブロックが受け取るのは `buy.stripe.com` または `checkout.stripe.com` の URL のみ。
   - それ以外の URL はレンダリング時に拒否。
2. 鍵・カード情報・決済 API・webhook はテーマ/プラグインに保持しない
   - `sk_live` / `sk_test` / カード情報入力フォーム / API 呼び出し / webhook 署名検証は実装しない。
   - SAQ-A 相当の境界に固定し、運用上の PCI 範囲を最小化。
3. 表示ブロック所有は Companion Plugin
   - ADR-028 と PF-006 を継承し、表示・レンダリングのみを持つ。
4. 動的価格・Checkout Session 生成・webhook は将来スコープ
   - 将来別スコープで検討し、現 MVP では未実装。

## Consequences

### 肯定的影響

- MVP で最短最小リスクにより収益導線を追加できる。
- 決済情報保持を避けることで PCI 負荷を下げ、セキュリティ監査コストを抑える。
- AGENT NEO の責務は「Stripe への確実な導線」を提供することに集中し、PF-006・REQ-NF-025 の境界が明確。

### 注意点・制約

- 価格変更・数量分岐・在庫計算などの動的価格ロジックは本スコープ外。
- サブスク管理や webhook ベースの入金処理は将来版スコープ。
- 表示ブロックは機能上は単純なリンク導線のため、決済分析は Stripe 側管理を前提とする。

## Alternatives Considered

### 案A: WP Simple Pay 利用

既存プラグインをそのまま同梱し、管理画面から各種決済導線を提供する。

却下理由: 同梱・更新・セキュリティ更新の運用負荷が高く、今フェーズの MVP 目標（最小構成・最短実装）と衝突する。

### 案B: WooCommerce + Stripe 汎用統合

WooCommerce のカート/注文フローを採用し、Stripe 決済を Woo 連携で実装する。

却下理由: 料金表現・在庫・送料・税処理等を同時に組み込む必要があり、テーマ側実装規模が増大する。

### 案C: 自前 API 決済

AGENT NEO 側で API キーを保持し、session 作成、webhook 受信、状態管理を実装する。

却下理由: 鍵管理、PCI、認証、監査、障害対応をテーマ側で吸収することになり、REQ-F-047/REQ-NF-027 の境界に反する。

### 本決定（採択）

**MVP = Payment Link / Checkout URL のみを貼るブロック化**。
