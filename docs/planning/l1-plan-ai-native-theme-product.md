# L1 企画書 — HELIX Theme 製品化「AI と話すテーマ」

- 位置づけ: HELIX V モデルの L1 企画（フリー形式）。HELIX-WP-THEME を製品として販売する**別企画**
  （WP 運用ハーネス企画の L1 で非対象とされた「第三者への配布・汎用パッケージ化」を、
  独立企画として起案するもの）。
- 状態: **candidate**（PO 対話 2026-08-22 から起草。PO 確認で confirmed へ）
- 日付: 2026-08-22
- 入場ゲート: **本格着手（配布・販売の実行）は WP 運用ハーネスの成功基準達成
  （売上 ≧ 運用コスト×2・連続 3 か月、目安月商 15 万）を再入場条件とする**。
  それまでは自社デモサイト運用による磨き込みのみ行う（＝現行計画の作業がそのまま商品力形成）。

## コンセプト

**「AI と話すテーマ」** — AI が運用し、AI に読まれ、読者の AI に住み着く WordPress テーマ。

既存テーマ市場（テーマA・テーマB ほか市販テーマ）は全て「人間がエディタで書く」前提で作られている。
本製品は「AI エージェントが運用する」を第一級の前提に置いた初のテーマとして、
市場の空白ポジションを取る。

## 製品の五本柱

1. **トークン効率 — AI 運用費が安い**
   記事の正本をテーマ非依存の中間 JSON（意図語彙）で持ち、AI は JSON だけを出力する。
   生ブロックマークアップを書かせる場合との比は実測 1:3（PoC 証跡 2026-08-22）。
   訴求は裏側の仕組みではなく**数字**（「記事 1 本あたりの AI 費用」をデモサイト実績から提示）。
2. **AI クローラー可視化 — AI に読まれているのが見える**
   GPTBot・ClaudeBot 等の巡回を管理画面ダッシュボードで可視化。llms.txt 管理とセットで
   「LLMO 対応」の実体を提供する。実装は 2 段（WP フック軽量計測+アクセスログ解析。
   キャッシュ済みページが PHP に届かず過小計測になる罠への対策を設計に含む）。
3. **チャット→記事 — 会話がそのまま下書きになる**
   Claude / ChatGPT から MCP 経由で会話内容を中間 JSON に整形→レンダラ→下書き投稿。
   「ブログを書く」を「AI と喋る」に置き換えるメイン UX。既定は下書き止まり
   （公開は人の承認 — 承認ゲート思想を製品にも適用し、薄い記事の量産による SEO 毀損を防ぐ）。
4. **ナレッジ公開 — サイトが AI の知識になる**
   中間 JSON 正本を機械可読で公開（llms.txt に索引・記事ごとの JSON 変種）。
   訪問する AI は HTML 比約 1/3 のトークンで正味コンテンツを読める＝引用されやすい構造。
   スクレイピング容易化のリスクに対し、記事単位の公開 on/off を config で持つ。
5. **チャット内アプリ化 — 読者のチャットに住み着く**
   ChatGPT Apps SDK / MCP コネクタの流れ（2025 秋〜）の Web サイト版。テーマがリモート
   MCP サーバーを内蔵し、読者が自分の ChatGPT / Claude にサイトを接続して
   チャット内でサイト知識に質問できる。「AI コネクタ購読」（RSS→メルマガの次の購読形態）。
   五本柱で唯一の要 PoC（共用サーバーでのリモート MCP トランスポート成立性）。

五本柱は全て「記事正本＝中間 JSON」という単一の設計判断から派生する。

## 技術的裏付け（実証済み資産）

- FSE ブロックテーマ + agent-neo-core（制御プレーン: dry-run→apply→rollback、セクション編集、
  A/B テスト、広告ゾーン、`inc/mcp`・`inc/license` 実装済み）+ agent-neo-embed
  （sandbox iframe + CSP の dual-mode 埋め込み — 診断・ゲーム搭載の受け皿、E2E PoC 済み）。
- デザイン＝JSON トークン→theme.json 投影（helix-design-bridge、before/after 実証 2026-08-22）。
- 中間 JSON ⇄ マークアップの双方向変換（レンダラ/逆変換 v0、実記事 40KB→130 セクション
  無欠損、ラウンドトリップ完全復元 — poc-wp 証跡）。
- 検証環境: poc（HELIX）/ poc-themeB / poc-themeA の 3 面検証台（非捕捉 3 点セット適用済み）。

## 対象・非対象

| | 内容 |
| --- | --- |
| 対象 | HELIX-WP-THEME 本体+同梱プラグイン群の製品化（テーマ+制御プレーン+MCP 接続） |
| 対象 | デモサイトによる実績形成（新規立ち上げ第一号を HELIX Theme デモサイトとする） |
| 非対象 | 運用ハーネス本体の販売（テーマから接続する上位サービスとして分離。松竹梅の「梅=テーマ単体」「松=ハーネス接続」の切り分けは L2 で確定） |
| 非対象 | サイト内 RAG チャットボット（競合過多・従量コスト — 明示 defer） |

## 販売戦略

- **デモンストレーション駆動**: 売る前にデモサイトで実績を作る。「AI が運用しているサイトの
  順位・運用証跡・AI 費用実額」自体をセールス素材とする。伸びなければ売らない（撤退容易）。
- 磨き込み作業（標準ゾーン整備・ブロック語彙拡充・目次・テーブル）は運用ハーネス企画の
  作業と完全に重なるため、製品化の先行投資はほぼゼロ。

## 価値仮説

- AI で運用したい層にとって「運用費の安さ」は購入判断に直結する（数字で示せる唯一のテーマになる）。
- AI 検索時代の不安（読まれているのか）に管理画面で直答する機能は、SEO プラグインが
  検索順位で果たした役割の AI 版になる。
- 読者のチャット内に住み着く購読形態は、確立すれば先行者のネットワーク効果が働く。
