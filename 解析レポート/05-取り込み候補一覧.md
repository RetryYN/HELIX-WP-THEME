# 取り込み候補一覧

## 取り込む

| 候補 | 理由 | 対象パッケージ |
|---|---|---|
| 薄い `functions.php` + Bootstrap | 保守性が高く、AIが読みやすい | Core |
| parts分割 | テンプレートを安全に差し替えられる | Core |
| block.json中心のブロック設計 | JSON操作と相性が良い | Core |
| FAQ/Step/Button/Accordion/Post List | 個人/法人の両方で使う | Core |
| 条件付きCSS/JS読み込み | パフォーマンスに直結 | Core |
| Design Tokens | パッケージ/ブランド切替に必要 | Core |
| CPTによる再利用パーツ | CTA/LP/広告の運用効率が上がる | 個人/法人 |
| 広告/CTA管理 | アフィリエイトと法人LPのCV導線に必要 | 個人/法人 |
| 構造化データ | SEO価値が高い | Core |
| 設定export/import | AI操作、法人展開、バックアップに有効 | 法人 |

## 再設計して取り込む

| 候補 | 再設計理由 | 新設計 |
|---|---|---|
| REST計測 | 公開POSTは濫用されやすい | nonce、rate limit、bot対策、event schema |
| 管理画面設定 | 多機能すぎると使いづらい | package別UIに分割 |
| カスタマイザー | JSON操作と相性が弱い部分がある | design-tokens + theme settingsに寄せる |
| ショートコード | ブロック時代では優先度が下がる | 互換/埋め込み用途に限定 |
| LPテンプレート | 固定テンプレートだけでは法人LPに弱い | JSON section builder化 |
| 広告タグ | 収益化には有効だが法人では不要 | 個人専用featureにする |
| Review | 個人では重要、法人では過剰な場合がある | 法人はCase Study中心にする |
| Widget areas | 多すぎると複雑 | Coreは最小、法人で拡張 |

## 見送るまたは低優先

| 候補 | 理由 |
|---|---|
| Pjax | 複雑化しやすく、初期価値が限定的 |
| 旧Widget互換の大量実装 | 新規テーマではブロック/パターン優先 |
| ふきだし管理 | アフィリエイトでは使えるが中核ではない |
| Font Awesome同梱 | 重量増。必要なら選択式またはSVGアイコン |
| 細かいWP不要機能停止UI | Coreには必要だが詳細設定は後回し |
| ライセンス/アクティベート模倣 | 販売設計が確定してから別途設計 |
