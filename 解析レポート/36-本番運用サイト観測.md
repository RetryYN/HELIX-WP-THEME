## 2. JIN:R 固有観測

### 2.1 REST namespace（JIN:R 専用）

| Namespace | route 数 | 内容 |
|---|---|---|
| `jinr` | **3** | `/post_by_url`, `/external_url` — テーマ自身の REST は極めて薄い |
| `yyirest/v1` | 6 | YYI Rinker (Amazon アフィリリンク管理プラグイン) のテンプレート管理 |

**含意**: JIN:R テーマ自体の REST 公開は最小限。SWELL も含めて、商用テーマは REST API を独自に増やさず WP 標準 + プラグイン側で機能拡張する文化。AGENT NEO は `agent-neo/v1` で 30+ routes 提供する **明確な差別化** が成立する。

### 2.2 OGP / Twitter Card / SEO meta（実出力）

```html
<meta property="og:type" content="website">
<meta property="og:title" content="IT就活大学">
<meta property="og:url" content="https://it-shukatu-college.com">
<meta property="og:description" content="IT業界を目指す就活生を対象に...">
<meta property="og:image" content="https://it-shukatu-college.com/wp-content/uploads/2024/09/cropped-IT就活大学：ロゴ.png">
<meta name="description" content="IT業界を目指す就活生を対象に...">
<meta property="og:site_name" content="IT就活大学">
<meta name="twitter:card" content="summary_large_image">
<meta name="twitter:site" content="@IT_Shukatu_Col">
<meta name='robots' content='max-image-preview:large'/>
```

**JIN:R テーマの SEO 統合機能は使用済み**（OGP/Twitter Card は出力されている）。

### 2.3 JSON-LD: **本番サイトでは出力なし**

`<script type="application/ld+json">` を grep しても 0 件。

**含意**:
- ローカル fresh install で SWELL アクティブ時には @graph JSON-LD が出ていた
- JIN:R テーマは JSON-LD 出力機能を持つ（解析レポート 31）が、設定で無効化されている可能性
- もしくは aseo/v1 や Site Kit 等のプラグインで上書き / 抑制されている

AGENT NEO は **JSON-LD 出力をデフォルト ON + 設定で OFF 可能**（ただし他プラグイン重複検知時は自動 OFF）の設計が安全。

### 2.4 命名規約 (BEM ベース)

実 HTML から抽出された CSS class:

| プレフィックス | 用途 | 例 |
|---|---|---|
| `b--jinr-block` | block 単位 | `b--jinr-block b--jinr-button` |
| `c--jinr-slider` | component | `c--jinr-slider` |
| `o--jinr-mainvisual` | object | `o--jinr-mainvisual o--jinr-slider` |
| `d--slider-design1` | design variant | `d--slider-animation-high` |
| `a--slider-button` | animation | `a--slider-button ef` |
| `js--scr-animation` | JS hook | `js--scr-animation` |

**AGENT NEO への含意**: 命名は AGENT NEO 独自規約で。BEM 風 + AI 機械可読のため `data-agent-section-id` `data-agent-block-type` 等の data 属性を**併用**するのが正解。

### 2.5 ホームページ実装

```html
<body class="home wp-singular page-template page-template-template-full-width
             page-template-template-full-width-php page page-id-20 wp-theme-jinr">
```

**重要発見**: トップページが **固定ページ + `template-full-width.php`** で実装されている（home.php ではない）。

**含意**: JIN:R 運用者は **動的 home.php ではなく固定ページでトップを作っている**。これは LP/HP 設計の現実的な使われ方として AGENT NEO の HP/LP/BLP ブループリント設計に反映すべき:
- HP も Blueprint（固定ページの構造化形式）として扱う
- 動的 home.php は デフォルトテンプレートとして残しつつ、推奨は固定ページ + Blueprint

### 2.6 セキュリティ・パフォーマンスの問題

| 項目 | 観測値 | 問題 |
|---|---|---|
| `Set-Cookie: PHPSESSID=...` | 出力されている | **理由なくセッション開始**。CDN/cache 互換性破壊 |
| `Cache-Control` | `no-store, no-cache, must-revalidate` + `s-maxage=10` 同居 | **矛盾するヘッダ**（ブラウザ無キャッシュ + CDN 10秒キャッシュ）|
| `Pragma: no-cache` | 出力 | 古い HTTP/1.0 互換ヘッダで現代では不要 |
| `X-Mod-Pagespeed: Powered By XPageSpeed` | Apache PageSpeed Module 動作中 | キャッシュと干渉する余地、設定が複雑化 |

**AGENT NEO への含意（致命的）**:
- 「商用テーマでも本番でこの状態」 → **商品競争力の決定的差別化点**
- AGENT NEO は **theme でセッション開始しない**（PHPSESSID 出力ゼロを保証）
- AGENT NEO は **Cache-Control を矛盾なく出力**（origin: 適切な max-age, CDN: s-maxage、両者整合）
- AGENT NEO は **PageSpeed Module 不要で同等の性能**（used block CSS + lazy + preload で）
- これらはマーケ訴求の根拠材料: 「JIN:R を使うとこういう状態になりがち。AGENT NEO は最初から正しい」

### 2.7 Preload リソース（HTTP Link ヘッダ）

```
Link: </wp-includes/js/jquery/jquery.min.js?ver=3.7.1>; rel=preload; as=script
Link: </wp-content/plugins/yyi-rinker/js/event-tracking.js?v=1.12.0>; rel=preload; as=script
Link: </wp-content/themes/jinr/scss/others/kaereba.css?ver=6.9.4>; rel=preload; as=style
Link: </wp-includes/js/dist/hooks.min.js?...>; rel=preload; as=script
Link: </wp-includes/js/dist/i18n.min.js?...>; rel=preload; as=script
Link: </wp-content/plugins/contact-form-7/includes/swv/js/index.js?...>; rel=preload; as=script
Link: </wp-content/themes/jinr/lib/js/youtube.js?...>; rel=preload; as=script
```

**観測事実:**
- JIN:R は **jQuery を本番 preload している**（フロントエンドが jQuery 依存）
- YYI Rinker（Amazon アフィリ）の **クリック計測 JS が preload**（収益化モデルが本番で動作）
- WP コア i18n / hooks も preload
- contact-form-7 が preload
- youtube.js が preload（記事内 YT 埋込みあり）

**AGENT NEO への含意:**
- jQuery 非依存をデフォルトで（解析レポート 18 で既に方針化済）
- AGENT NEO 個人版は **クリック計測 JS を YYI Rinker と同等以上の性能で**内蔵すべき（外部プラグイン依存にしない）
- AdSense / メルカリ系の計測も含めて `agent-neo-tracking.js` で一括管理

## 3. SWELL 固有観測

### 3.1 OGP / Twitter Card / SEO meta（実出力）

```html
<meta name='robots' content='max-image-preview:large' />
<meta name="description" content="副業・フリーランスで稼ぐための実践メディア...">
<meta property="og:locale" content="ja_JP">
<meta property="og:type" content="website">
<meta property="og:title" content="...">
<meta property="og:description" content="...">
<meta property="og:url" content="https://solobiz-lab.com/">
<meta property="og:site_name" content="...">
<meta name="twitter:card" content="summary">
```

JIN:R との差:
- `og:locale` が SWELL のみ存在
- `og:image` は SWELL では検出されず（あるかもしれないが top では出ていない）
- `twitter:card` が `summary` (vs JIN:R の `summary_large_image`) — トップページは小さいカード扱い

### 3.2 JSON-LD: **@graph 形式で出力されている**

```json
{"@context": "https://schema.org","@graph": [
  {"@type":"Organization","@id":"https://solobiz-lab.com/#organization","name":"...","url":"..."},
  {"@type":"WebSite","@id":"https://solobiz-lab.com/#website","url":"...","name":"...",
   "description":"...",
   "potentialAction":{"@type":"SearchAction","target":"...?s={s}","query-input":"name=s required"}}
]}
```

ローカル fresh install と完全に同じ構造（@graph 配列、Organization + WebSite）。

**含意**: SWELL は本番でも JSON-LD を継続出力。AGENT NEO もこの構造を踏襲する。

### 3.3 命名規約

```html
<body class="home blog wp-theme-swell -body-solid -index-off -sidebar-on -frame-off top">
```

```html
class="wp-block-search__button-outside wp-block-search__text-button wp-block-search"
class="wp-block-search__label"
class="wp-block-search__inside-wrapper"
class="wp-block-search__input"
class="wp-block-search__button wp-element-button"
class="wp-block-group"
class="wp-block-heading"
class="wp-block-latest-posts__list wp-block-latest-posts"
```

**重要発見**: SWELL は **block レベルで Core blocks (`wp-block-*`) を中心に使用**。SWELL 独自 class（`swl-*`, `loos-*`）は **body 修飾子のみ**（`-body-solid` `-index-off` `-sidebar-on` 等）。

これは **「テーマは Core blocks を素直に使い、設定で見た目を変える」** 思想。AGENT NEO もこの思想を踏襲しつつ、独自ブロックは `agent-neo/*` 名前空間で追加。

### 3.4 セキュリティ・パフォーマンス（クリーン実装）

| 項目 | 観測値 | 評価 |
|---|---|---|
| `Set-Cookie` | **出力されない** ✓ | クリーン |
| `Cache-Control` | 単一値（矛盾なし） | クリーン |
| `X-Mod-Pagespeed` | なし | テーマ自前で性能を担保 |

JIN:R との対比:
- SWELL は本番でも **Cookie ゼロ** （セッション開始しない）
- JIN:R は本番で **PHPSESSID を毎回 Set-Cookie**（理由なく）

**AGENT NEO の方針確定**: SWELL 流のクリーン実装を踏襲。

### 3.5 トップページ実装

```html
class="home blog ..."
```

→ SWELL 運用者は **動的 blog 表示** を採用（最新記事一覧）。JIN:R 運用者の固定ページ Blueprint と対照的。

**含意**: HP/LP/BLP Blueprint は **3 種類すべてに対応**（動的 blog / 固定ページ Blueprint / カスタム index）。ユーザーが選択可能に。

### AGENT NEO への含意（参考レベル）

- aseo/v1 が **クライアント側 (AI コントロール)** の API

- aseo の `/posts/<id>/blocks` `/ai/write` `/ai/block-edit` 等が AGENT NEO テーマの何を呼ぶかが連携設計の核心
- AGENT NEO は agent-neo/v1 で**ブロック単位の操作・dryRun・schema validation**を提供すれば、aseo 側がそれを呼ぶ形になる
- ただし aseo は WIP のため **agent-neo/v1 を完全に整列させる必要はない**。基本構造は WP REST 慣習に従い、aseo が安定したら adapter で接続

## 5. 命名規約・実装思想の総合比較

| 項目 | JIN:R | SWELL | AGENT NEO 採用方針 |
|---|---|---|---|
| body class スタイル | `wp-theme-jinr` のみ | `wp-theme-swell -body-solid -index-off ...` | SWELL 流（修飾子で状態表現）|
| ブロック class | `b--jinr-* o--jinr-*` 独自命名 | `wp-block-*` Core 中心 | **SWELL 流 + agent-neo/* 独自ブロック** |
| データ属性 | 観測されず | 観測されず | **AGENT NEO 独自に `data-agent-*` 必須化**（AI 機械可読の差別化）|
| HOME 実装 | 固定ページ template-full-width | 動的 blog | 3 種対応（blueprint で選択）|

| theme 自身の REST 公開 | 3 routes のみ | （未確認 / 同程度推定）| **agent-neo/v1 で 30+ routes** ← 明確な差別化 |

## 6. AGENT NEO L2 設計への引き継ぎ事項

### マーケティング訴求材料（実証済み）

1. 「JIN:R 1.0.5 は PHP 8.2 で 100+ Warning、1.4.6 でも 2 件残存。商用テーマでもメンテ品質に課題」
2. 「JIN:R は本番で **PHPSESSID Cookie を出力**（CDN/cache 破壊の原因）」
3. 「JIN:R 本番の Cache-Control は **`no-store` と `s-maxage=10` が同居** する矛盾状態」
4. 「JIN:R は jQuery 依存・PageSpeed Module 補強・複数プラグイン連携で性能担保（モダン WP 環境では負債）」
5. 「SWELL はクリーンだが AI 操作 API を提供しない。AGENT NEO は SWELL のクリーンさ × AI 第一級操作 API」

### 設計確定事項（NF 強化）

| REQ-NF | 内容 |
|---|---|
| `theme_no_session_start` | テーマで `session_start()` を **絶対に呼ばない**。CI で grep 検査必須 |
| `cache_control_consistency` | Cache-Control / Pragma / Expires が矛盾しないことを検証 |
| `no_jquery_default` | jQuery を frontend で **デフォルト dequeue**。必要時のみ block.json で宣言依存 |
| `tracking_in_theme` | 個人版アフィリ計測 JS は **テーマ内蔵**（外部プラグイン依存しない）|
| `core_blocks_first` | 独自ブロックは `agent-neo/*` で限定。Core blocks 改造は最小限 |
| `data_agent_attributes` | DOM に `data-agent-section-id` `data-agent-block-type` 等を必須化（AI 機械可読の差別化）|
| `home_blueprint_three_modes` | HP は dynamic_blog / static_page / custom_index の 3 モード対応 |

### 設計確定事項（aseo/v1 連携指針 - WIP のため柔軟）

- AGENT NEO の `agent-neo/v1` は **WP REST 慣習に従う**（aseo に整列させない）
- aseo の `/ai/write` `/ai/block-edit` は AGENT NEO 側 `/agent-neo/v1/posts/<id>/blocks` を呼ぶ構造
- aseo が安定後、adapter 設計でブリッジ
- aseo の WIP 性質上、agent-neo/v1 は **より厳格な dryRun + schema 検証** を提供して aseo 側の不安定さを吸収する責務がある
