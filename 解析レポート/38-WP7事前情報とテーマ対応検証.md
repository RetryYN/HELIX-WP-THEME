# 38-WP7事前情報とテーマ対応検証

作成日: 2026-04-30

## 結論

WordPress 7.0 は公式情報上、2026-05-20リリース予定に更新されている。元の2026-04-09予定は延期済みで、延期理由は主にリアルタイム共同編集のアーキテクチャ安定化である。

SWELL 2.16.0 / JIN:R 1.4.6 とも、現時点のテーマヘッダでは WordPress 7.0 の PHP 最小要件 7.4 に明示追随していない。SWELL は `Requires PHP: 7.3.0`、JIN:R は `Requires PHP: 7.0` のため、WP 7.0前提の販売テーマとしてはヘッダ・検証表・サポート宣言を更新する必要がある。

## WP 7.0でテーマ開発に効く変更点

| 領域 | 内容 | テーマ影響 |
|---|---|---|
| リアルタイム共同編集 | ブロックエディタ上の共同編集。HTTP polling、presence、postmeta/transient周辺が議論対象 | メタボックス、独自ブロック、session、AJAX、postmeta更新処理は衝突・同期・キャッシュ影響を検証する |
| Custom CSS for Individual Block Instances | 個別ブロック単位のCSS指定。`customCSS` block supportが追加 | `block.json` の `supports` を点検し、ラップ要素が不安定なブロックは opt-out を検討 |
| Dimensions support | `dimensions.width` / `dimensions.height`、theme.jsonのdimension size presets | 余白・横幅・高さプリセットをtheme.json化するとAI/ユーザー操作性が上がる |
| Customizable Navigation Overlays | navigation-overlay areaのtemplate partをtheme.jsonで登録 | FSE/ブロックテーマ寄りのモバイルナビ設計を取り込める |
| Pseudo-class support in theme.json | `:hover`、`:focus`、`:focus-visible`、`:active` をtheme.jsonで表現 | ボタン/CTA/カードの状態設計をCSS直書きから構造化できる |
| DataViews / DataForm | 管理UIのデータ表示・フォームAPIが拡張 | AGENT NEOの管理画面/Automation SEO連携UIをWP標準寄りに寄せられる |
| Abilities API | `wp_register_ability()` / client-side abilitiesで操作能力を宣言可能 | AIエージェント操作契約の中核候補。readonly/destructive/idempotent注釈が有効 |

## テーマ別のWP 7.0リスク

### SWELL

良い点:

- `block.json` が多く、WP 7.0の `customCSS` / dimensions / block support 系の検証対象を機械的に洗い出しやすい。
- `WP_HTML_Tag_Processor` polyfillを持っており、HTML改変を正規API寄りに扱う設計思想がある。
- REST/CPT/`show_in_rest` があり、AIエージェントやAutomation SEOとの契約化に寄せやすい。

懸念:

- ルート `theme.json` が見当たらないため、WP 7.0のtheme.json拡張を最大限には使えていない可能性が高い。
- `Requires PHP: 7.3.0` はWP 7.0のPHP 7.4要件とズレる。
- 個別ブロックCSSが全ブロックに自動有効化される前提で、ラップ要素・server renderブロック・独自CSS衝突を検証する必要がある。

### JIN:R

良い点:

- 公式更新履歴上、WP6.5/6.6/6.7/6.8への追随実績がある。
- SEO head/JSON-LD/デザインプリセット/比較表/タブ/LP系ブロックなど、マーケティング用途の設計思想は強い。
- `show_in_rest` 登録が多く、投稿メタのREST公開に寄せる余地はある。

懸念:

- `block.json` がなく、ブロック登録がPHP直書き中心。WP 7.0のblock support差分を静的解析しにくい。
- `wp_ajax_nopriv_*`、session、paidpost、メール/ログイン系処理が多く、共同編集・キャッシュ・低価格ホスティングでの副作用検証が必要。
- PHP 8.3でCustomizer周辺warningが再現済み。WP 7.0対応以前にPHP 8.3/8.4/8.5互換の品質ゲートが必要。
- 公式Ver1.46はWP6.8対応までで、WP7.0対応宣言は未確認。

## 検証上の漏れ

現時点の検証は WordPress 6.9.4 上での実測であり、WP 7.0 RC/Final上の互換性検証は未実施。したがって以下は漏れとして残る。

| 漏れ | 優先度 | 理由 |
|---|---|---|
| WP 7.0 RC3/RC4/FinalでのDocker別環境検証 | 高 | 7.0は延期され、RC3が実質Beta扱い。6.9.4の結果だけでは互換保証にならない |
| PHP 7.4 / 8.1 / 8.2 / 8.3 / 8.4 / 8.5マトリクス | 高 | WP 7.0最小要件と今後のホスティング差分を吸収する必要がある |
| リアルタイム共同編集ON/OFF検証 | 高 | JIN:Rのsession/AJAX/postmeta、SWELLのserver render block/metaが影響を受ける可能性 |
| ブロック個別Custom CSS検証 | 高 | WP 7.0で自動有効化されるため、独自ブロックのouter wrapperが壊れる可能性 |
| theme.json未整備による機能取りこぼし検証 | 中 | navigation-overlay、pseudo state、dimension presetを活用できない |
| Abilities API検証 | 高 | AGENT NEO / Automation SEOのAI操作契約に直結する |
| ホスティング互換性 | 中 | WP公式でもhost testingを重視。共有サーバー、LiteSpeed、Redis、object cacheを別途見る |
| 本番相当プラグイン組み合わせ | 高 | 実運用ではSmart Slider/Rinker/EWWW/RTOC/Pochipp/Useful Blocks等で差が出る |
| 更新サーバー・ライセンス・自動更新のWP7互換 | 中 | SWELL/JIN:Rとも独自更新機構があり、メジャー更新時の失敗が運用事故になり得る |

## AGENT NEOで先回りすべき設計

1. `Requires PHP: 7.4` ではなく、販売時点では `Requires PHP: 8.1+` 推奨、テスト対象は `7.4/8.1/8.2/8.3/8.4/8.5` にする。
2. 全ブロックを `block.json` 管理に寄せ、`supports.customCSS`、`dimensions`、`spacing`、`typography`、`anchor`、`className` の方針を明記する。
3. ルート `theme.json` を正本にし、色、余白、フォント、CTA状態、疑似クラス、dimension preset、navigation overlayを構造化する。
4. AI操作はRESTだけでなく、WP 7.0のAbilities APIを採用候補にする。各操作に `readonly`、`destructive`、`idempotent`、`requires_capability` を持たせる。
5. 共同編集時に壊れる可能性がある処理を避ける。session依存、保存時副作用、postmeta直接更新、AJAX書き込みはテーマ本体ではなくAutomation SEO側の明示APIに寄せる。
6. WP7系の互換性CIを `wp:6.9.latest`、`wp:7.0-rc`、`wp:7.0-final`、`php:7.4/8.1/8.2/8.3/8.4/8.5` で回す。
