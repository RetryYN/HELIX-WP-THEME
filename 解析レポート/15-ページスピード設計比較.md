# ページスピード設計比較

## 結論

AGENT NEO のページスピード設計は、テーマA より ThemeB を優先参考にする。SEO は テーマA の統合UXが強いが、速度設計は ThemeB のほうが実装粒度が細かく、条件付きアセット、CSS分割、遅延読み込み、不要機能の抑制までテーマ全体の設計に組み込まれている。

したがって採用方針は次の通り。

| 領域 | 優先参考 | 理由 |
|---|---|---|
| SEO統合UX | テーマA | title、description、canonical、noindex、OGP、JSON-LDをテーマ側に統合している |
| ページスピード | ThemeB | CSS/JSの条件付き読み込み、遅延読み込み、分割CSS、不要機能除去が体系化されている |
| AGENT NEO方針 | 独自実装 | コード/CSS/画像は流用せず、設計抽象だけを採用する |

Core Web Vitals は 2026-04-29 時点で LCP、INP、CLS を基準にする。Google/web.dev の現行基準では、LCP は 2.5 秒以内、INP は 200 ms 以下、CLS は 0.1 以下が良好範囲。

## ThemeBの速度設計

### 強い点

| 観点 | 実コード根拠 | 評価 |
|---|---|---|
| CSS非同期/分割 | `lib/load/front.php`, `lib/load/separate.php`, `lib/menu/settings/speed.php` | `load_style_async`、`separate_style` によりCSS読み込み戦略を切り替えられる |
| ブロックCSS最適化 | `classes/Pre_Parse_Blocks.php`, `classes/Utility/Status.php` | 使用ブロックに応じたCSS読み込みを意識している |
| 遅延読み込み | `lib/content_filter.php`, `classes/Utility/Get.php`, `classes/Utility/Others.php` | native lazy、lazysizes、swiper向けlazyを使い分ける設計 |
| 不要機能削除 | `lib/hooks/remove.php`, `classes/Data/Default_Settings.php` | emoji削除、WordPress標準挙動の調整などが設定化されている |
| 条件付きJS | `lib/output.php`, `lib/load/front.php` | accordion、luminous、CTR、rellax、swiper等を使用時のみ読み込む方向 |
| 画像属性 | `classes/Utility/Get.php` | srcset、sizes、loading、decoding を生成側で制御する |

### 取り込むべき設計抽象

- `performance-profile.json` で速度設定を宣言的に管理する。
- `asset-policy.schema.json` でブロック/機能ごとのCSS/JS読み込み条件を定義する。
- `critical-css.schema.json` で初期表示に必要なCSSだけをインラインまたは先行読み込みする。
- `media-policy.schema.json` でLCP画像、通常画像、iframe、スライダー画像の読み込み方を分ける。
- `third-party-tags.schema.json` で広告、計測、CRM、外部フォームを遅延/同意/ページ条件付きにする。
- `web-vitals-budget.json` でLCP/INP/CLSとバンドル上限を機械判定できるようにする。

### 注意点

ThemeBの実装思想は強いが、設定が多いほどユーザーが誤設定する余地も増える。AGENT NEOでは人間向け設定項目を増やすより、AI/JSONで安全に制御できるプリセット化を優先する。

## テーマAの速度設計

### 強い点

| 観点 | 実コード根拠 | 評価 |
|---|---|---|
| jQueryフッター移動 | `functions.php` | jQueryを再登録し、フッター読み込みに寄せている |
| 画像preload | `include/head/preload.php` | アイコンフォント、ヘッダーロゴ、サムネイルをpreloadする |
| 画像最適化 | `include/custom-functions.php` | 投稿リスト画像に `loading='lazy'`、`width`、`height`、`srcset`、`sizes` を付与 |
| emoji削除 | `include/custom-functions.php` | `themeA_speed_emoji` でemoji関連を削除する |
| Google Fonts | `include/font-selection.php` | preconnectを出力する |
| YouTube/Swiper | `include/custom-functions.php` | YouTubeサムネイル保存、Swiper lazy設定がある |

### 弱い点

| 観点 | 実コード根拠 | リスク |
|---|---|---|
| グローバルCSSが大きい | `style.css` 約496KB、`block.css` 約383KB、`style-footer.css` 約172KB | 未使用CSSが増えやすく、LCP/TBTに不利 |
| jQuery依存 | `functions.php` の front scripts | INP/TBT面で現代的な最小JS設計より不利 |
| YouTube JS常時読み込み | `functions.php` の `themeA-youtube-script` | YouTube非使用ページでも余分なJSになり得る |
| 外部CDNのSwiper直接挿入 | `include/custom-functions.php` の `https://unpkg.com/swiper/swiper-bundle.min.js` | CSP、可用性、キャッシュ制御、第三者依存の観点で法人向けに弱い |
| FSE非対応 | 親テーマはclassic PHP template | block.json/theme.json単位のアセット契約にしづらい |

テーマAは「SEO統合」「コンテンツ編集UX」「デザインプリセット」が主戦場で、速度は基礎対策はあるが、AGENT NEOの速度基盤としてそのまま優先する設計ではない。

## AGENT NEO速度設計

### P0で入れるべきCore機能

| 機能 | 内容 | 対象 |
|---|---|---|
| Block Asset Registry | block.json と連動し、使用ブロックだけCSS/JSを読み込む | Core |
| Critical CSS Builder | hero/header/first viewport の最小CSSを生成する | Core/法人 |
| No Global Mega CSS | 全ブロック一括CSSを避け、route/block/feature単位へ分割する | Core |
| JS Islands | CTA、A/B、accordion、slider等を必要箇所だけ起動する | Core |
| Media Policy | LCP画像は eager/preload、その他は lazy/async decoding | Core |
| Font Policy | フォントは family/weight 上限とpreconnect/preloadを契約化 | Core |
| Third Party Governance | GA4/GTM/広告/CRM/外部フォームを同意・条件・遅延で制御 | Core/法人 |
| Web Vitals RUM | LCP/INP/CLSを実ユーザー計測し、Automation SEOへ改善材料として渡す | Core |
| No Front jQuery Default | フロントはjQuery非依存を原則にし、互換時だけ条件付き読み込み | Core |
| Emoji/Embed Cleanup | 不要なemoji、embed、dashicons等を設定ではなくプロファイルで制御 | Core |

### 個人版の速度要件

- アフィリエイトリンク、広告タグ、ランキング、比較表は表示ブロック単位でCSS/JSを読み込む。
- 外部ASPリンクのpreconnectは該当ページでのみ許可する。
- 広告タグはLCP領域をブロックしない。初期表示外広告は遅延読み込みにする。
- 商品カード/ランキング/比較表はCLSを起こさないよう、画像比率とCTA高さを固定する。

### 法人版の速度要件

- LP Hero はLCP予算を持つ。Hero画像はサイズ、format、preload、fetchpriorityを契約化する。
- CTA/A-B/計測スクリプトは初期描画をブロックしない。
- HubSpot、Salesforce、外部フォーム、MAタグはページ条件と同意状態で読み込む。
- LPセクションごとに `section_id` と performance marker を紐づけ、どのセクションがLCP/CLS/INPに悪影響を出しているか追跡できるようにする。

## 速度予算

| 項目 | 目標 | 補足 |
|---|---:|---|
| LCP | `2.5s` 以下 | 75パーセンタイル、mobile/desktop別 |
| INP | `200ms` 以下 | field計測を優先、labではTBTで代替監視 |
| CLS | `0.1` 以下 | 画像/広告/CTA/フォントで崩さない |
| 初期CSS | `20KB gzip` 以下 | critical CSS対象 |
| route CSS | `50KB gzip` 以下 | ページ種別ごと |
| 初期JS | `70KB gzip` 以下 | tracking/CTA/A-Bを除いた初期必須分 |
| render blocking third-party | `0` | 第三者タグは遅延/同意/条件付き |
| フォント | 2 family / 3 weights以内 | LPごとの上限。可変フォント優先 |

## JSON操作契約案

```json
{
  "performanceProfile": {
    "mode": "balanced",
    "coreWebVitalsBudget": {
      "lcpMs": 2500,
      "inpMs": 200,
      "cls": 0.1
    },
    "assetPolicy": {
      "blockCss": "used_blocks_only",
      "blockJs": "interaction_islands",
      "frontJquery": "disabled_by_default",
      "thirdParty": "defer_until_idle_or_consent"
    },
    "mediaPolicy": {
      "lcpImage": "preload_eager_fetchpriority_high",
      "belowFoldImages": "lazy_async_decoding",
      "iframes": "lazy_with_placeholder"
    }
  }
}
```

### Agent操作

| Action | 目的 |
|---|---|
| `performance.auditBudget` | 現在のページ/テンプレートが速度予算を超えていないか確認する |
| `performance.updateAssetPolicy` | ブロック、計測、外部タグの読み込み条件を変更する |
| `performance.setMediaPolicy` | LCP画像、lazy対象、iframe方針を変更する |
| `performance.recordWebVitals` | LCP/INP/CLS実測値を記録する |
| `performance.suggestFixes` | 未使用CSS、重いJS、CLS原因、第三者タグを改善案に変換する |

## 採用/不採用分類

| 参照元 | 採用 | 改良して採用 | 不採用 |
|---|---|---|---|
| ThemeB | 条件付きアセット、CSS分割、遅延読み込み、不要機能削除 | 設定UI中心ではなくJSON契約中心に再設計 | コード/CSS/画像の流用 |
| テーマA | preload、画像属性、YouTubeサムネイル思想 | SEO統合UXと速度ポリシーを分離して再設計 | 巨大グローバルCSS、フロントjQuery常時依存、外部CDN直書き |
