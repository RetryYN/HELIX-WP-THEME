# ドキュメントとテーマ群の抜け漏れレビュー

## 結論

L0/L1/L2と解析レポート01-28は、企画・市場・SEO・速度・LP/HP・制約・運用・AI運用・Automation SEO連携まで広くカバーできている。現時点で「企画の大筋が抜けている」状態ではない。

ただし、実装へ進む前の設計書としては、以下の抜け漏れが残る。特にL3詳細設計とL5 Visual Designはテンプレート残りが多く、L4実装へ入る前に凍結できる状態ではない。

## Findings

| Severity | 項目 | 内容 | 対応 |
|---|---|---|---|

## 追加すべき設計観点

| 観点 | 理由 | 反映先 |
|---|---|---|
| L3 API/Schema Freeze | AI操作/API/Cron/Automation SEO連携は仕様固定なしに実装すると破壊的変更が起きる | `docs/design/L3-detailed-design.md` |
| Option/Meta/CPT保存設計 | WordPressではoptions/post_meta/transient/CPTの肥大化と移行性が運用リスクになる | L3 D-DB/D-MIG |
| Uninstall/Cleanup詳細 | 商用プラグインは削除時のoptions/meta/log/cron cleanupが必須 | L3/L6 |
| WP.org配布向けreadme/asset制約 | 移行プラグインや無料Bridge Pluginを出すなら審査・外部通信・トラッキング同意の細部が必要 | L3/L6 |
| WP 7.0/Gutenberg互換テスト | FSE/block API/共同編集/metadata互換の破壊的変更を吸収する必要がある | L6 QA matrix |
| Automation SEO Connector v2契約 | 既存 `seo-tool/v1` とAGENT NEO `agent-neo/v1` の責務境界を固定する必要がある | L3 API |
| 実装スキャフォールド | ドキュメントから実装へ移るにはtheme/core-plugin/migration-pluginの実ファイルが必要 | L4.1 |

## 推奨する次アクション

1. L3詳細設計をテンプレートから実仕様へ更新する。優先はA-001〜A-024、schema一覧、error catalog、permission/capability、WP-CLI/MCP contract。
2. L5 Visual Designを実トークンと画面別wireへ更新する。個人アフィリエイト、法人LP、管理画面、Automation SEO Fit、Theme Bridge Profileを優先する。
3. L1トレーサビリティでREQ-NF-001〜007を補完する。
4. `themes/agent-neo-theme`、`plugins/agent-neo-core`、`plugins/agent-neo-migration` の雛形を作り、L3契約に沿って実装スプリントへ移る。
5. AFFINGER/Cocoon/Lightningをコードレベルで見る必要があるか判断する。市場戦略だけなら現状で足りるが、互換移行adapterを作るなら不足。
