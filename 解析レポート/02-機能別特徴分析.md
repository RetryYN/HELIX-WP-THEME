# 機能別特徴分析

## 1. テンプレート機能

| 機能 | 参照テーマの特徴 | 設計に生かせるもの | パッケージ |
|---|---|---|---|
| 投稿詳細 | `single.php` と `parts/single/*` で記事上部、下部、著者、関連記事、シェアを分割 | 収益記事テンプレート、法人ニューステンプレートを分ける | 共通 |
| LP | `single-lp.php` とLP用メタ設定 | 個人は簡易LP、法人はセクションビルダー化 | 個人/法人 |
| アーカイブ | `archive.php`、`archive-term.php`、`home.php` | 投稿一覧のカード/リスト切替、カテゴリ説明表示 | 共通 |
| トップ | `parts/top/*` にMV、スライダー、pickup banner | 法人LPのHero、個人の収益記事導線に転用 | 個人/法人 |
| ヘッダー | PC/SP、固定ヘッダー、情報バー、検索導線 | 法人は製品導線、個人は収益記事導線を優先 | 共通 |
| フッター | 複数ウィジェット、固定ボタン、モーダル | 法人は問い合わせ/資料DL、個人はプロフィール/SNS | 共通 |

### 新テーマでの判断

| 判断 | 内容 |
|---|---|
| 取り込む | parts分割、LP専用テンプレート、トップ導線の考え方 |
| 再設計 | LPはテンプレート固定ではなくJSONセクション構成にする |
| 見送る | 過剰な細分化や旧Widget依存 |

## 2. Gutenbergブロック

参照テーマは `src/gutenberg/blocks/*/block.json` を中心に、編集体験を強化している。これはAIエージェントが読み取りやすい構造なので、新テーマでも中核にする。

| ブロック系統 | 特徴 | 個人アフィリエイトでの価値 | 法人LPでの価値 |
|---|---|---|---|
| FAQ | Q/A構造、FAQ記事に使える | 商標記事、比較記事、SEO補強 | 製品FAQ、導入前の不安解消 |
| Step | 手順・導入フロー | 申込手順、使い方解説 | 導入フロー、オンボーディング |
| Button | CTAの基礎 | アフィリエイトリンク誘導 | 問い合わせ、資料DL、デモ申込 |
| Review | 評価・レビュー表示 | 商品レビューの中核 | 導入事例の評価表現には限定利用 |
| Post List | 条件付き投稿一覧 | 収益記事への回遊 | ニュース、事例、コラム導線 |
| Banner Link | 画像付き導線 | キャンペーン誘導 | 製品キャンペーン、資料導線 |
| Full Wide | 横幅いっぱいのセクション | 簡易LP | 法人LPセクションの基礎 |
| Accordion | 折りたたみ | 比較表の補足、FAQ | 料金注記、仕様詳細 |
| Tab | タブ切り替え | 比較軸の切替 | 機能/プラン/業種別訴求 |
| Restricted Area | 制限表示 | 優先度低 | 会員、代理店、顧客限定資料 |

### 新テーマで優先する独自ブロック

| 優先 | ブロック | 理由 |
|---|---|---|
| P0 | FAQ | 両パッケージで必須 |
| P0 | Step | 両パッケージで必須 |
| P0 | CTA Button | CV導線の基礎 |
| P0 | Product Card | 個人は商品、法人は製品 |
| P0 | Comparison Table | 個人は比較、法人はプラン/機能比較 |
| P0 | LP Section | 法人LP強化の中核 |
| P1 | Ranking | アフィリエイト特化 |
| P1 | Case Study | 法人向け |
| P1 | Post List | 回遊導線 |
| P2 | Restricted Area | 法人オプション |

## 3. 管理画面

参照テーマは独自管理メニューで、速度、構造化データ、jQuery、Font Awesome、機能停止、広告、エディター設定などを持つ。

| 管理機能 | 特徴 | 新テーマでの扱い |
|---|---|---|
| 基本設定 | パフォーマンス、構造化データ、不要機能停止 | 共通Coreに必要 |
| エディター設定 | 色、ボーダー、ボタン、マーカー、FAQ、テーブル | JSONデザイントークンに寄せる |
| 広告設定 | ad code、infeed、広告タグ | 個人パッケージで中核 |
| ふきだし | 会話アイコン管理 | 個人では任意、法人では低優先 |
| パターン導線 | WPパターン/再利用ブロックへの導線 | 法人の再利用パーツ管理に有効 |
| アクティベート | ライセンス/認証 | 自テーマの販売形態次第。今は設計対象外 |

### 設計に生かす点

| 採用 | 内容 |
|---|---|
| 設定カテゴリを分ける | `performance`、`editor`、`affiliate`、`lp`、`tracking`、`seo` |
| 同じ保存領域にまとめる | 設定をJSONまたは単一optionにまとめ、export/importしやすくする |
| パッケージ別UI | 個人には広告/レビュー、法人にはLP/CTA/ブランドだけを見せる |

## 4. CPT/Taxonomy

| CPT/Taxonomy | 参照テーマの用途 | 新テーマでの設計 |
|---|---|---|
| `lp` | LP専用投稿タイプ | 法人で強化。個人は簡易利用 |
| `blog_parts` | 再利用パーツ | 法人のCTA/セクション管理に採用 |
| `ad_tag` | 広告タグ管理 | 個人アフィリエイトの中核 |
| `parts_use` | 再利用パーツ用途分類 | CTA、FAQ、LPセクション、カテゴリ用などに再設計 |

### 設計に生かす点

| 取り込み | 理由 |
|---|---|
| 再利用パーツCPT | LPや記事内CTAの運用効率が上がる |
| 広告/CTAを投稿とは別管理 | アフィリエイトリンクや法人CTAを差し替えやすい |
| taxonomyで用途分類 | AIエージェントが適切な部品を選びやすい |

## 5. REST/API

参照テーマはブロック設定取得/更新、PV計測、ボタン/広告クリック計測、リセットなどをRESTで扱っている。

| API系統 | 特徴 | 新テーマでの判断 |
|---|---|---|
| ブロック設定 | 管理者権限で設定更新 | JSON設定APIとして採用 |
| PV計測 | 公開POST | 再設計。bot対策、rate limitが必要 |
| CTA/広告クリック | post metaにカウント | 再設計。イベントログ型か集計型を選ぶ |
| リセット | 管理者権限 | 法人向け管理機能に採用 |

### 新テーマのAPI方針

| API | 認可 | 用途 |
|---|---|---|
| `GET /theme-settings` | edit_posts以上 | エディター設定取得 |
| `POST /theme-settings` | manage_options | 設定更新 |
| `POST /events/cta` | nonce + rate limit | CTAクリック計測 |
| `POST /events/affiliate` | nonce + rate limit | アフィリエイトクリック計測 |
| `POST /agent/actions/dry-run` | manage_options | AI操作の事前検証 |
| `POST /agent/actions/apply` | manage_options + nonce | AI操作の適用 |

## 6. パフォーマンス

| 機能 | 参照テーマの特徴 | 新テーマでの判断 |
|---|---|---|
| CSS分割 | 使用ブロックに応じたCSS読み込み | 採用 |
| インラインCSS | main CSSや動的CSSをinline出力可能 | 小規模では有効。過剰化に注意 |
| 遅延JS | SNS埋め込みなどを遅延 | 採用候補 |
| prefetch/PJAX | 体感速度改善 | 初期版では見送り。複雑化しやすい |
| 不要WP機能停止 | emoji、sitemap、oEmbed等 | 管理UIで選択式にする |

## 8. セキュリティ/運用

| 観点 | 設計に生かすこと |
|---|---|
| REST公開POST | nonce、rate limit、bot判定、入力制限を必須 |
| 管理更新 | `manage_options` または専用capability |
| メタ保存 | nonce確認、権限確認、sanitize、allowlist |
| 権限 | 法人パッケージは編集者/承認者/管理者を分ける |
| 監査 | 法人は設定変更ログとJSON exportが重要 |
