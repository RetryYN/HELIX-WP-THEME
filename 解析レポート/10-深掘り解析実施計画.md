# 10. 深掘り解析実施計画

## 目的

参照テーマを「さらっと見る」段階から、AGENT NEO の要件・設計・価格戦略へ接続できる粒度まで掘る。対象はコード、設定、REST、ブロック、テンプレート、計測、販売訴求、企画書との整合である。

## 解析スコープ

| 領域 | 対象 | 成果 |
|---|---|---|
| R0 Evidence | SWELL親テーマ、子テーマ、企画書、既存解析レポート | 証拠マップ |
| R1 Contracts | REST、CPT、taxonomy、block.json、settings、template parts | 観測契約 |
| R2 As-Is Design | 起動層、管理画面、動的CSS、アセット制御、パーツ分割 | 設計パターン |
| R3 Intent | 個人/法人/移行/S1/Automation SEOの事業意図 | 要件仮説 |
| R4 Routing | Core、個人、法人、移行、S1への機能振り分け | 実装優先度 |

## 深掘り対象

### 1. REST/API

| 観点 | 見るもの | AGENT NEOへの反映 |
|---|---|---|
| エンドポイント | `lib/rest_api.php` と関連クラス | `agent-actions.schema.json`、REST操作面 |
| 認可 | nonce、permission_callback、公開POST | 書き込みAPIはnonce/capability/rate limit必須 |
| 計測 | PV、button、ad counter | `tracking/event`、`section-engagement` と整合 |
| 設定 | block settings、style reset | JSON設定のdryRun/diffReviewへ置換 |

### 2. CPT/Meta/Options

| 観点 | 見るもの | AGENT NEOへの反映 |
|---|---|---|
| LP | `lp` post type | 法人LPと個人簡易LPの基盤 |
| 再利用部品 | `blog_parts` | reusable_parts、CTAパーツ、資料DLパーツ |
| 広告 | `ad_tag` | 個人版のad_tag_manager |
| taxonomy | `parts_use` | 部品用途分類、AIが検索しやすいregistry |
| settings | `Default_Settings.php` | design-tokens、package defaults |

### 3. Gutenberg/block.json

| 観点 | 見るもの | AGENT NEOへの反映 |
|---|---|---|
| block.json | `src/gutenberg/blocks/**/block.json` | `block-registry.json`の属性設計 |
| render | PHP render callback | `component-contracts.json` |
| style | block CSS分割 | conditional assets |
| content model | FAQ/Step/Button/Review/PostList | Core/個人/法人のブロック境界 |

### 4. 管理画面/設定

| 観点 | 見るもの | AGENT NEOへの反映 |
|---|---|---|
| メニュー構造 | `classes/Admin_Menu.php` | 個人はプリセット中心、法人は詳細設定 |
| editor settings | 色、ボーダー、ボタン、マーカー | design-tokens |
| speed settings | CSS/JS最適化、lazy load | performance defaults |
| ad settings | 広告コード、表示位置 | personal affiliate |

### 5. テンプレート/パーツ

| 観点 | 見るもの | AGENT NEOへの反映 |
|---|---|---|
| header/footer | `parts/header`, `parts/footer` | layout-registry |
| single/archive | post head/list/pagination | content templates |
| top/LP | main visual、post slider、pickup banner | LP section builder |
| breadcrumbs | parts/breadcrumb | SEO Core |

### 6. 販売/競合

| 観点 | 見るもの | AGENT NEOへの反映 |
|---|---|---|
| 価格 | SWELL/JIN:R/AFFINGER/Cocoon/Lightning | SKU価格の妥当性 |
| 売り方 | 買い切り、複数サイト、コミュニティ、フォーラム | LPコピーとFAQ |
| 上位版 | AFFINGER PACK3、Lightning Passport | 法人版/S1/Automation SEO別課金 |
| 無料導線 | Cocoon、Lightning無料版 | 移行プラグイン lead magnet |

## 実施順序

1. 価格・競合の公式情報を固定する。
2. 企画書とL1/L2の差分を抽出する。
3. SWELLのREST/CPT/block.json/settings/template partsを証拠付きで再集計する。
4. 機能をCore/個人/法人/移行/S1/Automation SEOへルーティングする。
5. ライセンス上の禁止事項を明記する。
6. JSON契約に落とす候補を `analysis-summary.json` と `package.matrix.json` へ反映する。

## ライセンス境界

参照テーマのコード、画像、CSS、固有文言、デザインデータはコピーしない。採用するのは設計抽象、機能カテゴリ、契約構造、改善余地だけに限定する。
