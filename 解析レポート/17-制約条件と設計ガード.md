# 制約条件と設計ガード

## 結論

AGENT NEOの最大制約は「高機能テーマとして作りたい機能の多くが、WordPress.org基準ではプラグイン領域に入る」こと。特にSEO、計測、CPT、カスタムブロック、フォーム、キャッシュ、SNS共有はテーマ本体に抱え込むと、配布先・移行性・審査・保守で制約になる。

したがって、AGENT NEOは次の境界で設計する。

| 区分 | 持たせるもの | 持たせない/分離するもの |
|---|---|---|
| Theme Core | FSE templates、theme.json、patterns、style variations、表示用CSS、テンプレートパーツ | 永続データ、CPT登録、計測保存、SEOメタ保存、フォーム処理 |
| Companion Plugin | JSON操作API、CPT、カスタムブロック、SEO Core、計測、A/B、LP/HP Blueprint、Automation SEO連携 | 見た目だけで完結するスタイル責務 |
| Migration Plugin | 既存WP抽出、変換プレビュー、S1誘導 | 無制限AI再構築、参照テーマ専用変換の乱立 |
| Automation SEO | AI生成、SEO/IA再設計、改善提案 | テーマ本体へのAI原価抱え込み |

## 1. ライセンス/著作権制約

### 制約

| 制約 | 内容 | 設計ガード |
|---|---|---|
| 参照テーマ流用禁止 | ThemeB/テーマA/テーマC等のコード、画像、CSS、固有文言、デモデザインはコピーしない | 設計抽象・機能分類・UX思想だけを取り込む |
| GPL互換 | WordPressテーマ/プラグインとして配布するファイルはGPL互換に寄せる | `LICENSE`, `readme`, `resources.md` を用意 |
| 第三者素材 | フォント、画像、JS、アイコンのライセンスが不明なものは同梱しない | 依存一覧とライセンス監査を必須化 |
| minify元ソース | minified JS/CSSを同梱する場合、元ソース/ビルド手順も管理する | `src/`, `build/`, `package-lock` を監査対象にする |
| 商標/名称 | WordPress、ThemeB、テーマAなどを製品名/slug先頭に使わない | AGENT NEO独自命名に限定 |

### 公式根拠

WordPress.org Theme Directoryでは、テーマzip内のコード、データ、画像はGPLまたはGPL互換である必要があり、第三者ライブラリや素材も互換ライセンスが必要とされている。また、デザインのクローンは不可とされている。

## 2. テーマ/プラグイン境界制約

### WordPress.org基準でテーマ本体に入れにくいもの

| 機能 | 判定 | AGENT NEO方針 |
|---|---|---|
| Custom Post Type | プラグイン領域 | `agent-neo-core` pluginへ |
| Custom blocks | プラグイン領域になり得る | reusable dataを持つブロックはplugin、純粋なstyle/patternはtheme |
| SEO options | プラグイン領域 | SEO Coreはcompanion pluginへ |
| Analytics/tracking | プラグイン領域 | 計測/A-Bはcompanion pluginへ |
| Contact forms | プラグイン領域 | 初版は外部フォーム連携。内蔵フォームはplugin |
| Caching/resource optimization | プラグイン領域 | テーマは読み込み方針のみ。キャッシュはplugin/hostingへ |
| Social share/follow | プラグイン領域扱いに注意 | 個人版機能ならplugin側で制御 |

### 設計ガード

- Theme Coreは見た目とFSE構造に絞る。
- 収益化、SEO、計測、AI操作、CPT、設定保存はCompanion Pluginに置く。
- テーマ単体でも表示崩壊しないが、高度機能はplugin有効化時に解放する。
- WordPress.org配布を狙う移行プラグインは、trialware/ロック機能/過剰アップセルを避ける。

## 3. プライバシー/計測制約

### 制約

| 制約 | 内容 | 設計ガード |
|---|---|---|
| 計測はopt-in | ユーザー追跡や外部送信は明示同意が必要 | 初期状態はローカル/無効。外部送信は同意後 |
| PII最小化 | メール、氏名、IP、Cookie IDをむやみに保存しない | 匿名/仮名ID、短期保持、削除API |
| 外部送信の明示 | Automation SEO、GA4、GTM、CRM送信内容を説明する | privacy policy template と data map |
| 第三者広告/タグ | ASP/広告/CRMタグはページ速度とプライバシーを壊す | third-party tag governanceで遅延/条件/同意 |
| 管理画面広告 | WordPress.org pluginでは過剰な広告・誘導が不利 | 設定ページ内に限定し、dismiss可能にする |

### 公式根拠

WordPress.org Plugin Guidelinesでは、ユーザー追跡には同意が必要であり、外部サーバーへの接触やデータ利用はreadmeやprivacy policyで説明することが求められている。

## 4. アフィリエイト/広告表示制約

### 制約

| 制約 | 内容 | 設計ガード |
|---|---|---|
| PR表記 | 広告/PR/アフィリエイトであることを判別できる表示が必要 | affiliate disclosure blockをP0 |
| 比較の根拠 | ランキング、レビュー、比較に根拠が必要 | `review_basis`, `last_verified_at`, `source_url` を持つ |
| 誇大表示 | 「必ず稼げる」「No.1」等は根拠なしに出せない | copy validationで禁止表現/根拠要求 |
| 広告主関与 | 事業者が表示内容に関与するとステマ規制対象になり得る | PR表示とレビュー根拠の明示 |

### 公式根拠

消費者庁は、2023年10月1日から「一般消費者が事業者の表示であることを判別することが困難な表示」を景品表示法違反として扱う指定告示を施行している。アフィリエイト広告等も広告表示の明瞭性が重要になる。

## 5. AI操作制約

### 制約

| 制約 | 内容 | 設計ガード |
|---|---|---|
| 破壊的変更 | AIがLP/CTA/SEOを壊す可能性 | dryRun、diffReview、rollback、versioning |
| XSS | AI生成HTMLや広告タグがscriptを混入する可能性 | allowlist HTML、sanitize、script禁止、権限分離 |
| SSRF | URL取得/OGP取得/移行で内部URLへアクセスする可能性 | URL allowlist、private IP拒否、timeout |
| 権限昇格 | 個人版から法人機能や管理APIを叩く可能性 | capability + package gate + license scope |
| MCP/CLI危険操作 | terminal経由でファイルやDBを変更できる | path allowlist、confirm、audit log |
| Prompt Injection | 移行元コンテンツや外部ページがAI指示を含む可能性 | content-as-data扱い、tool権限分離 |

## 6. SEO制約

| 制約 | 内容 | 設計ガード |
|---|---|---|
| SEO plugin重複 | Yoast/Rank Math等とmeta/JSON-LDが重複する | conflict detectorと出力優先順位 |
| Ranking保証禁止 | AI/テーマで検索順位を保証できない | 販売文言で保証表現を禁止 |
| FAQ/Review schema | 表示内容と構造化データが一致しないとリスク | visible content syncを必須 |
| canonical/noindex誤設定 | AI操作で流入ページをnoindex化する恐れ | critical SEO change warning |
| 生成コンテンツ品質 | AI記事の品質/独自性/監修が不足する恐れ | review workflow、根拠/source管理 |

## 7. パフォーマンス制約

| 制約 | 内容 | 設計ガード |
|---|---|---|
| 巨大CSS | テーマA型の巨大global CSSはAGENT NEOと相性が悪い | used block CSS、critical CSS |
| 第三者タグ | GA4/GTM/広告/CRMがLCP/INPを悪化させる | defer、idle、consent、page condition |
| Hero画像 | LPのHeroがLCPを支配する | image budget、preload、fetchpriority |
| A/B計測 | 計測JSが初期描画を邪魔する | no-blocking tracking |
| フォント | 多数フォント/weightでCLS/LCP悪化 | font budget |

## 8. アクセシビリティ制約

| 制約 | 内容 | 設計ガード |
|---|---|---|
| キーボード操作 | CTA、メニュー、フォーム、タブがkeyboardで使えないと不可 | focus visible、aria、tab order |
| skip link | ヘッダー/ナビを飛ばす導線が必要 | `<main>` とskip link |
| 色コントラスト | ブランド色だけで読ませると失敗 | WCAG 2.2 AA目標 |
| 動き | LP演出が過剰だと酔い/操作阻害 | prefers-reduced-motion対応 |

## 9. 販売/パッケージ制約

| 制約 | 内容 | 設計ガード |
|---|---|---|
| 法人版価格 | `¥98,000` はテーマ単体だと高く見える | LP運用基盤 + 計測 + S1導線で売る |
| AI原価 | Automation SEOをテーマ価格に抱えると赤字化 | 別課金/BYO API/S1 |
| 無料移行プラグイン | 無制限AI移行を無料化すると原価崩壊 | 抽出/プレビュー無料、AI再構築はS1 |
| GPL再配布 | 買い切りテーマは再配布され得る | ライセンスは更新/サポート/クラウド連携価値で設計 |
| WordPress.org制約 | trialwareやロック機能は不可 | 無料pluginは自立価値を持たせる |

## 10. 実装制約

| 制約 | 内容 | 設計ガード |
|---|---|---|
| WP/PHP対応 | WordPress 6.6+ / PHP 8.1+前提 | CI matrix |
| FSE整合 | classic PHPに寄せすぎるとFSEテーマ価値が薄れる | theme.json/templates/patterns優先 |
| データ移植性 | テーマ無効化でLP/SEO/計測データが消えると危険 | plugin側DB/metaに保存 |
| 多機能化 | 管理画面が複雑になりすぎる | package gate、progressive disclosure |
| 後方互換 | JSON契約変更でAI操作が壊れる | schema versioning |

## 11. プラグイン依存度制約

### 結論

AGENT NEOは「プラグイン不要の万能テーマ」ではなく、「Theme Core + Core Pluginを最小必須セットにしたAI運用基盤」として設計する。ただし、外部のSEOプラグイン、フォームプラグイン、キャッシュプラグイン、GA/GTM系プラグインへは依存しない。依存しないが、検出して衝突を避け、必要に応じてadapterで連携する。

### 依存度レベル

| レベル | 依存種別 | 依存度 | AGENT NEO方針 |
|---|---|---:|---|
| D0 | WordPress本体 / PHP | 必須 | WP 6.6+ / PHP 8.1+を前提にする |
| D1 | `agent-neo-theme` | 必須 | 表示、FSE、theme.json、templates、patternsを担当 |
| D2 | `agent-neo-core-plugin` | 実質必須 | JSON操作API、MCP、WP CLI、CPT、SEO Core、計測、A/B、Blueprintを担当 |
| D3 | `agent-neo-migration-plugin` | 任意 | 移行時だけ利用。通常運用の必須依存にしない |
| D4 | `seo-tool-connector` | 推奨/連携 | Automation SEO連携、既存tracking API互換。ない場合はローカル軽量計測にfallback |
| D5 | Automation SEO | 有料/外部依存 | AI生成、SEO/IA再設計、改善提案。テーマ本体の動作必須条件にしない |
| D6 | Yoast / Rank Math等SEOプラグイン | 任意/共存 | 依存しない。検出して重複meta/JSON-LDを抑制 |
| D7 | Contact Form 7 / MW WP Form / HubSpot等 | 任意/adapter | フォームは内蔵前提にしない。CTA/外部フォームadapterで扱う |
| D8 | キャッシュ/高速化プラグイン | 任意/共存 | 依存しない。テーマ側は条件付きassetsと速度予算を守る |
| D9 | GA4/GTM/広告タグ系 | 任意/同意制 | 依存しない。third-party tag governanceで遅延/同意/条件付き出力 |

### パッケージ別の依存度

| パッケージ | 必須依存 | 任意依存 | 設計上の注意 |
|---|---|---|---|
| 個人版 | Theme + Core Plugin | seo-tool-connector、ASPタグ、SEOプラグイン共存 | 導入摩擦を下げるため、ランキング/比較/CTAはCore Pluginだけで完結させる |
| 法人版 | Theme + Core Plugin | Automation SEO、CRM/MA、外部フォーム、GTM | `¥98,000`の価値は外部連携ではなく、LP/HP Blueprint、計測、改善運用基盤に置く |
| 移行プラグイン | Migration Plugin単体 | Automation SEO、Core Plugin | wp.org申請を想定し、無料版単体でも抽出/プレビュー価値を持たせる |
| S1/Automation SEO | Automation SEO | Theme/Core Plugin/seo-tool-connector | テーマ必須機能ではなく、上位サービスとして分離する |

### 依存度が高すぎる場合のリスク

| リスク | 内容 | 回避策 |
|---|---|---|
| 導入摩擦 | 「テーマなのに複数プラグイン必須」に見える | 必須はTheme + Core Pluginの2点に限定 |
| 衝突 | SEO、schema、canonical、OGP、cache、JS最適化が競合 | PluginConflictDetectorと出力優先順位を持つ |
| サポート負荷 | 他社プラグインの不具合まで問い合わせ対象になる | supported adapter listと責任境界を明記 |
| 速度劣化 | タグ/フォーム/解析プラグインがLCP/INPを壊す | third-party tag governanceとRUMで検知 |
| ロックイン | AGENT NEOを外すとLP/SEO/計測データが消える | データはplugin側に保存し、export可能にする |
| 審査リスク | wp.org pluginが有料機能ロックや過剰アップセルに見える | 無料pluginは単体価値を持ち、premiumは自社配布に分離 |

### 設計ガード

- 初期MVPの必須依存は `agent-neo-theme` + `agent-neo-core-plugin` に限定する。
- SEOプラグイン、フォームプラグイン、キャッシュプラグイン、計測プラグインは必須化しない。
- 外部プラグインは `detect -> capability map -> adapter -> conflict rule` の順で扱う。
- プラグイン未導入でも、表示・基本SEO・基本CTA・ローカル軽量計測は成立させる。
- Automation SEO未契約でも、手動編集とJSON操作APIは動くようにする。
- 他社プラグインの内部DBやprivate APIに密結合しない。
- 連携adapterは個別パッケージ化し、Core Pluginを肥大化させない。

## 初期アーキテクチャ制約

AGENT NEOは最初から分離構成にする。

```text
agent-neo-theme/
  theme.json
  templates/
  parts/
  patterns/
  styles/

agent-neo-core-plugin/
  REST API
  MCP bridge
  WP CLI
  CPT / custom blocks
  SEO Core
  Tracking / A-B
  LP/HP Blueprint
  License/package gate

agent-neo-migration-plugin/
  extraction
  conversion preview
  S1 handoff
```

## Gate

| Gate | 判定 | 根拠 |
|---|---|---|
| RG0 | passed | WordPress公式Theme/Plugin Guidelines、消費者庁ステマ情報、既存設計を確認 |
| RG1 | passed | ライセンス、plugin territory、privacy、AI操作、SEO、計測の制約を抽出 |
| RG2 | passed | Theme Core / Companion Plugin / Migration Plugin / Automation SEOの境界とプラグイン依存度を定義 |
| RG3 | passed | L1/L2/package matrix/summaryへ反映対象を決定 |
| R4 | passed | 制約を設計ガードと未決事項へルーティング |
