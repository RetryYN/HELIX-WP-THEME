# テーマコーディングルール逆引き設計

## 結論

AGENT NEO Themeは、SWELL型の「薄いbootstrap + 責務別module分割 + block.json中心 + 条件付きasset」を採用し、JIN:R型の「SEO設定UXとページ文脈に応じたmeta生成思想」を抽象化して取り込む。ただし、JIN:Rのように`functions.php`へenqueue、SEO、block初期化、管理画面処理を集中させる構造は採用しない。

テーマ本体を作るなら、次の方針にする。

| 判断 | 方針 |
|---|---|
| 起動 | `functions.php`はbootstrapだけ。実処理は`inc/`と`src/`へ分割 |
| FSE | `theme.json`、`templates/`、`parts/`、`patterns/`を正本にする |
| PHP | WordPress Coding Standards準拠。snake_case、escape/sanitize徹底 |
| Block | `block.json`中心。表示だけのblock/patternはtheme、永続データやCPTはCompanion Plugin |
| CSS/JS | route/block/part単位で分割。未使用CSS/JSは読み込まない |
| SEO | themeは表示契約とhead出力adapterまで。SEO保存/重複検出はCore Plugin |
| AI操作 | theme内に安定ID、section属性、manifestを持たせる。書き込みAPIはthemeに持たせない |

## HELIX Reverse実施

| Phase | 実施内容 | 判定 |
|---|---|---|
| R0 Evidence Acquisition | SWELL/JIN:Rのbootstrap、autoload、hook、block、SEO、asset、sanitize/escapeを確認 | passed |
| R1 Observed Contracts | 実コードから命名、読み込み順、block登録、asset条件、SEO出力、権限チェックを抽出 | passed |
| R2 As-Is Design | SWELLは分割/速度、JIN:RはSEO UX/ページ文脈の強みと復元 | passed |
| R3 Intent Hypotheses | AGENT NEO ThemeではFSE/AI操作/速度/SEO共存を優先すると仮定 | passed |
| R4 Gap & Routing | L2/L3/JSON/packageへ反映する規約に整理 | passed |

## R0: 観測証拠

| 対象 | 証拠 | 観測 |
|---|---|---|
| SWELL bootstrap | `swell/functions.php` | `functions.php`で環境チェック、定数、autoload、main class、責務別`lib/*`読み込み |
| SWELL loader | `swell/lib/load_files.php` | front/admin/block assets等をloader層で分離 |
| SWELL autoload | `swell/lib/autoloader.php` | theme namespace/class prefix配下だけをautoload |
| SWELL block | `swell/lib/gutenberg/register_blocks.php`、`classes/Utility/Others.php` | block一覧を集中管理し、`block.json` metadataから登録 |
| SWELL performance | `swell/lib/load/front.php`、`classes/Pre_Parse_Blocks.php` | 使用blockをpre-parseし、必要CSSだけ読み込む |
| SWELL SEO/schema | `swell/classes/Json_Ld.php` | EntityごとにJSON-LD生成関数を分割し、SEO plugin存在時の分岐を持つ |
| JIN:R bootstrap | `jinr/functions.php` | enqueue、meta削除、customizer、block初期化、SEO関連読み込みが集中 |
| JIN:R SEO | `jinr/include/head/title.php`、`include/json-ld.php` | ページ種別ごとにtitle/schemaを組み立てるUXは強い |
| JIN:R block | `jinr/functions.php` | dynamic render callbackを多数登録するが、初期化が肥大化しやすい |

## R1: 逆引きしたコーディングルール

### 命名

| 対象 | AGENT NEO規約 | 理由 |
|---|---|---|
| theme slug | `agent-neo` | WP標準のlowercase-hyphen |
| text domain | `agent-neo` | i18nとslugを一致 |
| PHP namespace | `Agent_Neo\Theme` | 衝突回避。WPCS互換のunderscore系class名 |
| class | `Agent_Neo_Theme`, `Asset_Loader` | WordPress Coding Standardsに寄せる |
| function | `agent_neo_get_asset_url()` | lowercase + underscore |
| hook | `agent_neo/theme/setup` | vendor prefix必須 |
| block namespace | `agent-neo/hero`, `agent-neo/cta` | WP block namespaceとして安定 |
| CSS class | `an-hero`, `an-section`, `is-style-*` | 固有prefixで衝突回避 |
| data属性 | `data-an-section-id`, `data-an-cta-id` | AI/計測が安定参照できる |

### ファイル/ディレクトリ

| ルール | 採用 |
|---|---|
| `functions.php`は起動だけ | 必須 |
| class fileは`class-*.php` | 必須 |
| view/template partialは`parts/`または`patterns/` | 必須 |
| 設定defaultは1箇所に集約 | 必須 |
| build成果物とsrcを分ける | 必須 |
| minifiedだけの同梱禁止 | 必須 |

### Hook

| ルール | 採用 |
|---|---|
| hook登録はmoduleの`register()`へ集約 | 必須 |
| 無名関数の多用を避ける | 必須 |
| hook名、priority、責務を一覧化 | 必須 |
| `init`、`after_setup_theme`、`wp_enqueue_scripts`、`enqueue_block_assets`の責務を分離 | 必須 |
| 公開filter/actionは`agent_neo/*` prefix | 必須 |

### Escape/Sanitize

| 出力/入力 | ルール |
|---|---|
| HTML text | `esc_html()` |
| attribute | `esc_attr()` |
| URL | `esc_url()` |
| rich text | `wp_kses()` with allowlist |
| option/meta input | `sanitize_text_field()`、`sanitize_key()`、`absint()`、`rest_sanitize_value_from_schema()` |
| JSON-LD | 配列構築後に`wp_json_encode()`、空値削除、script内へ安全出力 |
| AI生成HTML | themeでは保存しない。表示時もallowlist必須 |

## R2: 参照テーマから採用/不採用

| 観測パターン | 採用判断 | AGENT NEOでの形 |
|---|---|---|
| SWELLの薄い`functions.php` | 採用 | bootstrapのみ |
| SWELLの責務別`lib/load/*` | 採用 | `inc/assets/class-asset-loader.php`等へ |
| SWELLの`block.json`登録 | 採用 | `blocks/*/block.json`正本 |
| SWELLのused block CSS | 採用/改良 | `Used_Block_Collector` + `asset-policy.json` |
| SWELLのdefault settings集中 | 採用 | `inc/settings/class-defaults.php` |
| SWELLのCPT/RESTをtheme内に持つ構造 | 不採用 | Core Pluginへ移動 |
| JIN:RのSEO title/description UX | 採用/改良 | SEO表示adapterとUI方針に抽象化 |
| JIN:Rの`functions.php`肥大化 | 不採用 | module register方式 |
| JIN:Rのglobal CSS/jQuery依存 | 不採用 | vanilla JS + conditional islands |
| JIN:Rのページ種別別schema | 採用/改良 | Entity Graph BuilderはCore Plugin、themeはrender hookだけ |

### 起動設計

| Step | 内容 | ファイル |
|---|---|---|
| 1 | `ABSPATH`チェック、version/path定数、bootstrap読み込み | `functions.php` |
| 2 | autoloadまたは明示require | `inc/bootstrap.php` |
| 3 | module container生成 | `inc/class-theme.php` |
| 4 | `after_setup_theme`でtheme support/i18n | `inc/setup/*` |
| 5 | `init`でpattern/block category登録 | `inc/blocks/*`, `inc/patterns/*` |
| 6 | `wp_enqueue_scripts`で条件付きasset | `inc/assets/*` |
| 7 | `wp_head`でhead adapter出力 | `inc/seo/*` |

### ThemeとCore Pluginの境界

| 機能 | Theme | Core Plugin |
|---|---|---|
| FSE templates | owner | 参照のみ |
| style variation | owner | 参照のみ |
| pattern | owner | 必要なら生成補助 |
| visual-only block | owner | 連携可 |
| data block/CPT | render shellのみ | owner |
| SEO meta保存 | 表示adapter | owner |
| JSON操作API | manifest提供 | owner |

## R4: L3で凍結すべきテーマ規約

### Coding Rules

| ID | ルール | 判定 |
|---|---|---|
| CR-001 | WordPress Coding Standards準拠 | P0 |
| CR-002 | `functions.php`はbootstrapのみ | P0 |
| CR-003 | すべての公開関数/hook/CSS/data属性に`agent_neo`/`an-` prefix | P0 |
| CR-004 | 入力はschema sanitize、出力はcontext escape | P0 |
| CR-005 | blockは`block.json`を正本にする | P0 |
| CR-006 | route/block/part別asset policyを持つ | P0 |
| CR-007 | jQueryは初期無効、必要時のみfeature flag | P0 |
| CR-008 | SEO/headは重複検出可能なadapter出力 | P0 |
| CR-009 | 参照テーマのコード/CSS/画像/固有文言コピー禁止 | P0 |
| CR-010 | theme無効化で消えると困るデータはthemeに保存しない | P0 |

### テスト/検証

| ID | 検証 | 期待 |
|---|---|---|
| TC-CR-001 | PHPCS WordPress ruleset | error 0 |
| TC-CR-002 | Theme Check | required error 0 |
| TC-CR-003 | block.json schema check | all blocks valid |
| TC-CR-004 | asset policy check | 未使用block CSS/JSを読み込まない |
| TC-CR-005 | escape/sanitize grep | raw echo/未escape attributeを検出しない |
| TC-CR-006 | plugin off fallback | Core Plugin無効でも表示は崩壊しない |
| TC-CR-007 | SEO plugin coexistence | duplicate title/meta/schema warningまたは抑制 |

## 公式規約との整合

| 公式規約 | AGENT NEOへの反映 |
|---|---|
| WordPress PHP Coding Standards | 命名、ファイル名、escape/sanitize、WPCS/PHPCSを採用 |
| WordPress Plugin/Theme Best Practices | 衝突回避prefix、最小bootstrap、標準hook、外部依存明示 |
| WordPress Plugin Security | nonce/capability/sanitize/escapeの考え方をTheme側にも適用 |

## 逆引きで見えた注意点

- 参照テーマの「便利機能」はテーマ内に入れすぎない。AGENT NEOではFSE表示層に絞る。
- JIN:RのSEO設計はUXとして参考になるが、実装形はclassic theme寄りなのでFSEへ再設計する。
- SWELLの速度設計は強いが、CPT/REST/計測までtheme内に置く設計はAGENT NEOではCore Plugin側へ分ける。
- コーディング規約は参照テーマ準拠ではなく、WordPress公式規約 + AGENT NEO独自prefix/JSON契約を正本にする。
