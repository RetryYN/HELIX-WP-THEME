# テーマ構築観点総合レビュー

## 1. 結論

ThemeB/テーマAの逆引き解析で、SEO、速度、LP/HP、制約、プラグイン依存、自動化API、AIエージェント運用性は主要論点として整理済みである。一方で、商用テーマとして実装に入る前に、WordPress公式基準とWeb標準から見て以下を明示契約に昇格すべきである。

| 判定 | 観点 | 理由 |
|---|---|---|
| 要追加 | Theme Review/配布準備 | `style.css`、`readme.txt`、`theme.json`、`templates/index.html`、管理通知、設定保存、外部通信などは審査・配布・信頼性に直結する |
| 要追加 | アクセシビリティ実査 | WCAG 2.2 AA目標だけでは不足。キーボード、focus、contrast、skip link、aria、動的UIの検証契約が必要 |
| 要追加 | i18n/RTL/日本語組版 | ja/en対応だけでは不足。textdomain、翻訳関数、RTL、日付/通貨/改行/フォントfallbackを契約化する |
| 要追加 | Release/SBOM/供給網 | 商用テーマはzip成果物、依存ライセンス、checksum、changelog、rollback、脆弱性対応の証跡が必要 |
| 要追加 | ホスティング互換性 | 共有サーバー、REST無効、loopback不可、WP-Cron遅延、WAF、権限不足、object cache有無を想定する必要がある |
| 要追加 | Privacy retention/削除 | 計測・AI・外部連携を持つため、収集最小化だけでなく保持期間、export/erase、ログ匿名化が必要 |
| 要追加 | ブロック更新互換 | block.json正本に加え、attributes、supports、variation、deprecated変換、asset lazy enqueueの方針が必要 |
| 要追加 | SEO indexing policy | canonical/noindexだけでなく、sitemap、robots、taxonomy、pagination、404、redirect、media attachment、hreflangの方針が必要 |
| 要追加 | Documentation/Support | 売れるテーマは機能だけでなく、導入手順、移行、FAQ、トラブル診断、サポート提出情報が強い |

総合判定は `passed_with_required_gaps`。企画の方向性は成立しているが、L3詳細設計に入る前に「テーマ品質/配布準備」をP0非機能要件へ追加する。

## 2. Web一次情報から逆算した観点

| ソース | AGENT NEOへ取り込む観点 |
|---|---|
| WordPress Theme Handbook | block theme、theme.json、template、style variation、theme releaseの標準構造を正本にする |
| WordPress Theme Review Required | plugin territory、必須ファイル、管理画面、設定保存、外部通信、ユーザー同意、権限確認をガード化する |
| WordPress Security APIs | sanitize、validate、escape late、nonce、capability、permission_callbackを全操作面で必須にする |
| WordPress block.json metadata | block.jsonをブロックの単一正本にし、server registration、asset lazy enqueue、schema validation、i18nを使う |
| WordPress i18n | textdomain、翻訳関数、翻訳ファイル、RTL、日本語/英語の表示差分を検証する |
| WordPress Privacy | 計測・外部API・ログ・ブラウザ保存の個人データ扱い、export/erase、retentionを定義する |
| W3C WCAG 2.2 | a11yを抽象目標ではなく、contrast、focus、keyboard、target size、status messagesまでテスト対象にする |
| web.dev Core Web Vitals | LCP/INP/CLSを性能予算にし、Lighthouseだけでなくfield/RUMも前提にする |
| Google Search Central | 構造化データ、sitemap、robots、technical requirementsをSEO契約へ追加する |
| WP-CLI | テーマ導入、更新、診断、契約検証をCLIで再現可能にする |

## 4. 実装前に追加すべき品質ゲート

| Gate | 内容 | fail条件 |
|---|---|---|
| Theme Review Gate | 必須ファイル、plugin territory、管理通知、設定保存、外部通信、権限、同意を確認 | Theme本体にCPT/SEO保存/計測保存/API永続化が混入 |
| Accessibility Gate | WCAG 2.2 AA目標、keyboard、focus、contrast、aria、motion、tap targetを確認 | 主要LP/記事/管理画面でキーボード操作不能 |
| i18n/RTL Gate | textdomain、翻訳抽出、RTL、ja/en表示、日時/通貨、長文翻訳を確認 | ハードコード文言、翻訳不能UI、RTL崩れ |
| Release Gate | version、changelog、SBOM、license list、checksum、rollback、deprecationを確認 | 依存元不明、minified sourceなし、rollback不可 |
| Hosting Gate | PHP/WP/DB、REST、loopback、cron、WAF、file permission、object cache有無を確認 | 共有サーバーで有効化不能、REST停止で全操作不能 |
| Privacy Gate | telemetry、tracking、cookies、localStorage、external API、log retentionを確認 | opt-inなし外部送信、保持期間未定義 |
| SEO Indexing Gate | robots、sitemap、canonical、noindex、pagination、taxonomy、redirect、404を確認 | noindex/canonical事故をdryRunで検出できない |
| Documentation Gate | setup、migration、troubleshooting、contract reference、support bundleを確認 | ユーザーが導入/復旧/問い合わせを再現できない |

## 5. AIエージェント前提での追加設計

AI操作前提では、通常テーマの「画面で何となく設定できる」は負債になる。追加すべき契約は以下。

| 契約 | 目的 |
|---|---|
| `quality-gate-result.schema.json` | AIが実装/更新前に、a11y/SEO/速度/Privacy/Releaseの通過状況を読めるようにする |
| `support-bundle.schema.json` | WP/PHP/DB/テーマ/プラグイン/設定/ログをマスクしてAIやサポートへ渡せるようにする |
| `documentation-map.json` | UI項目、API、WP-CLI、FAQ、runbookの参照先を機械可読化する |
| `editor-governance.schema.json` | AIがstyle variation、template、patternを壊さないように編集範囲を限定する |
| `seo-indexing-policy.json` | AIがnoindex/canonical/sitemap変更時にrisk diffを出せるようにする |
| `privacy-retention-policy.json` | AIがログ削除、匿名化、外部送信可否を判断できるようにする |
