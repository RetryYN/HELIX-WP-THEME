# 設計参考とパーツカタログ

## 目的

参照テーマから、コードをコピーせずに新テーマ設計へ転用できる「構造」「パーツ」「編集体験」を抽出する。個人アフィリエイト向けと法人LP向けで、同じ部品でも使い方が違うため、用途別に整理する。

## 設計参考として採用する構造

| 参考構造 | 参照テーマでの観測 | 新テーマへの転用 |
|---|---|---|
| `functions.php` を薄く保つ | 起動、定数、autoload、lib読み込みに集中 | `Bootstrap` に責務集約し、AIが変更しない起動層にする |
| `lib/` と `classes/` の分離 | WP hook系と状態/描画補助系を分けている | `inc/` と `features/` に整理し、feature単位で有効化 |
| `parts/` にテンプレート部品を分割 | header/footer/single/post-list/topなどを分割 | `layout-registry.json` で部品構成を宣言可能にする |
| `block.json` 中心 | ブロック属性・親子関係・カテゴリを宣言 | `block-registry.json` と同期し、AI生成可能な契約にする |
| 設定値からCSS生成 | 色・ボタン・FAQ・マーカー等を設定化 | `design-tokens.json` からCSS変数生成に再設計 |
| 機能停止フラグ | 不要WP機能、LP、広告、パターンなどをON/OFF | package matrixでCore/個人/法人の差分を宣言 |

## テンプレートパーツ参考

| パーツ系統 | 参照テーマの特徴 | 新テーマでの設計案 | 個人 | 法人 |
|---|---|---|---:|---:|
| Header | PC/SP、固定、情報バー、検索、メニュー説明 | `header.default`、`header.conversion`、`header.lp` | yes | yes |
| Footer | 複数カラム、SP専用、固定ボタン | `footer.simple`、`footer.corporate`、`footer.affiliate` | yes | yes |
| Single Head | タイトル、日付、カテゴリ、サムネイル | `single.review_head`、`single.article_head` | yes | yes |
| Single Bottom | 著者、関連記事、シェア、CTA | `single.affiliate_bottom`、`single.lead_bottom` | yes | yes |
| Post List | normal/simple/big/slider/widget | `post-list.card`、`post-list.ranking`、`post-list.news` | yes | yes |
| Top MV | single/movie/slider | `hero.article_pickup`、`hero.product_lp` | limited | yes |
| Breadcrumb | 独立パーツ | SEO Coreとして固定 | yes | yes |
| Sidebar | 共通、SP、固定、ページ別 | 個人は収益導線、法人は資料DL/問い合わせ | yes | yes |

## 個人アフィリエイト向けパーツ

| パーツ | 目的 | 推奨属性 |
|---|---|---|
| Product Card | 商品紹介の最小単位 | 商品名、画像、説明、価格、評価、CTA URL、PR表記 |
| Review Box | 商標レビュー記事の中核 | 総合評価、良い点、悪い点、向いている人、向かない人 |
| Ranking List | 複数商品の順位付け | 順位、商品、評価、特徴、CTA、計測ID |
| Comparison Table | 比較検討を支援 | 商品列、価格、機能、評価、キャンペーン、CTA |
| Affiliate CTA | クリック誘導 | ラベル、URL、rel、nofollow/sponsored、計測キー |
| Ad Slot | 広告タグ管理 | adId、表示位置、ASP、imp/click計測 |
| Disclosure Box | 広告表記 | PR文言、表示条件、全記事共通/記事別 |

| パーツ | 目的 | 推奨属性 |
|---|---|---|
| Hero Section | ファーストビューで製品価値を伝える | 見出し、サブコピー、CTA、画像/動画、実績文言 |
| Feature Grid | 機能一覧 | 機能名、説明、アイコン、詳細リンク |

| Case Study | 導入事例 | 企業名、課題、施策、成果、ロゴ |
| Pricing Section | 料金訴求 | プラン、価格、機能差分、問い合わせCTA |
| Trust Bar | 信頼要素 | 導入社数、受賞、認証、セキュリティ |

## パーツ設計で重要な判断

| 判断 | 方針 |
|---|---|
| 1パーツ1目的 | 何でもできる万能ブロックは避ける |
| 属性はJSON化 | AIが生成/検証できるよう、属性名と型を固定する |
| 表示と計測を分ける | CTA表示部品とイベント送信を疎結合にする |
| 個人/法人でUIを分ける | Product Cardは共通化できるが、見せ方は別presetにする |
| コピー防止 | 参照テーマのCSS class名・画像・文言・実装は使わず、概念だけ転用する |

## 具体的な設計転用例

```json
{
  "component": "agent-neo/product-card",
  "packages": ["personal_affiliate", "corporate_lp"],
  "presets": {
    "personal_affiliate": {
      "layout": "review-card",
      "fields": ["rating", "price", "pros", "cons", "affiliateCta"]
    },
    "corporate_lp": {
      "layout": "product-feature-card",
      "fields": ["featureList", "caseStudyLink", "leadCta"]
    }
  }
}
```
