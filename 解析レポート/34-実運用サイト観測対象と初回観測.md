# 実運用サイト観測対象と初回観測

実施日: 2026-04-30 JST

## 1. 目的

ユーザー指定の実運用中WordPressサイトを、ThemeB / テーマA の実運用観測対象として登録する。更新やローカル検証だけでは見えない、実サイトのプラグイン構成、SEO出力、REST API露出、ログイン面、HTML/アセット量を観測する。

管理画面URLは確認対象として扱うが、認証突破、ログイン試行、管理画面操作は行わない。観測は公開HTTP GETで取得できる範囲に限定する。

## 2. 観測対象

| 種別 | URL | 想定テーマ | 用途 |
|---|---|---|---|
| テーマA実運用 | `https://site-A.example/wp-admin/` | テーマA | テーマAの実運用SEO/速度/プラグイン連携/Automation SEO観測 |
| ThemeB実運用 | `https://site-B.example/wp-admin/` | ThemeB | ThemeBの実運用SEO/速度/プラグイン連携/Automation SEO観測 |

公開観測のrawは `tmp/real-site-observation/` に保存した。

## 4. テーマ・バージョン痕跡

| site | 観測された痕跡 | 判断 |

| テーマA実運用 | `/wp-content/themes/themeA/`、一部JS `ver=1.4.6` | テーマA `1.4.6` 相当で運用されている可能性が高い。 |
| ThemeB実運用 | `/wp-content/themes/themeB/`、CSS/JS `ver=2.15.0` | ThemeB `2.15.0` 相当で運用されている可能性が高い。ローカル `2.16.0` より古い。 |

## 5. SEO出力の実運用差分

| 観点 | テーマA実運用 | ThemeB実運用 | AGENT NEOへの示唆 |
|---|---|---|---|
| canonical | 出力あり | 出力あり | 実運用では両テーマともhome canonicalを持つ。ローカルThemeB初期環境のhome canonicalなしは設定/初期状態差分と見る。 |
| OGP | 6タグ | 6タグ | 実運用では両方ともOGPが整っている。テーマ単体ではなくSEO/運用設定込みで評価する必要がある。 |
| JSON-LD | homeで未検出 | homeで1 block | テーマAは実運用でも構造化データが出ない設定/ページがある。AGENT NEOでは必須schema profileを持つべき。 |
| title/description | テーマAは短いブランド型 | ThemeBは説明的なSEO title | 個人/法人パッケージでtitleテンプレートと検索意図テンプレートを分ける。 |
| sitemap | 両方あり | 両方あり | sitemapはGoogle XML Sitemaps系の出力痕跡あり。テーマ責務ではなく連携検出対象。 |

## 6. REST API露出

両サイトとも `/wp-json/` が公開され、Automation SEOと思われる `aseo/v1` namespace が確認できた。

| site | namespaces | routes count | 注目routes |
|---|---|---:|---|
| テーマA実運用 | `oembed/1.0`, `aseo/v1`, `contact-form-7/v1`, `flexible-table-block/v1`, `yyirest/v1`, `themeA`, `google-site-kit/v1`, `wp/v2`, `wp-site-health/v1`, `wp-block-editor/v1`, `wp-abilities/v1` | 228 | `/aseo/v1/ai/write`, `/aseo/v1/ai/bulk`, `/aseo/v1/media/upload`, `/themeA/external_url` |
| ThemeB実運用 | `oembed/1.0`, `aseo/v1`, `contact-form-7/v1`, `flexible-table-block/v1`, `wp/v2`, `google-site-kit/v1`, `wp-site-health/v1`, `wp-block-editor/v1`, `wp-abilities/v1` | 251 | `/aseo/v1/ai/write`, `/aseo/v1/media/upload`, `/wp/v2/themeB-ct-pv`, `/wp/v2/themeB-lazyload-contents` |

判断:

| 観点 | 判断 |
|---|---|
| 実運用価値 | 両サイトともAutomation SEO連携の観測対象として有用。テーマ単体ではなく、テーマ + Automation SEO + SEO/計測プラグインの実態が見える。 |
| セキュリティ注意 | 公開REST indexにAI write / media upload / update apply 系ルート名が出ている。ルート名の公開自体はWP RESTの通常挙動だが、権限、nonce、rate limit、監査ログを必ず確認する必要がある。 |
| AGENT NEO設計 | AI操作APIは公開indexに出る前提で、機密情報をroute名やschemaに含めない。危険操作はcapability、nonce、署名、dry-run、audit log、rollbackを必須化する。 |

## 7. ログイン面の観測

両サイトとも `/wp-admin/` はWordPress標準ログインフォームをHTTP 200で返す。

| site | title | 観測された要素 |
|---|---|---|
| テーマA実運用 | `ログイン ‹ IT就活大学 — WordPress` | `name="log"`, `name="pwd"`, lost password link |
| ThemeB実運用 | `ログイン ‹ 大人のひとりビジネスラボ — WordPress` | `name="log"`, `name="pwd"`, lost password link |

判断:

| 観点 | 判断 |
|---|---|
| 露出 | 標準ログイン面が公開されている。一般的なWP運用では普通だが、法人パッケージではログインURL変更、WAF、2FA、reCAPTCHA、rate limitを推奨する。 |
| AGENT NEO | AI運用APIを持つなら、管理ログイン保護だけでなくREST書き込み面の保護が必要。 |

## 8. AGENT NEOへの取り込み

| 項目 | 採用方針 |
|---|---|
| 実運用観測対象 | この2サイトを `real_world_reference` として継続観測対象にする。 |
| ローカルとの差分評価 | ローカル初期環境と実運用ではSEOタグ、OGP、canonical、plugin構成が大きく変わる。評価軸に「初期状態」と「実運用状態」を分ける。 |
| Automation SEO | `aseo/v1` が両サイトに存在するため、AGENT NEOのAutomation SEO連携設計は実サイトREST露出を前提に作る。 |
| セキュリティ | 公開REST index、ログイン面、write系API、media系API、update系APIは監査対象にする。 |
| 速度 | テーマA実運用はHTML/画像/JSが重い。テーマの素性だけでなく、運用プラグインとトップ設計が速度を支配する。 |
| SEO | ThemeB実運用はJSON-LD `@graph` を確認。テーマA実運用はhome JSON-LD未検出。AGENT NEOはschema出力を設定任せにせず、最低保証contractを持つ。 |

## 9. 次アクション

1. この2サイトを定点観測スクリプトの対象に追加する。
2. `/wp-json/` のroute一覧から、認証必須、nonce必須、危険操作、読み取り専用を分類する。
3. Lighthouse / PageSpeed API / Playwrightでブラウザ実測を追加する。
4. robots / sitemap / canonical / JSON-LD / OGP / REST露出を週次差分で保存する。
5. AGENT NEOの `security-profile.json` に、AI write系RESTの保護条件を追加する。
