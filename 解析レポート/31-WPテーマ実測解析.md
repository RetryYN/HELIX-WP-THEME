# WPテーマ実測解析

実施日: 2026-04-30 JST

## 1. 結論

Docker上の WordPress 実機環境で SWELL / JIN:R / 子テーマを切り替え、HTTP応答、HTML出力、SEOタグ、JSON-LD、Automation SEO連携プラグイン影響を実測した。

最重要の結論は次の通り。

| 観点 | 結論 |
|---|---|
| 実測速度 | このローカルDocker環境では JIN:R が SWELL より TTFB が短い。JIN:R home 平均TTFB `0.2679s`、SWELL home 平均TTFB `0.5138s`。 |
| HTML量 | JIN:R は HTML が大きい。home 約 `57KB`、SWELL home 約 `40KB`。速度差はHTML量ではなく PHP処理、設定初期化、テーマ処理経路の差が大きい可能性がある。 |
| SEO出力 | JIN:R は canonical / OGP / JSON-LD をテーマ側で強く出す。SWELL はこの初期環境では home の canonical / OGP が出ていない。 |
| 構造化データ | JIN:R は `WebSite, Organization, ImageObject`、SWELL は `Organization, WebSite, SearchAction` を確認。どちらも AGENT NEO では @graph 統合と検証可能な entity contract に再設計すべき。 |
| Automation SEO連携 | `seo-tool-connector` は JIN:R home で平均 `+0.0112s` TTFB、`+667 bytes`、`+3 scripts` の増加。小さいが常時ON前提なら予算化が必要。 |
| 致命的な環境不整合 | `permalink_structure` が `/C:/Program%20Files/Git/%postname%/` に壊れている。投稿URL計測、クロール、SEO検証の前に修正必須。 |
| JIN:R運用リスク | PHP 8.2 で `Trying to access array offset on value of type null` warning が多数発生。WP 7.0 / PHP更新耐性の観点では要注意。 |

今回の測定は curl ベースのサーバー応答とHTML解析であり、ブラウザ実行後の Core Web Vitals / Lighthouse 実測ではない。ホスト側に Chrome / Edge / Lighthouse が見つからなかったため、LCP / CLS / INP は未測定。

## 4. HTTP実測結果

5回ずつ curl で `time_starttransfer` と `time_total` を測定した。`/hello-world/` は permalink 破損の影響で正しい投稿URLではないため、有効比較から除外する。

| theme | page | HTTP | avg TTFB | avg total | HTML size |
|---|---|---:|---:|---:|---:|
| `jinr` | `/` | 200 | `0.2679s` | `0.2903s` | `57221` |
| `jinr` | `/sample-page/` | 200 | `0.2759s` | `0.2987s` | `60540` |
| `jinr-child` | `/` | 200 | `0.2704s` | `0.2944s` | `57373` |
| `jinr-child` | `/sample-page/` | 200 | `0.2737s` | `0.2960s` | `60692` |
| `swell` | `/` | 200 | `0.5138s` | `0.5657s` | `40169` |
| `swell` | `/sample-page/` | 200 | `0.5386s` | `0.5748s` | `41937` |
| `swell_child` | `/` | 200 | `0.5528s` | `0.6129s` | `40331` |
| `swell_child` | `/sample-page/` | 200 | `0.5425s` | `0.5767s` | `42099` |

解釈:

| 観点 | 解釈 |
|---|---|
| JIN:R vs SWELL | この環境では JIN:R の方がサーバー応答は速い。ただし PHP warning を出しながら動いているため、品質が高いという意味ではない。 |
| 親テーマ vs 子テーマ | 子テーマ化で CSS link が1つ増え、HTMLも微増する。TTFB差は小さい。 |
| SWELLの遅さ | SWELLは初期化、設定、ブロック/構造化データ/機能ロードのコストが出ている可能性がある。ブラウザ側速度とは別評価。 |
| JIN:Rの大きいHTML | JIN:RはSEO/OGP/装飾/テーマ出力が多い。ブラウザ計測ではCSS/JSの影響も見る必要がある。 |

## 5. HTML / SEO出力

| theme | page | CSS links | scripts | inline scripts | images | JSON-LD | canonical | meta desc | robots meta | OGP tags |
|---|---|---:|---:|---:|---:|---:|---|---|---|---:|
| `jinr` | home | 4 | 14 | 6 | 1 | 2 | true | false | true | 6 |
| `jinr` | sample | 4 | 15 | 7 | 0 | 2 | true | true | true | 6 |
| `jinr-child` | home | 5 | 14 | 6 | 1 | 2 | true | false | true | 6 |
| `jinr-child` | sample | 5 | 15 | 7 | 0 | 2 | true | true | true | 6 |
| `swell` | home | 11 | 11 | 3 | 5 | 1 | false | false | true | 0 |
| `swell` | sample | 8 | 8 | 3 | 0 | 1 | true | true | true | 0 |
| `swell_child` | home | 12 | 11 | 3 | 5 | 1 | false | false | true | 0 |
| `swell_child` | sample | 9 | 8 | 3 | 0 | 1 | true | true | true | 0 |

SEO観点の差分:

| 観点 | JIN:R | SWELL | AGENT NEOで採用すべき設計 |
|---|---|---|---|
| canonical | home / sample とも出力 | sample は出力、home は初期環境では未出力 | ページ種別別の canonical policy を JSON contract 化する |
| OGP | 初期環境でも6タグ確認 | 初期環境では0 | テーマ単体で最低限の OGP を保証し、SEOプラグイン併用時は重複抑止 |
| meta description | sample はあり、home はなし | sample はあり、home はなし | site profile / page profile から home description を明示管理 |
| JSON-LD | 2 blocks | 1 block | entity graph を1つの `@graph` に集約し、schema検証ログを残す |
| scripts | JIN:Rの方が多い | SWELLはCSS linkが多い | asset budget と conditional loading を必須化 |

## 6. JSON-LD実測

| theme | JSON-LD blocks | type |
|---|---:|---|
| `jinr` | 2 | `WebSite, Organization, ImageObject` |
| `jinr-child` | 2 | `WebSite, Organization, ImageObject` |
| `swell` | 1 | `Organization, WebSite, SearchAction` |
| `swell_child` | 1 | `Organization, WebSite, SearchAction` |

AGENT NEOでは、JIN:Rの「SEOをテーマ側で完結しやすい思想」と、SWELLの「entity graphを整理して出す思想」を統合するのがよい。実装では `entity-graph.schema.json`、`seo-profile.json`、`seo-conflict-rules.json` を持ち、SEOプラグインが有効な場合は出力責務を切り替える。

## 7. Automation SEO / seo-tool-connector 影響

JIN:R home で `seo-tool-connector` の active / inactive を5回ずつ測定した。

| plugin | avg TTFB | avg total | size | scripts | CSS |
|---|---:|---:|---:|---:|---:|
| active | `0.2771s` | `0.3021s` | `57221` | 14 | 4 |
| inactive | `0.2659s` | `0.2900s` | `56554` | 11 | 4 |
| 差分 | `+0.0112s` | `+0.0121s` | `+667` | `+3` | 0 |

判断:

| 観点 | 判断 |
|---|---|
| 速度影響 | 現状は小さい。ただし全ページ常時ON、A/B、イベント送信、管理バー連携が増えると無視できなくなる。 |
| テーマ側対応 | `section_id`、`cta_id`、`offer_id`、`variant_id` をHTMLに安定出力し、プラグイン側のDOM推測を減らす。 |
| Automation SEO側対応 | selector推測ではなく theme manifest / section registry を読む。失敗時は `confidence` を下げ、勝手に書き換えない。 |
| RESTイベント | Apacheログで `/wp-json/seo-tool/v1/section-engagement` の 400 を確認。イベントschema、nonce、payload、bot除外、rate limit を検証対象にする。 |

## 8. 不都合な真実

| 問題 | 実測・確認内容 | 影響 | 優先度 |
|---|---|---|---|
| permalink破損 | `permalink_structure` が `/C:/Program%20Files/Git/%postname%/` | 投稿URL、canonical、sitemap、クロール検証、SEO検証が信用できない | Critical |
| JIN:R PHP warning | PHP 8.2でカスタマイザーUIの null array offset warning 多数 | WP 7.0 / PHP更新時の互換性リスク、ログ汚染、CLIノイズ | High |
| JIN:R mount不整合 | mount先が空で、backupから305ファイルを復旧 | 環境再現性が低い。CIで同じ問題が起きる可能性 | High |
| `/hello-world/` 計測不可 | permalink破損によりhome相当HTMLを返す | 投稿ページ性能比較が無効 | High |
| Lighthouse未測定 | Chrome / Edge / Lighthouseなし | Core Web Vitalsの実測判断は未完 | Medium |
| SEOタグ責務重複リスク | テーマ、SEOプラグイン、Automation SEOが同時にmeta/schemaを出し得る | 重複meta、重複JSON-LD、canonical競合 | High |

## 9. AGENT NEO設計への反映

| 領域 | 取り込む設計 | 反面教師 |
|---|---|---|
| SEO | JIN:Rのテーマ内SEO統合、RESTで触れるmeta発想 | テーマだけにSEOデータを閉じ込めない |
| 構造化データ | SWELLの `@graph` 型の整理 | 複数scriptの場当たり出力、検証不能なschema |
| 速度 | SWELLの conditional asset / block単位ロード思想 | CSS/JSをグローバルに読み切る設計 |
| AI運用 | `section_id` / `cta_id` / `variant_id` をテーマが正式出力 | CSS class / nth-child / 見出し推測に依存する運用 |
| 更新性 | PHP 8.2+ 警告ゼロをCI gate化 | 古いPHP前提でwarningを許容する運用 |
| 計測 | theme manifest と tracking contract をプラグインに渡す | プラグインがDOMを勝手に推測する設計 |

AGENT NEOのテーマ側は「見た目」だけでなく、次の contract を正本として持つべき。

| contract | 用途 |
|---|---|
| `theme-manifest.json` | テーマ能力、バージョン、対応WP/PHP、対応API |
| `section-registry.json` | LP/HP/記事内セクションの安定ID |
| `cta-registry.json` | CTA、offer、variant、計測イベントの対応 |
| `seo-profile.json` | title / description / canonical / robots / OGP の出力責務 |
| `entity-graph.schema.json` | JSON-LD の検証可能な entity graph |
| `asset-policy.json` | CSS/JS/画像/フォントの予算と読み込み方針 |
| `integration-health.json` | Automation SEO / seo-tool-connector / SEOプラグインの競合状態 |

## 10. 次アクション

1. permalink を修正する。Windows/Git Bashのパス変換を避けるため、`wp eval "update_option('permalink_structure','/%postname%/'); flush_rewrite_rules();"` 形式で実行する。
2. JIN:Rの warning 発生箇所を、移行時の互換性リスクとして別レポート化する。AGENT NEOでは PHPStan / PHPCS / WP_DEBUG 有効時 warningゼロを gate にする。
3. Chrome / Playwright / Lighthouse を追加し、LCP / CLS / INP / TBT / JS実行後DOMを測る。
4. `seo-tool-connector` の REST 400 を再現し、payload schema、nonce、capability、rate limit を確認する。
5. SWELL / JIN:R 両方で plugin active / inactive の全ページ測定を行い、Automation SEO連携のページ種別別コストを出す。
